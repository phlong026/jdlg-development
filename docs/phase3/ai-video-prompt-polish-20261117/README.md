# AI 视频润色：本地交付

基线 `978cd17`；分支 `feat/ai-video-prompt-polish-20261117`。前后端代码与本地联调完成，未部署、未上传、未推送，也未调用真实或付费模型。

## 功能

- 文生视频补全主体、场景、运镜与光线；首帧/首尾帧侧重保持项、运动与过渡；参考生视频严格按已选图片、视频、音频编号和用户用途整理。
- 生成页展示独立费用；报价变动后刷新可见费用，再次点击才提交。保存、视频报价、视频提交和润色互斥。
- 润色结果页提供原文展开、可编辑结果和“保留原文 / 采用结果”。只有主动采用才回填当前描述，使旧视频报价失效；不会自动生成视频。
- 恢复任务核对账号、草稿、编辑版本、素材和输入语义指纹。同内容因自动报价产生的修订前移允许采用，实际内容改变则拒绝旧结果。
- 结果与素材用途合计按 Unicode 码点校验 7000 字上限；超限不截断原稿。页面沿用米白和棕金风格，输入框有明确高度和底部安全区。
- 后台新增独立开关、模型、超时与按次价格，以及润色任务查询和有证据的人工核对。供应商绑定仅存数据库，不从报价或任务接口泄露。

## 账务与恢复

独立持久任务、费用事件和人工审计表，复用 MySQL 钱包作为余额权威。一张报价只能创建一个任务；同一账号和请求键幂等，余额、预留、任务与流水同事务。

视频和润色领取任务共用配置行锁及并发总数，默认上限为 **3**。调用前持久化 `submitting`；收到可用结果先落库，再结算。结算故障只重试账务，不能再次调用模型。

外部超时、断连、5xx或进程中断进入 `uncertain`，保留预留与并发名额，不自动换键重发。运营核实“未受理”后释放费用；核实已取得结果后录入文本并结算。决策、结果、费用和审计在同一事务内完成；相反决策及不同结果会冲突。

## 配置与迁移

`prompt_optimize` 默认关闭，模型为空，超时45秒；使用已有文本 AI 配置的供应商地址和匹配凭据。只支持 Bearer 认证的 HTTPS Chat Completions 或 Responses 文本接口，后台单独指定模型。独立价格代码为 `ai_video_studio_prompt_optimize`，必须启用、按次计费且为正整数。

服务初始化可重复建立新增表和可空配置列；另提供 [增量SQL](../../../service/sql/add_ai_video_prompt_polish.sql) 供审查。初始化失败时功能不会就绪。没有对线上数据库执行迁移。

[逻辑回退SQL](../../../service/sql/rollback_ai_video_prompt_polish.sql) 先关闭新任务，列出所有仍预留的任务。必须依真实供应商结果处理完这些任务后再回退应用代码；保留新增表、配置列、结果与账务记录，避免删除计费证据。旧版本兼容这些新增结构。已在独立临时旧结构上演练正向 SQL 和逻辑回退，确认关闭值为 JSON boolean false，原预留记录仍保留。
