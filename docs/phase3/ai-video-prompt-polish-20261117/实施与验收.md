# AI 视频润色：实施与验收

本地功能开发，基线 `978cd17`。保持现有米白、棕金页面；不部署、不上传、不调用任何真实模型或付费接口。

## 实施边界

- 按文生、首帧、首尾帧、参考方式优化描述，只接收文本结果。参考素材仅使用已有编号和用户用途，不做媒体识别。
- 独立报价、持久任务与费用事件；原稿在主动采用前保留。采用仅回填当前描述并使视频报价失效，不自动生成视频。
- 结果页可查看原文和编辑结果；账号、草稿修订、编辑版本、素材及输入指纹变化时拒绝旧结果回填。
- 后台单独配置模型、1–120秒超时、按次正整数费用和开关。默认关闭，沿用已配置文本接口的凭据。
- 视频与润色共用配置行锁和总并发上限，默认3。未知任务占用名额，必须核对；不得自动重复调用供应商。

## 验收证据

1. 新功能行为测试先失败后实现，前端、持久模型与HTTP路由分别验证。
2. `httptest.Server` 模拟 Chat Completions/Responses，覆盖成功、拒绝、截断、工具调用、超限、重定向、超时和5xx；不调用真实供应商。
3. 新建绑定 `127.0.0.1:13317` 的可销毁 MySQL，测试各自创建独立安全schema，不读应用DSN；覆盖钱包原子性、并发幂等、结算失败恢复、退款、未知态及相反人工决策竞争。
4. 小程序与后台完整相关测试、生成一致性、静态检查、依赖审计和独立代码复核。
5. 微信开发者工具离线页面检查，截图对比输入框、操作区、状态与参考模式的显示；真机和真实模型联调另行验收。

## 设计依据

- Go请求上下文与HTTP错误：[WithContext](https://pkg.go.dev/net/http#Request.WithContext)、[Client.Do](https://pkg.go.dev/net/http#Client.Do)。超时不证明供应商没有受理；客户端不重试或跟随重定向。
- MySQL事务锁：[Locking Reads](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)、[Unique constraints](https://dev.mysql.com/doc/refman/8.4/en/constraint-primary-key.html)。钱包、持久任务及费用同事务，唯一请求键和唯一报价消费保证幂等。
- 第三方文本接口的兼容形状由本地HTTP夹具验证，不将OpenAI文档当作该供应商真实模型可用性的证明。
