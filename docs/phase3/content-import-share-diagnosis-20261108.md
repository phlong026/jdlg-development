# 链接提取与分享正文空白检查

## 平台实现与边界

小红书公开图文页已有完整描述、按原顺序的图片、作者和封面提取，并逐张转存素材。公开页需要可读取的完整分享链接；页面风控、结构不匹配、缺图会失败。小红书视频还依赖服务端配置的解析服务，不能将代码实现视为生产凭据已就绪。

微信公众号已有正文 HTML 安全排版、结构化段落、标题、图片顺序及公众号名称提取。直接视频地址可以导入；只提供 wxv ID 的文内视频依赖独立采集服务。公众号名片、小程序卡片、脚本等不是正文；音频当前不支持完整还原。已有离线测试不证明任意线上链接都能提取。

## 已确认并修复：分享摘要误算正文

原 `selectArticleRoot` 将 `js_common_share_desc` 作为正文备用容器。只有标题和分享摘要的响应，也会生成非空段落并被任务标记为草稿生成成功；宽泛的 `rich_media_wrp` 容器还可能将摘要混进正文。

修复删除摘要容器候选，并在布局与结构化提取时统一忽略该节点。仅摘要、容器包摘要、空正文加摘要返回现有的 `article_body_missing`；正常正文备用容器继续可用。小程序任务列表将其显示为“未取得文章正文，请更新完整文章链接或手动补充正文”，沿用现有手动补传入口。

不重写历史已发布内容、版本快照或素材；没有新增依赖、接口字段、配置或数据库变更。此项涉及 Go 后端，必须部署新后端后才会改变生产提取行为。此记录未声称已经部署，也未改动当前体验版。
