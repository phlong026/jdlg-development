# 设计师工作台与二级页面整改清单

## 本轮目标

沿用当前字体、导航、图标和品牌色。一个页面只承担一个主要任务；页面名称、栏目名称和操作按钮分层呈现。减少重复入口、重复标题、默认白框和无必要的解释文案。公开合集与仅指定成员可看的项目资料包继续分开管理。

## 已核验的问题

- 当前本地工作台已收敛为“我的项目 / 内容创作 / 设计师主页”；旧的“项目笔记”是“我的项目”的同一路由别名，不是另一套项目数据。旧体验版可能尚未更新，不能把本地效果视为手机已发布。
- 微信开发者工具实看：项目列表重复“我的项目”，新建表单常驻，输入框文字被裁切，归属直接显示 designer-40；项目列表、详情菜单受按钮默认布局影响，文本居中、宽度缩水。
- 实看项目详情：项目名重复，空笔记同时提供“新建”和“开始记录”，成员、记录、分享资料使用多行大白框，主要操作不突出。
- 代码核验：designer-40 是权限归属 ID，不是用户昵称；创建账号另存于 designer_id，展示名称应从用户资料读取，不能改动权限 ID。
- 代码核验：资料库缺少统一返回导航；AI 文案、内容创作的入口名称与页面标题不一致。

## 实施顺序及边界

先记录当前界面与回归基线，再分别实施项目页面、内容页面、昵称展示，最后合并验证。原有项目权限、邀请审批、版本冻结、分享撤回、未保存提醒继续保留。不增加新依赖，不修改数据库结构。昵称通过已有批量资料接口读取，避免逐条查询。所有用户可见变化仅限本轮页面清理。

- 微信开发者工具逐页实看列表、详情、创建表单、笔记、AI 文案、资料库、合集与素材入口；每轮保存视觉评估。
- 最终分别记录：本地修改、提交/推送、后端部署、小程序上传/体验版、手机验收。


## 最终页面层级与操作路径

| 页面 | 标题层级 | 主操作 / 最短路径 |
| --- | --- | --- |
| 我的 | 我的 → 设计师工作台 → 三个入口 | 我的项目、内容创作、设计师主页 |
| 我的项目 | 导航“我的项目” → 数量 → 项目名 | 新建项目 → 输入名称 → 创建；单归属不再选择 |
| 项目详情 | 导航“项目详情” → 项目名和状态 → 项目笔记 | 新建/打开笔记；分享资料、成员、记录作为单行菜单 |
| 新建/编辑笔记 | 导航说明动作 → 标题输入 → 正文与附件 | 填写 → 保存；已有笔记的低频动作保留 |
| 项目成员 | 导航“项目成员” → 人数 | 空态只邀请；有成员后才出现方案确认人表单 |
| 分享资料 | 导航“分享资料” → 项目名 → 内容与接收人 | 选择内容、接收人 → 预览 → 分享；添加接收人返回直达原分享页 |
| 内容创作 | 导航“内容创作” → 我的内容/项目合集/资料库 | 新建；AI文案、链接导入、分享记录属于内部工具 |
| AI文案 | 导航“AI文案” → 文案类型 → 资料、结果 | 填资料 → 生成文案；有结果后才展示编辑优化、保存 |
| 资料库 | 导航“资料库” → 已选用/可用内容 | 切到可用内容 → 选用；从编辑器进入时标题改为选择素材/内容 |
| 项目合集 | 导航“项目合集” → 数量 → 合集列表 | 新建 → 名称/已发布作品 → 保存草稿或预览发布 |

“我的项目”承载一个真实项目的资料、笔记、成员和方案版本；“项目笔记”是项目内的内容，不再作为平级入口。项目合集用于对外组合已发布作品，项目资料包用于指定成员交付；本轮没有把两者合并或扩大访问权限。

## 实际发现与修复补充

- 项目列表和菜单按钮受微信原生默认宽度影响，已显式重置宽度、边框及文字对齐；单行输入固定高度并垂直居中。
- 项目成员空态去掉确认人空表单；从分享资料进入成员页返回由三步缩短为一步。
- 资料库原来没有统一导航，内容靠近状态栏；现有独立导航及双标签，不再同时堆叠两个空卡片。
- 合集列表 `.compact` 同名样式冲突导致新建按钮过大，已拆分紧凑按钮样式；无已选作品时不再展示空选中卡片，底部去掉重复返回。
- 昵称查询与原权限 ID 分离，列表批量读取；昵称查询失败不会导致项目列表消失或已成功创建被误报失败。
