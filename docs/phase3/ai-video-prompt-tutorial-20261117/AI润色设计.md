# AI 视频提示词润色方案

本页为设计方案，尚未实现，也未调用模型或扣费。教程模块与本方案分别交付。

## 产品行为

将润色定义为“保留创作意图，补全可执行描述”。第一版采用用户文字、当前模式及素材编号/用途作为输入；读取已有文本 AI 配置，后台单独指定模型与价格。

| 当前方式 | 润色重点 | 保留内容 |
| --- | --- | --- |
| 文生视频 | 主体、场景、动作、运镜、光线与氛围 | 画面主题、禁止项和用户明确的细节 |
| 图生视频（含首尾帧） | 哪些保持稳定、怎样运动、怎样过渡 | 已选首尾帧、建筑/人物等保持项 |
| 参考生视频 | 按界面编号整理图片、视频、音频各自用途 | 媒体 ID、顺序、编号与已有用途绑定 |

润色不会修改时长、比例、清晰度、数量或生成模式。参考素材的画面/音轨内容只采用用户描述，不把未分析的媒体内容写成已知事实。识图或音轨分析可作为后续独立能力。

## 页面交互

1. 在“画面描述”标题右侧显示 `AI 润色 · X 灵石`，教程保留轻量入口。
2. 用户有一句基本描述即可润色；空白输入先引导使用教程案例。
3. 有效报价下点击一次开始，显示“润色中”，保留原文。重复点击沿用同一请求。
4. 完成后进入“润色结果”页：原文可折叠，润色结果可编辑，底部操作为“保留原文”和“采用结果”。字体、米白背景及棕金按钮沿用现有页面。
5. 只有点击“采用结果”才回填当前输入；采用后旧视频报价失效，重新计算视频费用。视频生成仍由用户另外点击。

结果应简洁，通常约 120–300 字；参考模式可适当增加。以现有最终提示词规则作上限校验，计入素材用途拼接，超限提示修改，不静默截断。结果页留足底部安全区，软键盘不遮住编辑位置。

## 对照案例

原文：`让这个庭院动起来，镜头往前。`

图生润色示例：

> 以首帧庭院为基础，保持建筑结构、门窗位置、石材质感与植物布局稳定。镜头由水景处缓慢、平稳地向客厅落地窗推进，树叶与树影随微风轻动。光线柔和自然，避免新增人物、建筑或文字。

这只是表达示例，不是已执行模型调用的结果；实际优化优先保留用户已有的具体意图。

## 费用与恢复

- 使用独立价格项 `ai_video_studio_prompt_optimize`，与视频生成费用分开。发起前展示本次费用，价格变化后重新确认可见价格。
- 复用现有钱包的报价快照、幂等预留和费用流水原则：先创建持久任务，再调用模型；保存合格结果后结算。采用或复制同一结果不再扣费。
- 明确失败按账务事实释放预留；超时或供应商受理结果未知时进入待确认。客户端先只读查询，不能通过换请求键盲目重发。
- 关闭润色开关后禁止新任务，已有结果仍可查看。没有配置时隐藏或准确停用入口。

## 防止串稿

每次结果绑定账号、草稿 ID 与修订、编辑版本、生成模式、提示词指纹和素材指纹。换账号、改原文、切模式、替换/增删/重排素材后，旧结果不得直接采用。用户可保留旧结果供复制，但回填前必须重新核对当前输入。

服务端只接受白名单输出字段并校验长度及引用编号，不执行模型返回的参数或操作。提交、查询、采用和取消的成功/失败回调都验证页面会话与操作身份。

## 实施验收

- 三种方式分别验证“保留意图＋补充描述”，不能自动创建视频任务。
- 未采用、关闭结果页、失败及网络断开都保留原稿。
- 草稿修改和账号切换后，迟到结果不能覆盖当前输入。
- 重复点击、重进页面和查询恢复不重复扣费；费用页面与实际流水一致。
- 参考编号与用途、最终长度、余额不足、配置关闭、明确退款和待确认路径均有回归测试。
- 真实润色模型、实际扣费与真机验收属于后续实施验证；当前“暂不付费调用、暂不部署”的约束继续有效。
