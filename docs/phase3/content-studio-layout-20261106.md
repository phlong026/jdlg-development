# 内容创作全流程排版整改

## 修改前计划与范围

用户要求覆盖内容创作全部相关页面，图集优先参考小红书的媒体优先、滑图和独立文案，视频参考抖音的播放器优先；保留项目笔记此前完成的私密协作、固定版本和分享能力。

1. 先运行既有行为回归，针对媒体异步回填、图集/视频形态、正文与图注分离、预览与阅读一致性增加失败测试。
2. 内容编辑：新建时明确图集、视频、文章；图集直接管理有序图片和一份文案，视频直接管理主视频和文案，封面/归属/来源等收起，长文章复用块编辑。媒体失败提供重试，不以永久空白占位代替加载与错误。
3. 发布预览和客户阅读共用主包展示模板及纯展示模型；图集左右滑、视频等比居中并限制屏高，保留既有视频跟踪事件和不可变版本读取。
4. 工作台、导入、AI文案、素材选择、合集编辑和合集阅读逐页减层级、突出主动作、增加缩略图和可辨认状态；项目笔记及受邀资料复核上一轮排版，不将公共合集与私密资料混为一种业务。
5. 复用现有正文JSON格式，新增可选的presentation呈现语义；旧内容保持可读，原排版布局不强制转换。采集整条文案与媒体图注分离，避免重复和长度校验冲突。
6. 小步独立验证、代码审查、完整小程序与Go测试、类型/语法/原生编译、凭据扫描及依赖审计通过后提交中文Lore记录。原生模拟器截图使用合成数据；真实接口、手机和发布状态分别记录。

不新增依赖，不重建保存/权限/分享系统。后台仅调整与正文呈现契约直接相关的兼容入口；不扩展到无关账户、订单和造价页面。本轮用户要求提交代码，不将本地提交当作体验版上线。


## 完成范围与操作链路

| 页面/入口 | 本轮结果 |
| --- | --- |
| 内容创作工作台 | 图集、视频、文章、项目笔记、文件分组；缩略图与作品形态一致；新建直接进入对应编辑器 |
| 图集编辑 | 大图原生左右滑动、缩略图调序/移除/设封面；一份完整正文，短图注独立；设置收起 |
| 视频编辑 | 主视频优先、独立封面、完整文案；16:9/竖屏等比限高；未知尺寸由原生 metadata 回填 |
| 文章编辑 | 保留标题/引用/列表/图文穿插；只展开当前块操作；已有复杂排版不强制改为图集 |
| 发布预览、客户阅读 | 共用 content-presentation 模型与模板；正文首图即使兼作封面也保留；顺序跟随正文；媒体错误可重试 |
| 链接导入 | 整条文案作为正文采集，不复制进每张图的图注；失败状态直接提供手动补传入口 |
| AI文案 | 输入、结果、快速调整分区；长结果底部操作不覆盖正文；保留流式生成、停止及采纳 |
| 素材选择 | 图片缩略图、视频/文件辨识、格式与尺寸；图片预览下载最多3个并发；列表分页保持 |
| 公开合集编辑/预览/阅读 | 展示作品原有图集/视频/文章格式与版本，预览和目录均有缩略图；与私密项目资料包分开 |
| 项目笔记、私密版本及受邀阅读 | 延续上一轮共享笔记模板、滑图和媒体自适应；本轮完整回归覆盖，不重建业务 |
| 后台内容编辑、预览、详情 | 可视化块编辑替代直接填写JSON；高级源码折叠保留；图集媒体优先、封面不重复、类型与小程序一致 |

简化方式：预览与阅读只维护一套展示；重用既有保存、素材、权限和分享接口；封面、来源、版权等低频项收起；不添加依赖。新建图集/视频直接进入编辑，导入失败直接手动补传，AI结果直接带回编辑器。

## 兼容与交付边界

- 正文仍为 schema=1 的 article_v2，presentation 为可选字段。服务端 context 广告 presentation_formats 能力；连接旧服务端时客户端不写未知字段。
- 新后端在目录、候选作品、合集和历史版本读取时推导顶层 presentation。历史发布正文不重写，授权、撤回、固定版本边界保持原实现。
- 媒体暂时下载失败保留可读正文，账户切换导致的媒体身份失效仍清空内容；这两条路径有独立回归。
- 前后端改动均需发布后才能在体验版完整体现，尤其新图集分类和显式呈现字段。本轮提交代码，不构成服务端部署或体验版上传凭证。
