# 三期内容制作与我的页面落地

## 目标与范围

以2026-10-26内容制作效果图及用户2026-10-27补充图片左侧“我的”为视觉依据。复用已有内容草稿、授权媒体、导入任务、发布/撤回、原生分享及本人访问查询，不新增依赖。

1. 内容制作：首页搜索、资料类型、四项创作入口、真实内容列表及分页；链接导入独立视图、粘贴、能力状态、权属、任务进度与重试。
2. 编辑与阅读：正文/图片/视频、封面、来源、草稿/预览/发布/撤回、发布后阅读及真实分享。原排版和旧格式的只读边界保留。
3. 我的：身份、账户、工作台两排四列、资料、服务、管理员及退出。保留既有角色与登录权限，不照抄示例数字。

项目协作、受邀权限及AI业务能力以现有服务实际能力为准，不借页面承诺不存在的接口。生产开关、微信消息发送、上传发布与真机验收独立记录。

## 实施与验证

先增加交互回归测试，再实施对应页面。主页与导入由主代理负责，“我的”及编辑阅读分配独立文件范围。保留本次开始前已有的shareweb测试改动。

- 验证搜索重置分页、筛选、导入粘贴、重复提交及失败恢复。
- 验证保存/预览/发布、来源与原排版不丢失、权限错误、退出/切换账号及迟到响应。
- 验证“我的”所有旧入口、账户显示、头像/昵称及工作台导航。
- 运行小程序完整测试、类型检查、编译一致性、路由检查、依赖与秘密扫描。
- 使用真实小程序编译/渲染截图和效果图比较，记录视觉判定；若运行环境受阻，明确区分静态预览与原生运行。
- 只提交本轮所属文件，提交前读差异并检查逆向补丁可应用。

## 本轮代码结果

- 内容制作按图拆分首页与链接导入视图；复用 `content_q`、服务端游标与导入任务。图文/视频分类从真实媒体推导，未提供的笔记/文档能力明确提示未开通。私有封面最多两个下载并行，分页不重复下载，迟到结果不跨账号回写。
- 新增 `contentwriting`：设计说明/项目介绍/推广文案三类，真实资料输入、结果编辑、精简/扩写/语气。使用原聊天流式调用与价格；用户点击发送才触发。SSE跨行/跨UTF-8块正常解析，失败、未完成或换账号不能采用结果。
- 编辑器独立保存草稿、服务端预览、发布与撤回；发布后直接进入阅读与分享。AI从编辑器发起时回到同一草稿，保留原文并追加结果，签名变化/保存/换账号时明确拒绝覆盖。独立策划页可以建立新草稿。
- 阅读页保持原排版、原生视频、来源及追踪同意规则，呈现金棕色阅读排版和真实微信分享/复制链接动作。
- “我的”以本聊天用户图片左侧为准：身份与编辑、账户在前、两排四列工作台、个人资料两列、账号服务、管理员和退出。保留全部既有动作和权限，没有抄入示例反馈/回访/账户数字。
- 补齐4个私有页面的导航组件声明，去除这些页面及阅读/策划页无效的分享JSON字段；分享仍由既有生命周期与原生回调控制。新增策划路由在小程序与Go清单中都明确排除采集。

## 简化、回退与剩余范围

沿用现有接口、内容模型、授权下载、聊天和分享链，没有添加平行存储、权限方案或第三方依赖。编辑器保存与预览复用同一草稿写入函数。回退只需撤回本轮前端提交，恢复旧路由清单；没有本轮数据库迁移。工作树中其他聊天的content-capture/ops工作不属于本轮提交范围。

完整私人项目、邀请笔记与手机客户管理缺少相应契约，保留待开通状态；普通资料和公开内容不能冒充这些私人业务。线上仍需独立部署/开关/授权和真实样例、微信及角色验收。
