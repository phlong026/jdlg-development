## 本次发现并处理的问题

1. 当前发布分支不注册内容制作相关页面，用户无法进入。恢复六个分包，并同步前后端67条路由清单，私人页面仍排除公开采集。
2. 消息中心只剩空状态，无法展示后端通知。恢复已有完整页面、分页、已读、回流及服务号能力状态。
3. 编辑图文时上传PDF/DOCX会切换当前编辑目标，导致未保存内容丢失。文档改为独立建档并保留图文，空白编辑器的直接打开文档行为保留。
4. 保存/预览请求期间继续输入的正文会被旧响应覆盖。发布前修复并回归，确保保留新输入且不将过期预览用于发布。

## 角色与权限

| 当前小程序账号 | 我的页创作入口 | 可操作范围 | 分享访问/客户管理 |
| --- | --- | --- | --- |
| 设计师认证审核通过，账号正常 | 设计师工作台，沿用本次微信登录 | 自动分配 `designer-用户ID` 个人归属；仅自己的创作、资料、项目笔记及已授权内容 | 分享访问需独立 `can_view`；CRM仍使用独立管理账号 |
| 普通业主、未认证、审核中或未通过 | 隐藏 | 无创作管理权限；受邀项目的阅读、反馈、确认仍按邀请控制 | 不因登录或邀请获得统计/管理权限 |
| 施工团队、企业或其他身份 | 默认隐藏；有显式 `can_manage` 才显示内容创作工作台 | 仅授权的归属范围，不显示设计师发布及主页入口 | 分享访问需另行授权，不能由创作权限推导 |
| 只有分享查看授权的账号 | 不显示创作工作台；我的资料显示本人分享入口 | 不可制作或管理内容 | 仅本人分享、授权归属范围的访问记录 |
| 已封禁或退出登录 | 隐藏 | 服务端拒绝；过期账号的异步响应不恢复入口 | 不保留上一个账号的能力 |

认证依据是审核记录 `type=designer / status=approved / identity_type=设计师`，不是用户自填昵称、身份文案或提现资格。认证撤销后自动个人创作权限立即失效；独立人工授权仍按其自身有效性处理。认证不会自动获得CRM、规则管理、删除权限或他人的访问数据。

内容工作台、项目笔记、原生引用和分享素材复用小程序签名登录；不跳管理端二次登录。前端按服务器能力隐藏入口，后端每次重新校验范围，两层控制不互相替代。
