# 视频号导入与分享播放修复候选（2026-11-11）

本次从 `fix/shared-video-stream-20261111`、`1214ae1` 继续，保留11月11日设计师工作台版本；未切换到11月9日笔记样式分支。此前8.0.4已上传，本次候选未上传、未部署、未完成真机验收。

## 最终行为

- 已转存的视频继续使用自有存储，不再把“视频号外链过期”作为已入库视频播放失败的解释。
- 内容阅读页、单篇项目笔记与分享资料接收页通过登录接口申请短时视频地址，原生 `video` 按 Range 播放，避免 `wx.downloadFile` 先整段下载以及其200MB限制。图片和文档沿用原授权下载。
- 播放票据10分钟过期；每次请求重新核验账号、登记资料、分享、成员、固定版本和素材。播放失败显示手动重新加载，不自动无限重试，迟到错误不能覆盖新票据。
- 已发布内容的原签名地址被全局资料门禁提前401拦截，线上已复现；现有签发POST改发统一票据URL，接口结构及前端调用保持兼容。新签发不再返回旧媒体签名地址，不把媒体路径加入匿名白名单。保留现有浏览跟踪、主动阅读回执和账号关联语义，播放本身不冒充已读确认。
- 链接导入 MP4 从50MiB提高到500MiB。生产链路采用0600临时文件、流式下载、文件校验、文件转存，保留私有存储；不取消所有资源限制。
- `media_source_expired` 仅在用户显式重试后清空旧解析快照，再解析一次；结果不明的付费请求不可重试。重新解析可能产生供应商费用。
- 大文件保存期间续租；单任务20分钟，来源下载最多15分钟，超时用独立有界上下文写入失败状态。MP4元数据解析具有预算与取消检查。
- 三个匿名业务入口仍为首页、模板广场、找设计师列表；其他业务页面保持登记门禁。

## 已核对的边界

草稿元数据的 `asset.url` 仍为公开跟踪路由，但当前草稿编辑、预览、重试均按 `media_id` 使用带鉴权的 `/workbench/media/:id`，已有行为测试锁定。未发布素材公开404、私有200属于权限设计，本次不改资产持久化结构。未来新增草稿消费者必须继续使用私有路由。

播放票据保存在单进程内存，最多4096份，服务重启失效；多实例部署前必须共享票据存储。退出登录不立即撤销已签发的10分钟票据；账号停用、登记资料失效、分享撤销和成员移除会拒绝后续请求。

## 部署顺序与回退

需要后端部署，无数据库迁移、无新增依赖，不重放旧迁移或覆盖环境配置。

1. 核对生产实际二进制SHA、PID、启动参数、API站点配置与现有来源版本，备份程序和Nginx include。
2. 在实际承载 `api.jiadilingguang.com` 的 server 合并 `ops/phase3-release/shared-video.conf`，避免重复 location。它关闭这些location的原始访问日志及会附原始URI的上游错误日志，状态/耗时保留在Go脱敏日志；明确转发Range并关闭播放响应缓冲；保留既有证书、安全头和站点策略。必须 `nginx -t` 后才 reload。
3. 使用包内 `binary_release.py prepare` 指定实际旧PID/旧SHA与候选SHA，随后 activate；发布器保持运行环境和配置并核验健康。
4. 使用真实已登记受邀账号申请票据，再从公开HTTPS域名测 `Range: bytes=0-1023`：必须206、Content-Range和1024字节；越界416、撤销后拒绝；检查应用与Nginx日志无原始票据/签名，包括受控模拟上游502/timeout的错误路径。
5. 后端验证通过后再上传小程序候选，避免新客户端请求旧后端不存在的票据接口。
6. 真机检查视频号素材导入、插入笔记/分享资料、跨账号打开、首帧、拖动、弱网、过期手动重试；超50MiB素材真实导入单独验收。

后端失败先用 `binary_release.py rollback --backup <本次私有备份目录>` 恢复旧程序。恢复Nginx备份并 `nginx -t`、reload；前端若已上传则恢复前一个已知可用版本。原业务数据、已转存媒体与任务记录不删除。当前程序回退会丢弃内存票据，用户重新加载即可重新申请。
