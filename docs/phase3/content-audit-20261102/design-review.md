# 设计师工作台与内容创作逐页设计审查｜2026-11-02

## 证据边界

本报告检查当前开发版916/JDLG/miniprogram/miniprogram/pages 下 my、contentworkbench、contentedit、contentwriting、nativereferences、projectcollections 的 WXML/SCSS/WXSS，必要时对照事件实现。属于代码静态审查；报告初稿时原生模拟器尚未登录；随后用户登录，已补充内容工作台、AI文案、编辑/预览、合集、资料库、分享记录的原生检查，实际结果见 README.md。以下未单独注明的布局结论仍属于静态审查。文中布局风险需登录后在窄屏、长内容、键盘弹出、大字体条件下验证。并非“所有页面已逐个点完”。

## 总体判断

现有品牌底色是暖白/米色、棕金主按钮、深棕正文，应保留品牌与系统原生字体。主要问题是入口层级及名词分散、内容页顶部控制层数多、编辑动作过密、AI生成路径解释不一致，不能靠统一圆角和颜色解决。

已有三期需求文件（1024三期/需求整理/三期内容创作需求增补_黑谷借鉴与任务清单_20261101.md）U1–U6 覆盖多数方向。当前代码已经有 U2 三卡空态、U4 类型示例、U6 部分版权措辞和保存提示，不应继续列为“尚未实现”。本报告关注实现后的剩余问题。

## 1. 我的 / 设计师工作台（my）

证据：my.wxml:29–71，my.scss:945–978。

- 层级：工作台排在会员、余额、充值及订单之后。对设计师的高频生产动作，账户信息先占一段空间。建议按已有 U1 保留“我的”完整入口，同时在业务首页提供常用创作入口；不直接删充值业务。工作台首页优先继续编辑与最近内容，避免每次从目录找功能。
- 可读性：菜单说明 19rpx、max-width 148rpx 且强制单行省略。关键不可用原因也复用该位置，可能被截断。建议将辅助说明提高到可读字号，禁用原因允许两行；点击禁用项给明确原因/开通条件，不仅灰显。
- 视觉：账户卡的渐变和工作台阴影比实际业务内容更显眼。可减轻账户装饰，强化工作台标题和第一主入口，但保留暖金品牌。
- 验收：长组织名、不同菜单数量、未开通与已开通账号、大字体分别核验；工作台每个入口返回后保持滚动与身份状态。

## 2. 内容工作台（contentworkbench）

证据：contentworkbench.wxml:12–24、36–47、51–64。

- 列表上方依次出现跨页面导航、搜索、灵石/生成量、归属筛选、快捷能力、内容类型筛选，共六层控制。建议保留“我的内容/项目合集/资料库”一级入口，搜索与筛选靠近列表；灵石移至生成动作附近；链接导入/AI文案并入新建菜单并保留一个常用快捷入口。需用登录后首屏测量确认能否看见至少一条内容。
- owner_tabs 应保持所属空间语义，类型 Tab 保持内容类型语义；避免两个视觉相似的选项条让用户不知道当前筛的是空间还是类型。
- 类型筛选目前明确写“分类显示已加载内容，可继续加载更多资料”（:46）。这是产品体验限制：用户不能把“暂无这类内容”理解为全库没有。建议服务端按类型筛选后分页；完成前空态改为“已加载内容中暂无此类”，给继续查找动作。
- U2 空态已经实现，但“三步开始”配①②③呈现成必须顺序完成的流程，实际上是三种独立入口。建议改“选择一种方式开始”，取消步骤编号。平台文案应与 importPlatforms 实际可用性一致，不硬编码保证任意链接可导入。
- 导入页的归属、版权、任务状态已具备完整语义；保留失败原因/重试/不确定不重复提交。优化时不要用一个笼统 toast 取代。
- 验收：空库、有数据、筛选零结果、分页后新增命中、无导入能力、多归属、失败可重试及结果不确定。

## 3. 内容编辑（contentedit）

证据：contentedit.wxml:11、23–32、41–56、70–78。

- 设置折叠已实现，可保持。标题→正文应是主流程；版权和来源放折叠区，但发布前摘要必须能确认归属及版权。
- 每个正文块可同时呈现转标题/转引用/H2/H3/上移/下移/移除，长文反复出现动作行。建议默认只展示当前块的操作，格式转换收进“格式”菜单；常用加段落、图片、视频维持直接可达，避免一次增加工具栏与块菜单两套入口。
- “插入块”属于编辑器概念，可改为“添加内容”，选择器再用“文字/小标题/引用/图片/视频”说明；H2/H3改“大标题/小标题”并保留层级语义。
- 错误 banner 位于顶端（:11），保存/预览在底部固定区域（:78），长文时失败原因可能不可见。这正是既有 U6-2。建议在操作区附近展示当前保存/发布错误，焦点定位对应字段，保留已输入内容。
- 内容标题与正文的草稿、已发布 Vn、未发布修改状态需要明确分离。已有“已发布·Vn/查看并分享”卡；进一步标出当前修改尚未更新对外版本，避免保存被理解为直接更新分享页。
- 素材管理同时包含上传文档归档和正文媒体，任务方向不同。保留“选择已有素材”直达，文档归档通过新建文档入口完成，减少文章编辑中途切换任务。
- 验收：20段长文、上传失败、封面失败、未保存返回、已发布版本再次编辑、只读导入正文、删除/撤回确认。

## 4. AI文案（contentwriting）

证据：contentwriting.wxml:8–9、24–38；contentwriting.ts:144–203；contentwriting.wxss:13、190–242、340–351。

- 已实现类型示例与“共用资料”解释，不应重新要求新增。但示例在输入前占空间，建议默认一行示例摘要，可展开全文；让创作资料始终优先。
- 确认的表达冲突：:35 说“生成将进入AI对话，费用以发送前显示为准”，主按钮 :38 却走 quickGenerate 就地流式；只有 generateWriting 才跳聊天。应分开说明“快速生成”和“去对话深聊”，实际扣费须按真实计费实现告知，不能保留错误承诺。
- 精简/扩写/语气（:32）仍走聊天，不是就地生成。建议优先统一为当前结果区就地优化，深聊作为次操作；如暂不变功能，按钮文案明确会跳对话。
- 高风险布局：底部只预留250rpx+safe-area。有结果时底部至少包含84rpx保存+84rpx重生成+82rpx深聊+16rpx间距+40rpx上下内边距，已达306rpx，还未计保存说明；重生成期间会额外出现停止按钮。建议主按钮和重新生成横排，深聊降为轻链接，并动态测量底部实际高度预留空间。静态可证空间不足，真实遮挡仍需登录后长文验证。
- 当前内容核对提示合理；保存入口已有“会新建草稿”提示，编辑器来源则使用返回标签，保留来源差异，不强行将全部保存动作改为相同行为。
- 验收：空输入、有结果、停止生成、生成失败、流式重生成、返回编辑器采纳、独立生成保存、长结果到底、大字体与键盘。

## 5. 资料库 / 素材选择（nativereferences）

证据：nativereferences.wxml:9–32；nativereferences.wxss:1。

- 普通资料库没有搜索框（仅pickerMode显示），但选择器有搜索；资料规模增加时普通入口反而更难找。建议普通“已选用/可用内容”也支持搜索，分页与搜索统一服务端条件。
- 媒体选择行只有标题和选择按钮（:12），缺缩略图和类型/尺寸等信息，多张“图片”无法识别。图像/视频必须显示预览缩略图，文档显示扩展名和大小；不要为了紧凑牺牲可识别性。
- 普通资料库实际上保存内容引用，并非完整媒体库；目前“资料库”“素材管理”“选择素材”跨页面混用。按既有 U5 区分“可引用内容”与“原始素材”，先统一入口解释，不能把私密资料包等同公开内容引用。
- “生成记录”放在已选用列表尾部，弱关联且长列表难发现，建议移动为独立次级入口；空态直接提供“去可用内容选用”。
- 现有失效引用禁用打开并保留移除是正确方向；可增加可读失效原因，但不要展示越权信息。
- 验收：重名素材、无标题素材、长标题、失效引用、选用后返回、分页查找、取消选择。

## 6. 项目合集（projectcollections）

证据：projectcollections.wxml:11–20、31–47；projectcollections.wxss:1。

- 列表每条并列编辑/查看/删除或撤回，操作权重接近。建议已发布主动作“查看并分享”，编辑为次动作，撤回收进更多并解释对既有分享影响。封面/标题可直接打开，减少点小按钮。
- 已选作品一行同时有置顶、上、下、封面、移除五个操作；flex-wrap使短标题区域与按钮在窄屏竞争。建议进入显式“排序”状态时显示上下移动，其他状态只保留封面标记和更多，桌面式密集操作不宜全部常驻。
- 候选作品只有标题和版本，无封面；应加入缩略图，避免多项目同名误选。选择模式保留已选数量，候选已选择时给一致勾选状态。
- 当前发布预览弹层仅标题+作品序号+标题列表（:47），没有封面和简介，不能代表客户收到的合集页面。建议复用真实阅读布局做预览，并显示发布范围；至少加入封面、简介、作品缩略图。
- collections.length是已加载数量，有nextCursor时文案“X个合集”会被误认总数。改“已加载X个”或使用后端总数。
- 合集当前选择已发布内容的版本快照，应该保留。不能因简化流程将草稿/私密附件直接塞进对外合集。
- 验收：1/20/更多作品、长标题、排序、设封面、归属锁定、预览和客户阅读页一致、撤回后分享访问、未保存返回。

## 统一设计约束与优先级

P1：先修AI提示与实际路径冲突、长页错误可见性、AI底部占位；这些直接影响任务完成与理解。
P2：减少内容页顶部层级、素材选择加入缩略图、合集预览接近真实页面、统一名称与操作主次。
P3：统一背景色/间距/圆角与辅助字号。现有背景分别有#fbfaf7、#faf8f4、#f6f3ed、#f7f5f1；可收敛为主底色+分区底色两档，主色保留#a87943，不另造品牌。先通过真实页面截图评审，再决定具体色值，不能把颜色变量统一当成业务验收。

验收报告应逐项标识：静态问题、模拟点击、真实服务端结果、真机结果；不把代码存在或0编译错误写成真实用户流程通过。
