## 我的项目与项目笔记

业务关系应为：**我的项目 → 某个项目 → 多条笔记 → 固定方案版本 → 业主反馈与确认**。

- 项目是稳定档案，归集地点、面积、层数、风格、状态及相关客户和成果。
- 笔记属于某个项目，记录图文、方案说明及修改过程；其固定版本用于分享、反馈、确认和导出。
- 当前已存在独立项目 ID 和多笔记关系，并非仅将生成历史改名。但“我的项目”和“项目笔记”两个菜单均打开 `/pages/projectnotes/projectnotes`，用户看到的是同一个项目与笔记综合页，入口尚未区分。
- 页面组织建议：保留“我的项目”为总入口，笔记和版本放入项目详情；如果保留独立“项目笔记”，它应提供跨项目笔记列表和项目筛选。此次登录修复未把重复入口改造成两个独立模块。

## 本次登录问题与交付边界

- 用户截图已显示“设计师·已认证”，无需重新注册或认证。
- `workbench/context` 无查询参数可通过；`contents?limit=20` 原先签名遗漏查询参数，后端拒绝后被前端显示为登录页。修复让实际请求与签名使用同一个完整路径，不放宽服务器权限。
- 工作台新增已有“AI文案”和“资料库”入口。资料库副标题为“已发布内容引用”，不能把这个入口视为统一资料能力全部完成。
- 普通注册、普通业主、未通过认证的账号不会自动取得创作管理权限；认证设计师拥有个人创作范围；其他账号按显式授权处理。分享统计查看权限和CRM权限仍独立。
- 本轮发布是已完成模块及访问缺陷修复，不是上述全部需求的最终验收。剩余项继续属于需求范围，不能因为本次先发布基础能力而自动取消。
