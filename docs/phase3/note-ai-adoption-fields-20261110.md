# 笔记 AI 采纳字段清单（T4.2 交付物）

- 日期：2026-11-10
- 关联：T4.1（就地面板）、T4.2（回填校验收敛）、P3 决策（`设计师工作台新建笔记-总任务清单-20261110.md`）
- 结论：AI 结果是否允许采纳，由**草稿身份（账号/项目/笔记/修订/草稿实例）**决定，不以 `note_id + revision + 正文哈希` 之类弱标识替代。新面板使用**结构签名**（含格式/封面/媒体），旧 ack 链路保留**完整草稿签名**；两条链路口径见第五节。

## 一、允许继续采纳（只影响内容字段）

| 字段 | 规则 |
|---|---|
| `title` | 最多 80 字，超长拒绝采纳并提示 |
| `body` / 正文 | 与现有正文合并；8000 字上限按 `separator + 剩余空间` 截断，原文不破坏，剩余部分可复制 |
| 分享文案 / 视频文案 | 按各自字段上限校验；不写入笔记正文 |
| 未变化的媒体 | 仅在 `media_ids` 与当前草稿一致时保留 |

## 二、必须拒绝采纳（任一项变化则整条结果不采纳）

| 字段 | 原因 |
|---|---|
| 账号（token/account） | 防跨账号串写 |
| 项目 ID | 防结果写入其它项目 |
| 笔记 ID | 防串到另一篇笔记 |
| 修订号 `revision` | 防覆盖已提交的更新 |
| 草稿实例 ID | 防写入已丢弃/新建的草稿 |
| `body_format` | 结构化正文（article_v2）不得被 AI 结果改成纯文本 |
| `cover_media_id` / `media_ids` | AI 结果不得增删素材或改封面 |

## 三、实现对应（本轮）

1. **就地生成**：`openNoteAIWriting` 打开半屏面板，不跳页；`startNoteAI` 通过 `utils/ai-stream` 就地 SSE。
2. **身份绑定**：面板发起时记录 `{token, projectID, noteID, revision, instanceID}`；流式回调、插入前都校验同一身份，失败即停止/拒绝。
3. **插入**：`insertNoteAI` 等 `busy` 结束（排队而非丢弃），按跟踪的光标位置插入；8000 字按算法截断并提示剩余可复制。
4. **兼容**：既有 `receiveNoteWriting` ack 协议保留（`_writingLaunch`），防止其它入口回归。
5. **回归**：`tests/private-project-notes.test.js` 覆盖不跳页、光标插入、截断、排队、换账号拒绝；T1.1 旧断言已迁移到面板语义（业务保护目标不变）。

## 四、边界

- 编辑器视频/图文块追加路径（`edit:321-339`）不受 8000 字限制影响。
- `contentwriting` 作为 my/contentworkbench 独立入口继续可用；三个「快速调整」改为就地 `quickGenerate`（T4.3）。

## 五、两条采纳链路的口径（实现现状）

| 链路 | 标识 | 允许变化 | 必须拒绝 | 超限处理 | busy 时 |
|---|---|---|---|---|---|
| 新：就地面板（T4.1） | 结构签名：项目/笔记/修订/草稿实例/正文格式/封面/媒体 + 请求代际 | 标题、正文、分享文案 | 账号、项目、笔记、修订、实例、格式、封面、媒体变化 | 按 8000 字算法截断，剩余可复制 | 排队（≤5s，面板关闭即取消） |
| 旧：EventChannel ack（T1.1 兼容） | 完整草稿签名（`noteWritingSignature`） | 无（完整签名一致才采纳） | 签名不一致、账号/实例变化 | 整段拒绝（由 AI 页保留文案） | 返回 retryable，由 AI 页重试 |

兼容策略：面板是主路径；旧 ack 链路保留给 `contentwriting` 独立入口，规则不降级。两条链路均不接受账号/项目/笔记/修订/实例变化。
