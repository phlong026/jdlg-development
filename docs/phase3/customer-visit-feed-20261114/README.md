# 客户跟踪 · 逐次访问列表

日期：2026-11-14。基线：`108eec7`，分支：`feat/customer-visit-feed-20261113`。

## 业务结果

设计师工作台“客户跟踪”默认进入“客户查看”，按真实内容访问倒序排列。同一客户查看不同内容或多次打开同一内容，可出现多条卡片。原有按客户聚合、素材热度、分享记录，以及客户详情中的项目活动、可信客户关联与线索承接继续保留。

卡片展示已授权的头像昵称、系统意向、内容历史封面与标题、访问来源、访问时间、本次停留或观看时长、有数据的视频进度，以及统计范围内该客户对该内容版本的累计浏览次数。

按用户最后确认，日期快捷项下的搜索、意向和来源只占一行；查看记录/按客户汇总的切换收进顶部“客户查看”的下拉入口。压缩卡片间距和内部留白，保留可读字号。

搜索及下拉控件复用 `mini-icon` 线条图标，移除文字字符图标；统一72rpx高度、圆角与垂直对齐。素材及分享视角使用相同控件规范。

## 统计与权限约束

- 每个有效 `page_view` 是一条访问，心跳和视频进度事件只补充指标。匿名访客使用默认头像和匿名名称；复制按钮只复制已展示的已识别昵称。
- 时长区分前台可见停留与实际视频播放。视频进度按已播放区间去重计算，封顶100%，不把拖动位置当播放完成；没有进度数据时不显示百分比。
- 累计次数限定当前日期及来源筛选范围、本人分享统计段、访客、内容和版本，包含本次访问。全部时间限定系统实际可查询的数据保留期，历史分享仍按既有400条预算分段并提供切换。
- 来源按实际记录映射为微信分享、朋友圈等；未记录渠道显示来源未知。分享来源不推断为私聊，也不赋予同事数据或私密内容阅读权限。
- 新接口复用现有登录、活跃账号和本人分享授权，Service层继续校验实际分享人。素材归属相同不代表可以读取其他分享人的访客。
- 日期按北京时间处理，自定义结束日包含全天。首次钻取保留快照，分页沿用快照，显式刷新重新取快照；近N天随刷新滚动。

## 接入与回滚

新接口沿用 `TRACKING_MY_CUSTOMER_VIEW_ENABLED=true`，不新增开关、依赖、数据库表或迁移。后端与小程序需匹配版本后再上线；本次实施授权仅覆盖代码与本地验证。

回滚通过撤销本功能提交恢复原页面和接口；既有访问记录、客户关系和项目不需要删除。不得为撤销UI而清理业务数据。

权限和快照检查沿用项目既有中间件与只读事务；官方事务使用约定见[Go事务文档](https://go.dev/doc/database/execute-transactions)。
