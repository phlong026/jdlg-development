## 图文、视频参考黑谷的创建方法

采用“先素材、后文案”的顺序。图文在一个页面完成选图、标题和可选介绍，首图默认封面；只在选中图片时显示操作。视频先选主视频，再补标题与可选介绍；有视频后才显示封面操作，不要求空白阶段先挑封面。素材来源在添加时选择，不先做平台、模板、渠道等额外向导。

底部统一“保存草稿 / 发布”。只想记录可保存，不需要预览或公开；公开发布由用户明确点击，内部自动完成必要保存。预览为可选轻量入口；分享文案、阅读样式仍可从二级设置进入，不作为创建前置条件。此处借鉴黑谷的编辑顺序和简洁度，不假定黑谷的“保存”即公开，也不复制其蓝色、多排筛选或多个展开文案框。

17—18为空白新建状态，03—06为已有内容和设置状态，两组保持同一动作语义。

## 项目笔记的三个独立目标

| 目标 | 最短用户流程 | 完成点 |
| --- | --- | --- |
| 已有项目，内部记录 | 选项目 → 新建笔记 → 标题和正文 → 保存笔记 | 保存成功即完成，不提示继续生成或分享 |
| 第一次建项目并记录 | 填项目名称 → 创建并写笔记 → 标题和正文 → 保存笔记 | 创建项目后当前代码已自动进入新笔记，继续沿用 |
| 给客户看 | 编辑完成 → 发给客户 → 发送预览中选择微信接收人 | 后台顺序保存、取得固定版本和分享；用户仍自行发送微信 |

## 已从拟实施主流程剔除

| 非必需操作 | 新方案如何处理 |
| --- | --- |
| 新建项目时关联客户 | 从首屏移除，创建后在项目资料里按需关联 |
| 已有项目再次填写项目名称/归属 | 继承当前项目，不重复输入；多归属权限仍需合法且明确 |
| 必须先预览再保存或发送 | 去掉前置要求，预览为可选入口 |
| 保存后必须生成方案版本 | 内部记录不生成；仅准备分享时由系统处理 |
| 必须手动创建分享 | 仅“发给客户”时内部取得可用分享，不再要求单独点击 |
| 普通分享前邀请成员/审批加入 | 不作为普通链接阅读前置步骤；特定成员能力仍保留规则 |
| 普通分享前指定确认人 | 只在需要正式方案确认时设置，不影响普通发送 |
| 创建前导出、查看历史、处理反馈 | 均是后续按需功能，放项目详情/更多 |
| 保存成功后的强制“下一步”提示 | 改为“已保存”，不引导所有笔记进入交付流程 |

位置、面积、层数、风格本来就不是当前创建必填，当前已放在项目详情“编辑资料”中，不重复当成新整改项。

## 必须保留

- 新项目名称和有效项目归属。单一可用归属直接沿用；多归属按当前规则明确，不移除权限校验。
- 项目笔记标题、非空正文与真正的保存写入。当前前后端都要求正文非空，不能只改效果图就声称允许仅图片保存。
- 图片、视频为选填；有上传则必须处理完成或明确失败，不能串入其他笔记。
- 发送需要固定快照及有效分享，这些是系统必要操作，合并用户点击而非删除底层能力。
- 旧分享、私有媒体、指定确认和客户权限规则不变。
