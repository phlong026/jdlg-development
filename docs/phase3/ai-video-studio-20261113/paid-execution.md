# 秘塔 H3 执行与灵石账务交接

本文件补充当前目录 README。用户确认沿用现有操作界面，点击“生成视频”直接提交；无需先点击报价或二次确认。供应商为秘塔 H3，使用甲地灵光独立凭据，灵石单价由后台配置。

## 费用规则

后台 `/admin/ai-video-studio` 独立配置 768P、2K 和 768P 长档的正整数灵石单价，支持按秒、按条、按次的服务端计价契约。页面自动取得十分钟有效报价，冻结单价、计费单位、数量、时长和草稿修订。价格变化只影响新报价；关闭模式、档位或运营开关会拒绝新建批次。

提交时在同一 MySQL 事务中检查报价、草稿、素材归属及有效性，扣除可用余额作为预留，写入批次、子任务、费用和用户灵石明细。余额不足不创建批次、不产生部分扣减。同一账号和请求键只创建一个批次，同一报价换键也不能再次消费。客户端发送前持久保存账号范围内的原请求键，断网或重进可用原键找回结果。

每个子任务分摊固定费用，整数余数按子任务顺序分配，所有分摊之和严格等于报价。成功只结算已预留额度，不再次扣余额；明确失败或取消尚未开始的任务则退回其预留费用。结算和退款均有幂等费用事实。部分成功保留成功视频并只结算成功项，失败项单独退款。

秘塔未公开保证原生提交幂等和取消。网络超时、HTTP 错误或不完整提交响应都可能已经受理，因此进入待确认，禁止自动重复提交或自动退款。已取得供应商标识的任务只查询实际状态。后台可根据核对依据补回真实标识，或确认未受理后退款；每次处理记录管理账号和依据，不能手填成片地址伪造成功。

## 钱包切换是发布前置步骤

共享 `UserRedisModel` 保留调用接口，余额真源改为 `users.stones`；普通旧功能的增减余额也使用数据库原子更新。Redis 不再是余额真源，也不再异步覆盖 MySQL。管理员设置/调整余额与对应流水同事务。旧账户合并命令中直接修改 Redis 的执行入口禁用，需使用另行审查的数据库合并流程。

这项变更不代表重写了旧微信支付、虚拟支付、签到和邀请奖励的全部业务事务；这些既有流程的业务幂等仍按其原实现。本次新视频批次和费用是独立的持久事务。

生产发布需要维护窗口：

1. 备份数据库、私有媒体和旧前后端。停止所有旧 API/工作进程，等待已有余额同步结束，阻止新充值和消费。
2. 在停止写入后只读导出 MySQL `users.id/stones` 与旧 Redis `user:stones:*`，核对差异及业务流水。不能直接选择较大值、较小值或盲目覆盖；差异逐项确认并留存迁移依据。
3. 保留 Redis 原余额导出作为迁移证据。确认 MySQL 余额与未完成旧订单/退款责任一致，再启用新服务。禁止新旧钱包实例混跑。
4. 新服务自动增加独立工作区表、报价 `billing_unit` 字段和报价消费唯一关系；字段默认空的历史报价不可用于扣费。先保持后台开关关闭，完成读写、余额和流水核对后再开放。
5. 通过测试账号验证配置、余额不足、一次生成、失败退款、重复查询与关闭能力。前后端版本配套；小程序上传、服务器部署和正式发布分别留证。

## 配置

- 本机私有文件为 `service/.env.local`，Git 忽略且权限 0600；独立密钥变量为 `AI_VIDEO_STUDIO_METASO_API_KEY`。生产使用受控环境注入，不能把本机环境文件直接覆盖服务器原配置。
- `TRACKING_MEDIA_SIGN_KEY` 必须显式配置至少 32 字节；图像和混合参考依赖公网 HTTPS 可访问的授权素材、私有媒体存储，以及音视频 `ffprobe` 探测。不要使用可预测的回退密钥。
- 后台单价与开关准备完毕之前，服务继续拒绝付费提交；不提供零价回退。
- 已经付费的在途任务由服务端继续查询和结算，不依赖小程序保持打开。配置关闭仍允许历史查询。

## 接口补充

以下路径相对于 `/api/v1/miniprogram/ai-video-studio`：

| 接口 | 契约 |
| --- | --- |
| `POST /batches` | `{quote_id,idempotency_key}`；成功返回原批次或新批次；余额不足返回 402、输入/版本冲突返回 409 |
| `GET /batches/:id` | 本人批次、逐条结果、费用汇总与 `can_cancel`；不向用户暴露供应商凭据或原始响应 |
| `GET /submissions/:idempotencyKey` | 只读找回本人已创建批次，未找到返回 404；不因自动恢复查询而首次创建付费任务 |
| `POST /batches/:id/cancel` | 仅取消未开始的子任务；已受理项继续查询；返回更新后的批次 |

管理路径相对于 `/api/v1/management/ai-video-studio`：

| 接口 | 契约 |
| --- | --- |
| `GET /tasks/:id` | 批次详情，供运营查看真实外部任务标识和费用 |
| `POST /results/:id/reconcile` | `action` 为 `query`、`attach_external_id` 或 `refund_confirmed_rejected`；后两者需 10–500 字核对依据；补回标识必须经供应商查询验证 |

任务详情自动刷新状态，离页停止客户端轮询。服务器认领任务使用数据库租约和状态条件，过期的提交步骤不会再次发送付费请求。成功 URL 先持久化再结算；如账务暂时失败，恢复程序依据已有结果补办结算，不能丢掉成片或误退款。

## 回退

先关闭新模块开关，停止新的批次提交。保留所有任务、报价消费关系、费用、用户流水和媒体。正在执行或状态待确认的任务必须完成核对，不能因回退代码就退款或抹除。

回退至本次变更之前的程序会重新启用旧 Redis 钱包逻辑，因此不能只换旧二进制：必须再次停止全部钱包写入，以权威 MySQL 余额与在途事实为准同步旧余额缓存，核对后才启动旧进程。不得复用切换前 Redis 导出覆盖新余额。代码回退可用 Git 逆向提交；账务和媒体事实不能通过删除表回退。

## 验收边界

自动化、隔离 MySQL 和模拟器证据记录在验证文件；真实供应商生成、真实灵石余额、真机下载和生产发布是独立验收。未取得独立秘塔凭据之前，不宣称完成真实供应商联调。AI 润色和完整项目笔记选择器仍在原任务书未完成范围，未因本次补齐生成/扣费而自动通过。
