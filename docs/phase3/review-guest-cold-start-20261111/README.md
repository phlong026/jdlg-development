# 首页未登录审核问题的完整链路修复

2026-11-11，公众平台确认8.0.5在19:10:56提交审核后仍被拒，原因是首页打开即显示授权登录。该结果不是旧审核版本记录。保留11月11日设计师工作台及现有视频修复，不更改页面样式。

## 已确认根因

首页onShow自动请求 `/templates/featured`。全局服务端资料门禁使该接口匿名返回401；客户端全局请求处理器随后调用首页登录组件的check，使登录面板visible=true。此前只测首页生命周期不主动调用登录，没有把真实数据请求与全局401处理串联验证，导致8.0.5仍有问题。

另有两个关联缺口：公开列表加载后会自动预取仍受保护的详情，再次产生401；匿名tracking entry也被全局门禁拦截，即使单独放开entry，events仍只接受已登录账号凭据，不能实现约定的匿名访问记录。

## 最终边界

- 仍只有首页、模板广场、找设计师列表三个业务页面允许匿名。
- GET精确允许 `/templates/featured`、`/templates/tab-config`、`/templates`、`/templates/search`、`/inspirations`、`/designers`，不使用前缀通配。响应为公开列表，不新增手机号或私人资料字段。
- 公开页的后台401/428不会自动打开资料面板或跳登录；带过期token的401仍清理过期缓存，受保护页面保持原门禁。
- 未完成登记的用户不自动预取模板/灵感详情或设计师主页；列表已有封面仍可预取。完整登记用户保留原优化。
- 匿名entry、events与share只允许三个公开route，临时凭据必须属于匿名entry；不能把已登录账号凭据当成匿名使用。登录后的身份关联沿用原服务端验证。
- 带账号但资料不全的用户不能通过tracking传输例外制造其他受保护页面的实名访问/分享事实。

## 发布与验证

候选版本8.0.6。提交、部署、上传、公众平台体验版、审核提交与最终审核结果分别记录；代码检查通过不代表微信审核通过。

修复前六个列表接口的真实匿名请求均401。修复后需验证匿名200、私有详情401、三个页面无自动登录/资料弹层，以及匿名访问实际记录和登录关联。

本轮不改数据库schema或环境配置。程序替换前核对7402c41运行SHA并备份；客户端与后端均保留回退版本。当前发布状态以receipt.json为准。
