## 采集环境的实际验收

服务器为 `162.14.210.252`，部署根目录 `/opt/jdlg-content-capture`，官方 Headless Shell 版本 `156.0.8078.47`。

- Browser 和 Worker 使用不同的专用非 root 账号，不能读取 `/www`；没有使用 `--no-sandbox` 或给这两个进程授予 SYS_ADMIN。
- CDP 仅在专用 namespace 的回环地址监听；Worker 通过 `0660` Unix socket 接入 Nginx。内部 HTTPS exact location 对公网返回 403，域名 TLS 校验保留。
- 微信白名单 HTTPS 可以连接；元数据地址、私网、宿主业务端口、非白名单公网、其他 DNS 及 IPv6 均被实际阻断。
- 真实 CDP 临时页面已经渲染，实际 renderer PID 的 UID、seccomp、NoNewPrivileges、capability 和 AppArmor label 检查通过。
- Chrome 停止时 readiness 为 503，重启后恢复 200；Worker PID 不变，新 CDP 地址自动发现，旧临时 profile 不复用。
- `verify.sh --installed` 的 26 项部署策略及运行检查通过；发布元数据保存于服务器。测试二进制经散列匹配清理，原业务唯一进程保持运行。

## 私人笔记按最新回答实现的规则

设计师保存草稿 → 冻结 V1 → 邀请现有甲第账号并指定确认人 → 分享 V1 → 受邀账号登录查看及反馈 → 设计师处理反馈 → 指定业主确认 V1。修改草稿后需冻结并分享 V2；V1 正文、媒体和确认保持不变。

同企业其他设计师不能读取该项目。转发卡片不增加权限；成员或分享撤销后，正文与媒体重新校验。项目媒体只进入独立 `note_media`，普通企业素材列表及普通已知 ID 下载不能读取。小程序下载受控代理后使用本地临时文件，不把账号凭据写入媒体 URL。

同一版本只能有一条确认，更换确认人不会给旧版本生成第二条；新版本可由当前指定业主独立确认。反馈处理与方案确认分别记录。前端只采用服务端 `can_confirm`，账号变化会清除私人正文和表单、轮换打开事件并隔离旧请求；反馈响应丢失后重试沿用同一幂等键。

浏览提醒发给该分享的实际创建人。私人通知只带通用文案和项目/版本管理路由，不包含正文、raw token、客户资料或媒体地址。投影和外发前重新检查当前授权；隐私删除清理原始浏览事实并阻止重新采集，同时保留方案、反馈和确认业务记录。

实现复用现有仓储、事务、签名认证、私有对象存储和消息队列，没有新增依赖或私人项目数据库结构。全部接口及限制见[私人项目说明](private-project-notes.md)。
