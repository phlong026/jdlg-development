# 分享浏览提醒：访客与浏览内容

2026-11-18已通过[PR #59](https://github.com/phlong026/jdlg-development/pull/59)合并、部署并重启后端。模板已配置为`thing1→visitor`、`time2→time`，未配置未确认的`const3`；通知外发继续关闭。部署回执、验证与未完成项见[机器记录](release-receipt.json)。

业务目标是让分享人知道谁、何时浏览了自己分享的内容。原访问记录已保存访客、分享、内容和时间，但通知只生成“有人浏览了你分享的内容”，仅填写微信模板无法带出具体访客。本次新增受权限约束的单事件展示解析，不增加数据库字段或前端页面。

## 最终行为

- 已识别访问使用现有展示昵称；真正匿名访问显示“匿名访客”，已登录但无昵称显示保守兜底，不猜测真实姓名，不输出设备键或用户ID。
- 新访客模板模式下，站内正文显示“某访客浏览了你分享的《内容标题》”，时间使用原浏览事件时间。
- 服务号`visitor`值源使用纯昵称，归一为空格单行、去控制字符并限制20个Unicode字符。`time`仍是北京时间。模板点击沿用消息中心和该分享的访问汇总，不新增单次详情路由。
- 合集内作品使用实际被浏览作品的名称，不把合集名误作作品名；同session继续导航不会覆盖原事件的页面事实。
- 窗口内合并保留通知ID，不再创建投递；正文、内容、路由、标题、事件ID与时间同步到最新事实。并发已读或取消使合并更新0行时回滚并重试，不静默丢失本次浏览。

当前沿用原配置：同一收件人、同一分享、同一提醒类型在30分钟内合并未读提醒，不等同于每次浏览都逐条推送。逐次访问记录仍保留在客户跟踪中，开启外发前需按实际频率需求确认该设置。

## 配置契约

`OFFICIAL_ACCOUNT_BROWSE_FIELDS`新增值源`visitor`，兼容既有`title/body/time`及原重复键、尾随JSON拒绝规则。当前已核实模板的访问人字段为`thing1`、来访时间为`time2`，配置示例：

```json
{"thing1":"visitor","time2":"time"}
```

现有模板另有`const3`，但常量只能使用平台审核枚举，不能把模板示例当作审核证明。本轮不配置或发送未确认的常量。

含`visitor`即为新访客模板模式，仅外发`browse`、`collection_directory_browse`和`collection_content_browse`。创建投递与发送前分别限制类型，私人项目工作流通知不套用访客模板，其站内原文保持。旧`title/body/time`映射不查询新展示资料、不改变旧正文与外发种类。

## 权限与错误

以事件ID精确读取notice、原始event、session和share，核对分享人、收件人、tenant、owner及全部元数据，重建通知事实；删除、撤销、过期、自访或失效素材均不返回个人资料。只查询这一条事实关联的profile和素材，不扫描访客列表。

Consumer在通知事务之外解析展示资料。权限失效取消物化，核心读取或展示资料临时失败重试；发送前再按最新`Notice.EventID`解析，而非通知ID或中文正文。发送前失效进入Cancelled，临时异常进入可重试失败，不调用微信接口，也不误记永久`template_mapping_failed`。签名和服务号绑定版本校验沿用原链路。
