# 三期普通客服咨询上下文契约

## 适用范围

本契约仅覆盖已发布公开内容阅读页主动发起的普通客服咨询。项目笔记、私有方案或其他需要项目权限的引用不在本次范围内。

## 小程序路由参数

内容阅读页只向客服页传递：

```text
source=content_reader
content_id=<稳定内容 ID>
content_version=<大于 0 的明确版本号>
```

不传递标题、正文、私有项目 ID、分享 token、访客标识或匿名访问记录。

## 咨询保存

复用既有客服事件 `payload.consultation_plan`，不新建客户表、不增加数据库迁移。内容引用的稳定结构为：

```json
{
  "visible": true,
  "summary": "正在咨询内容版本 v7",
  "contentRef": {
    "contentId": "content-0001",
    "version": 7
  }
}
```

客服页同时在既有线索备注中写入 `咨询内容：<contentId> v<version>`，便于接待者直接识别问题指向。

## 服务端信任边界

- `content_id` 和 `content_version` 是待核验声明，不是权限证明。
- 客服接口在建立线索前通过现有 `ReadContent` 公开内容契约验证精确版本；未发布、已撤回或不存在的版本返回 400，不创建线索。
- 验证通过后，服务端重建上述最小引用，不信任客户端同级字段。
- 项目、方案和私有笔记需要独立的服务端成员权限校验；本次不接收这些客户端引用。

## 隐私与身份

- 咨询上下文与访问分析同意状态分离，不引入强制实名访问门禁。
- 不用分享 token、访客浏览身份或匿名访问记录自动识别客户。
- 仅在用户已登录并显式提交留资或转人工时，沿用现有客服线索流程保存；不建第二套客户。
- 企业微信转人工仍沿用现有配置和失败提示，本契约不改变责任路由。
