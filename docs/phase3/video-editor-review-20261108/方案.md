# 视频创作与阅读优化方案 · 2026-11-08

> 以下为确认前的历史分析与效果图方案；最新代码实现及验证状态见 [实施结果.md](实施结果.md)。

范围：依据用户提供的六张截图与当前 JDLG 提交 `17ea638` 只读分析。图1—4为本产品，图5—6为用户提供的黑谷参考；未将截图中的界面入口外推为黑谷后台、模型或发布接口能力。本轮不修改业务代码、不部署、不上传。

## 一、结论

需要把视频作为独立作品流程设计，复用原有素材、草稿、版本、分享和AI能力。当前同时存在上传契约缺口、校验反馈含糊、编辑/阅读布局混用、AI成果字段不完整和阅读正文缺少异常兜底。上一轮原生编译与合成数据验证不能代替真机“选视频—上传—保存—预览—发布—接收者播放”验收。

## 三、目标编辑流程

入口“新建视频”直接进入视频作品编辑；日常不再展示图集/视频/文章三模式选项。其他类型保留独立入口，复杂文章和旧内容不强制转换。

```
编辑视频                         更多
[缩略图 9:16/16:9]  视频名称/时长/上传状态
[播放]             更换视频 · 素材库
[封面缩略图]       选择/更换封面

阅读样式            视频号式 | 抖音式
视频标题                         AI生成文案
转发文案                         复制
朋友圈文案                       复制
视频介绍（选填，可展开）
内容设置（归属、版权、来源、原文链接、标签）

保存草稿                         预览发布
```

1. 无视频时用紧凑上传卡片，明确“上传本地视频 / 选择已有视频”。选择器取消不报错，权限拒绝和文件错误有明确反馈。
2. 上传后就地显示缩略图、进度和成功状态；失败保留标题和文案，提供重试/换文件。替换视频成功前保留旧视频，避免坏掉已保存作品。
3. 视频缩略图只负责编辑定位。点击播放打开预览/全屏，避免编辑状态的大播放器遮挡封面、标题和文案。
4. AI就近生成标题、转发文案、朋友圈文案；结果分别可改、可重新生成、可采纳，不覆盖人工修改，不自动编造项目事实。旧视频介绍与caption保持可读兼容。
5. 默认使用当前授权工作空间；单空间显示名称而非要求重复选，多空间提供切换。缺失归属时明确显示在界面上，不能藏在折叠设置里又用“正文块”术语报错。
6. 草稿与发布采用不同完整度规则：未完成草稿可保留编辑进度（需后端配合）；发布前验证主视频完成、标题有效、归属和权属有效、封面可用。校验在字段旁展示并滚动定位首个问题，修正后移除过期提示。
7. 版权、来源、原文链接、标签保留图2已认可能力，作为低频设置收起。采集来源自动带入，允许修正。

## 四、阅读页两种布局

“视频号式/抖音式”定义为本小程序作品落地页样式，与素材来自哪里分开存储；不把小程序内发布等同于向微信视频号或抖音账号自动发片。

- 视频号式（默认）：播放器 → 标题 → 创作者/简短介绍 → 展开详情 → 咨询入口。16:9按内容宽等比，竖屏按可用屏高限高、居中完整显示，不拉伸；长文案正常滚动。
- 抖音式：深色沉浸舞台，完整等比显示；标题和短文案位于底部安全区域，操作数量克制。16:9不强行裁为9:16，长文案通过展开层阅读，控制条与咨询按钮不重叠。
- 编辑缩略图、作品阅读、全屏播放三个场景分别计算空间。可用高度扣除系统状态栏、自定义导航、底部操作和安全区，不只用统一68vh。
- 独立封面用于播放前poster、分享卡片及海报；先显示封面再加载视频。封面裁切预览分别覆盖卡片/海报，不能裁切视频正文。
- 内容缺失/模型为空/格式不支持显示明确异常和重试；媒体失败仍显示标题与文案；作品撤回或无权限显示不可访问。禁止再次出现外围模块完整而正文静默空白。
- 已做访问分析选择的用户不重复展示整张说明卡，保留可查找的设置/关闭入口；未同意前不采集且可正常阅读。不能为了减少干扰而默认同意。
- 保留图4认可的咨询入口；内容正常可读后展示，避免正文失败时咨询卡成为主体。分享操作保持现有归因及版本能力。

## 五、实现复用与新增范围

| 复用现有 | 需要补齐 |
| --- | --- |
| 上传/素材库、授权空间、主视频media_id、独立cover_media_id | 选择结果归一化、上传状态/进度/失败原因、明确当前MP4/50MiB上限及60秒上传超时，避免客户端能力说明与服务端不一致 |
| article_v2、presentation=video、固定版本与预览令牌 | 独立reader_layout和用途明确的文案元数据；前后端能力协商，历史版本默认视频号式 |
| contentwriting流式生成、语音、改写、回填保护 | video场景与结构化多字段输出；每项结果独立采纳，旧值可恢复 |
| 分享卡片、朋友圈入口、复制链接、海报、分享追踪 | 分发文案独立复制和预览，分享标题按渠道取对应字段，不假设可自动填写微信任意长文案 |
| 统一content-presentation展示模型 | 两种阅读布局共用媒体资源与播放事件，增加poster及无内容兜底 |

不重建素材/权限/分享/版本系统；新增字段需前后端一起发布，不能仅上传小程序后宣称全部能力生效。旧正文和已发布版本不原地改写。

## 六、落地顺序与验收

第一批P0：修视频选择契约、同账号相册返回时的回调有效性、上传错误可见性；分项保存校验；定位并修复阅读页正文消失。先闭环真实视频，不以改版遮盖故障。

第二批P1：紧凑视频编辑器、就近封面、提示避让导航、AI多用途文案、视频号式阅读。

第三批P2：抖音式布局、各渠道文案/封面预览、弱网恢复等体验细化。两种布局的字段和接口从第二批预留，避免返工。

验收使用同一真实作品，依次执行：本地选视频 → 上传成功且素材类型为video → 设置封面 → AI生成及分别修改 → 存草稿 → 重进恢复 → 预览 → 发布 → 另一账号从分享入口播放与咨询。覆盖iOS/Android、16:9/9:16/1:1、相册取消/拒绝、超限/弱网/超时、已有素材替换、已同意/拒绝访问分析、历史版本和已撤回作品。

完成标准：上传失败说明具体原因并保留输入；有标题视频时不再显示含糊正文块报错；编辑首屏能看到素材状态和下一项主要信息；阅读第一屏有真实主内容而非大块说明；自定义封面实际出现；预览与接收者阅读一致。回归必须包含微信真实回调字段结构，原生编译或注入view的截图只作为局部证据。

## 2026-11-08 用户最新调整：上传不设业务上限

- 用户要求视频上传不限制时长和大小。取消现有50MiB业务限制，不新增时长门槛；前文50MiB/60秒描述仅为修改前现状。
- 上传采用分片、断点续传、失败分片重试和完成校验；上传进度持久化。单片或单次请求超时与作品大小/时长上限分离，不用一个60秒请求决定长视频是否可上传。
- 上传会话仍校验授权空间与文件安全，完成后生成可播放版本和封面。原片与播放版本分开保存；服务商单对象约束、设备可用空间等基础设施边界在实现时核实并处理，不能宣称物理无限容量。
- 最短主链路：选择视频 → AI生成并就地确认文案 → 预览发布。封面默认取可用首帧并允许更换，授权归属使用有效默认值，来源/版权/标签等低频设置收起。
- 本轮交付为界面效果图及方案更新；尚未修改上传接口、限制或部署配置。
