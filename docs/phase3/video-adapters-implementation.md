# 三期视频链接解析适配层实现说明

## 本次落地范围

`service/contentimport` 新增了两条独立解析通道：

- 抖音、小红书：服务端调用配置好的豆一豆解析网关，返回可供后续入库任务使用的视频源地址和原生内容 ID。
- 视频号：实验性元宝适配器先将视频号分享链接换成微信预览参数，再调用视频号预览接口取得 `feedInfo` 中的视频地址。

适配层只产生 `Source`。它不代表视频已下载、已持久化、已发布，也不代表已完成像素级去水印验收。`WatermarkExtraction` 只表示走的是平台解析通道。

## 可直接复用的能力

- 复制文案可直接提取其中的受支持 URL。
- 抖音长链归一到 `jingxuan?modal_id=`，小红书长链归一到 `/explore/{note_id}`。
- 小红书 `xsec_token` 原样保留；短链统一升级HTTPS后交给配置的解析服务，甲第服务不自行跟随未知重定向。
- 返回视频地址后由上层已有入库任务继续做下载、存储与发布状态管理。

## 安全与失败边界

- 解析服务的 host/path 固定在代码中，调用方不能指定任意 endpoint。
- 输入链接按精确 host 边界校验，拒绝用户名、密码、非默认端口、内网和任意域名。
- 所有请求最长 25 秒、响应上限 2 MiB，不自动跟随 3xx。超时和 5xx 标记为 `submission_uncertain`，且不自动重试付费请求。
- 豆一豆凭据只通过 `DouyidouConfig` 传入。元宝 Cookie 只通过 `YuanbaoConfig` 传入，不读取环境变量，不记录到日志，不传到 `channels.weixin.qq.com`。
- 元宝预览地址必须是 `channels.weixin.qq.com/finder-preview/` 且同时带有 `token` 和 `eid`。
- 返回 `decodeKey` 的视频标记为 `unsupported_encryption`，本期不伪装成普通 MP4 成功。只有元数据而没有视频 URL 时返回 `metadata_only`。
- 元宝通道必须显式开启；缺 Cookie、登录失效和风控均失败关闭，不回退到 PC 抓取、固定用户头或伪造设备头。

## 当前验证状态

自动化测试覆盖：豆一豆签名固定向量、解析字段兼容、原生 ID 校验、平台排除、元宝两步 payload、Cookie 不跨 host、H264 优先级、仅元数据、加密视频、登录/风控失败关闭、超时、响应上限和禁止重定向。

本轮未调用真实豆一豆或元宝账号，未读取任何真实 Cookie、AppSecret 或生产配置。真实可用性还需在安全的服务端环境中，用合法授权的测试账号和指定样本做集成验收。

集成任务、真实样例结果和剩余验收边界以 [完整方案](content-import-plan-20261027.md) 为准。
