## 1. 产品缺陷（已修复）

| ID | 严重度 | 现象 | 根因 | 处理 | 验证 |
|---|---|---|---|---|---|
| D-1 | 高 | 订单中心点击虚拟支付订单号 → 白屏 | 跳转目标 `/virtual-pay`，路由实为 `/virtualpay` | 修正路径 | 路由一致性脚本（红→绿）；浏览器点击后落在 `/virtualpay?keyword=…` |
| D-2 | 高 | 模板"取消精选"必然 400 | `bool` 加 `binding:"required"`，`false` 被当作缺失 | 请求结构体改指针 | 7 个绑定单测；真实接口：旧版 400 → 新版 200 |

| D-5 | 高 | "仅看异常单"漏掉其他页的异常单，计数只是本页数量 | 只在前端过滤当前页 50 条 | 后端 `status=exception`（失败+待处理）全量筛选 | 4 个单测；真实接口旧版 `total=0` → 新版 `6`；浏览器显示"6 条异常" |
| D-6 | 中 | 输入错误网址整页空白 | 路由表无兜底 | 加 `*` 兜底回总控台 | 浏览器验证 |
| D-11 | 低 | 约 1000 行死代码 | 旧页面/模块无引用 | 删除 | 全仓库引用检索；`tsc`、构建 |
| **J-1** | **高（阻塞调试）** | **`npm run dev` 开发模式整个后台白屏** | `react-icons-fi-proxy.js` 用 `export *` 转发 CJS 入口：生产构建由 Rollup 转换可用，开发服务器把 CJS 原样发给浏览器，没有任何具名导出 | 别名只在 `build` 时启用，开发走包自带 ESM 入口 | 浏览器可正常渲染；生产构建哈希不变 |

## 2. 观察到、**未修改**的问题（需要你决定）

| ID | 严重度 | 现象 | 根因 | 建议 | 为什么没改 |
|---|---|---|---|---|---|
| **J-4** | 低（监控噪音） | 浏览器中途取消请求（如页面跳转）会在日志里记成 **503**。实测：40 个"发出即断开"的请求 → 40 条 503 | `ManagementAccessRequired` 里 `readManagementAccess(c.Request.Context(), …)` 在客户端取消后返回 `context canceled`，被当作"授权服务不可用"返回 503 | 遇到 `errors.Is(err, context.Canceled)` 直接 `Abort`，不返回 503 | **这是鉴权中间件**，按"安全相关代码把握不足须人工审查"的规则，只给出建议，不擅自改。用户不受影响，但线上若按 5xx 告警会产生**假警报** |
| **J-5** | 中（待线上确认） | 迁移 `sync_enterprise_wechat_phones_to_identities.sql` 在本地报 `Illegal mix of collations`，被跳过（仅告警） | 该 SQL 跨表比较字符串时没有显式 `COLLATE`；当两张表排序规则不同就会失败 | ① 在线上执行 `SELECT TABLE_COLLATION, COUNT(*) FROM information_schema.TABLES WHERE TABLE_SCHEMA=DATABASE() GROUP BY 1` 确认是否一致；② 迁移 SQL 里显式写 `COLLATE` | 本地的报错是我自己给 MySQL 加了 `--collation-server` 造成的（已移除，现已不再出现）；线上是否一致**我无法判断** |
| J-6 | 低 | 启动时每次打印 6 条 `增量结构检查: Duplicate column / Duplicate key` 错误 | 启动时无条件执行 `ALTER TABLE ADD COLUMN`，再把"列已存在"当错误打印；**全新数据库上同样出现** | 先查 `information_schema` 再 `ALTER`，或忽略 1060/1061 | 无害，但会淹没真正的错误；不是阻塞项 |
| J-7 | 低 | 首次启动时 `management_crm_link_intent_up.sql` 报 `Table 'management_crm_link' doesn't exist` | 白名单自动迁移依赖 `customer_management_bridge_up.sql` 先手动执行 | 新环境先 `migrate` 再首次 `start`（`dev.sh bootstrap` 已固化顺序） | 生产按手册已先迁移，不受影响（fail-soft，仅日志） |
| J-8 | — | `/crm/source-sync` 在来源表未就绪时返回 503 | 设计如此，页面显示"来源接入表未就绪"，已优雅降级 | 无 | 不是缺陷；补跑迁移后恢复 200 |

## 3. 联调工具自身的问题（已修复，非产品缺陷）

| 问题 | 发现方式 | 处理 |
|---|---|---|
| 端口 18080 被无关容器 `gexiang-searxng` 占用，后端启动失败且 stdout 为空 | 排查日志发现服务把日志写在 `APPlog/` 按天文件 | 改用 28180；`dev.sh` 失败时直接展示真正的日志 |
| 种子数据撞 `users.openid` 唯一索引 | 运行报错 | 每个账号给唯一占位 openid |
| E2E 脚本"0/0 通过"——装饰器只定义不执行，**假绿** | 结果数为 0 | 改为定义即执行，且"零个检查被执行"视为失败 |
| 种子工具护栏对**空 DSN** 放行 | 为护栏写单测时发现 | 空 DSN 直接拒绝，补单测 |
| 种子订单没有支付通道（`CreateDetailed` 不写 `pay_channel`） | D-1 的 E2E 找不到虚拟支付链接 | 种子后幂等校正 |
| 本地 MySQL 排序规则混用 | 日志里的 `Illegal mix of collations` | 移除覆盖，`reset` 后从零重建验证 |
