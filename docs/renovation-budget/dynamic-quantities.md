# 装修预算动态算量约定

装修预算 `renovation-dynamic-v2` 保留现有报价清单、单价、档次系数、旧房系数和费用规则，只把原先固定的示例工程量改为按房屋空间动态计算。它是甲地灵光的参考测算规则，不是土巴兔内部公式。

## 两种算量模式

- `estimated`（快速估算）：按各层面积和房间数量分配空间面积。默认房型面积权重为卧室 12、客餐厅 20、厨房 8、卫生间 5、阳台 6；这是可调整的产品估算配置。空间长宽根据面宽/进深比例推导，未填写的门窗、窗帘盒、背景墙和橱柜使用安全的参考尺寸，并在 `geometrySummary.estimatedFields` 中标明。
- `measured`（实测）：每个空间必须填写长和宽，面积以全部空间 `长×宽` 的合计为准。层高优先级为“空间层高 → 测量楼层层高 → 分层设置层高 → 全屋层高”。门窗洞口留空按 0 处理，不冒充实测值。

`measurement` 中的楼层索引和空间实例索引均从 0 开始，例如首层第一间卧室为 `0.bedroom.0`。显示名称仍从 1 开始。估算模式不会把推导的长宽写回 measurement；用户切换实测后看到的是空字段或自己此前录入的值。

权重用于比例分配：`房间估算面积 = 本层面积 × 该房型权重 ÷ 本层所有房间权重之和`。总面积变化后重新分配，周长随矩形形状推导，不按100㎡样本锁定。空间尺寸模式不使用此房型比例；矩形以外的施工量可在明细中手工修正。

公开报价携带精简来源枚举：`estimated`、`measured`、`mixed`。涉及橱柜、背景墙等缺少实际尺寸而推导的项目时标为“含估算项”。实际统一层高按有效高度展示；不同楼层/空间高度时显示“分层/空间设置”，原始测量数组不公开上传。

## 工程量公式

对每个空间先计算：

- 地面面积、顶面面积：`长 × 宽`
- 周长、石膏线：`2 × (长 + 宽)`
- 墙面净面积：`周长 × 层高 - 门洞面积 - 窗洞面积`
- 踢脚线：`周长 - 门宽`
- 窗帘盒：显式长度优先，否则参考窗宽
- 电视背景墙：显式面积优先，否则每层首个客餐厅按一面墙 `宽 × 层高` 估算
- 橱柜：显式长度优先，否则按厨房两边墙 `长 + 宽 - 门宽` 估算
- 厨卫阳台包管：按 `层高 ÷ 3` 折算原清单中的“项”

工程量汇总保留 6 位小数，分项金额按元舍入。门窗洞口不得超过毛墙面积，门宽不得超过空间周长。

## 全屋项目

- 网络电视点位：卧室数 + 客餐厅数
- 电箱：`2 × 层数`
- 开槽修复：`层数`
- 开关布线、安装、给水、搬运、保洁、保护等面积系数项目继续按动态总面积计算
- 门、洁具、灯具和门槛石按相关空间实例数计算；现有两个厨房门槛石分组均保留

手工 `selections.quantities` 始终优先于动态工程量，排除项目和管理费、设计费、税金选项保持原规则。全屋房间数均为 0 时允许只计算公共工程。
