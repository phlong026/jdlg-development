# 预算结果页分享检查（2026-10-22）

范围：当前 `JDLG-home-restore` 前端和 `https://api.jiadilingguang.com` 真实 API。用户请求检查预算结果分享给好友的卡片和朋友圈；本轮只检查与记录，未部署服务器或修改生产数据。

## 结论

前端已经实现两类卡片与同一份结果的分享逻辑，但当前线上完整链路不可用：创建、读取分享报告的 API 均返回纯文本 HTTP 404。不能把代码与本地测试通过当作实际分享验收通过。

| 项目 | 检查结果 |
|---|---|
| 好友卡片 | 已有独立图片生成逻辑，标题使用当前地区、面积和金额，路径携带 `report_id` |
| 朋友圈 | 已有独立方图，标题与当前结果一致，`query` 携带同一 `report_id` |
| 接收者打开 | 实现为按编号匿名读取服务端快照，不回退到接收者本机旧预算 |
| 两类分享开放时机 | 当前报告保存成功且两张封面均就绪后，才设为可分享 |
| 线上报告创建 | POST `/api/v1/miniprogram/ai/cost/shares`，当前 404 |
| 线上报告读取 | GET `/api/v1/miniprogram/ai/cost/shares/:id`，当前 404 |
| 真实好友/朋友圈发送和跨账号打开 | 未执行，现有 API 阻塞，不能认定可用 |

页面目前的操作流程为：生成预算结果 → 点击“准备分享报告” → 登录（尚未登录时） → 保存公开快照并生成封面 → 发送给好友或右上角分享到朋友圈。当前 API 缺失会让准备过程报错，分享就绪状态保持关闭。

## 本次线上验证

请求中未携带任何 token，未创建报告记录。读取使用 32 位合法格式、专用于探测的不存在 ID；创建探测仅发送空对象且不带认证，正确部署的路由应先拒绝匿名创建。

- GET 不存在 ID：实际 `404`、`text/plain`、`404 page not found`。当前实现应为 JSON `code:404`、`分享报告已失效或不存在`，附 `Cache-Control: no-store`。
- 无认证 POST `{}`：实际 `404`、`text/plain`、`404 page not found`。当前实现应为 HTTP 401、JSON `code:401`，且不会建立快照。

原始有界探测结果见 `预算分享线上接口探测.json`。这说明当前公网 API 未提供该路由；具体是服务版本或路由转发问题，需要部署侧继续核对，不以 404 单独断言某个服务器版本。

- 前端分享、快照 DTO、封面绘制、朋友圈路由及报告测试：72 项中 69 通过、0 失败、3 跳过。
- 后端 `CGO_ENABLED=0 go test ./model ./route -run '^TestCostEstimateShare' -count=1`：两包通过，11 个顶层用例及 DTO 子用例通过。
- 验证覆盖：分享链接与卡片金额一致；两渠道使用同一快照；跨账号匿名读取；无效/过期链接不展示本机预算；封面失败不开放分享；匿名写入拒绝、撤销、限流、Redis 故障。
- 代码位置：`pages/aicostresult/aicostresult.ts`、`utils/costEstimateShare.ts`、`utils/costEstimateShareImage.ts`；后端为 `service/route/cost_estimate_share.go`、`service/model/cost_estimate_share_redis.go` 及 `service/route/index.go` 注册点。

## 修复与验收目标

1. 在正确的现有 API 服务中接通报告创建、匿名读取路由及现有 Redis；当前实现不需要新增表或迁移。
2. 从真实体验版创建一份不含个人信息的测试预算，确认拿到 `report_id`，并核对好友、朋友圈各自封面和标题。
3. 使用另一账号分别打开两种分享，确认地区、面积、金额及明细与原始报告一致；再验证过期/失效状态。

快照当前有效期 30 天。服务端只保存用户主动公开的当前预算副本。此次没有通过改封面或拼 URL 来绕过结果持久化依赖，也没有提交微信审核或正式发布。
