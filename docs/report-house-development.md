# 整屋图文报告开发计划

基于已确认的旧版整屋内容框架，新增 `report-house-v1` 协议，保留旧协议读取和已购报告。遵循先测试后实现；不重写支付体系、不增加依赖。

清理/改造范围：固定十页限制只留在 V5；新协议采用方案/楼层/资产结构和动态分页。统一识别决策类协议，复用输入确认、任务领取和阶段缓存。旧演示脚本仍仅用于样稿，不参与生产生成。

分工：主代理拥有输入、协议路由、worker、模型多模态适配、配置和集成；内容实现拥有 `report/house_content*`、`house_orchestrator*`；图片实现拥有 `report/house_images*`、图片 SQL 和底层绘图配置适配；排版实现拥有 `reportpdf/house*` 和 `render.py` 的新协议分派。

共享数据合同见 `service/report/house_types.go`。新输入为 `DecisionInput.house`，完整快照为 `DecisionSnapshot.house`，页面增加 `illustrations`。预览四页保持冻结；完整报告必须保留相同事实与诊断，确认只使用 confirm/undecided，不把客房 A/B 当整屋方案选择。

验收：不同居住模式/层数/房间需求改变结构化方案和图像任务；整屋需求拒绝项被保留；每图关联同方案版本；图片提交结果未知不重复计费；成功图片可恢复；视觉审核实际接收图片；动态 PDF 不截断、缺图不发布；旧 V5/旧十四页回归；新 API→异步→确认→测试支付→生图替身→真实 PDF→下载归属集成。

上线边界：真实模型、数据库迁移、支付、企微权限需凭据环境验证。编码及模拟测试不等于生产发布或建筑专业验收。
