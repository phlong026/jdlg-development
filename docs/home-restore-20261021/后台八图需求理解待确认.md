# 后台八图需求理解（待用户确认）

本轮只记录理解，没有修改对应后台页面。图片中的标注作为用户提供的需求证据，不扩展为改变支付、权限、客户归属或统计口径的授权。

| 图片 | 需求理解 |
| --- | --- |
| 图1 销售线索 | 客户标题优先展示可识别的姓名、微信号或手机号，避免只显示「用户4」「用户258」。已有联系方式应直接可见；未留资时保留真实的未知/未留资状态，不虚构联系方式。 |
| 图2 虚拟支付统计 | 把虚拟支付订单、待处理、发货中、退款等8项指标整合为一个紧凑统计区，缩小卡片高度和间距，各项数量与含义保留。 |
| 图3 支付配置状态 | 总开关、OfferID、生产AppKey、推送Token/AESKey等改成紧凑的配置状态行，减少纵向占用；凭据继续仅显示配置状态。 |
| 图4 侧边菜单 | 当前销售管理入口名称调整为「客户管理」，相关页面标题保持一致；总览、线索、客户的业务关系保持原有口径。 |
| 图5 渠道/排名列表 | 修复姓名列被挤压、裁切的问题，姓名可完整辨识；序号、身份标签和统计数字排版互不遮挡。 |
| 图6、图7 素材视角 | 缩略图、标题、发布状态和「查看原图」收拢在卡片上部；看过账号、匿名访客、被看、转发和停留时长紧凑排列；下方动作缩小留白，保留完整内容与访客查看能力。 |
| 图8 客户报备 | 清晰展示客户归属人，例如甘总，以及系统记录的报备时间；地址改为选择后回填，预计建房时间用选择器；补充备注默认展开，仍为选填。 |

图8的「自动选择」暂按“分级地址选择并回填、建房时间选择器”理解。需要用户确认是否还要求按当前账号所属地区自动带出默认值。客户归属人、原报备人、报备时间及预计建房时间应各自表达，不能混成一个字段。
