# 分享标题、封面与落地内容一致性排查

2026-10-21，针对用户反馈「测算页面正确、首页错误」。审计工作树为 JDLG-home-restore；本轮只修首页并给出其余入口的处理方案，不代表线上包已更新，也未修改待确认的后台界面。

## 首页证据与修复

- `wx.getImageInfo` 在原生模拟器成功读取包内 home-timeline.jpg，1280×1280、JPEG，原图未损坏。原生分享预览却显示破图；仅改变路径前导斜杠仍未解决。
- 将两张原始封面复制到 `wx.env.USER_DATA_PATH`，分享回调使用复制成功后的微信本地文件路径。文件内容和既定好友/朋友圈封面保持一致，不下载其他图片、不修改图像。
- 模拟器已经实际显示朋友圈缩略图与「甲第灵光 · AI建房助手」标题。证据：`模拟器-朋友圈封面已渲染.png`。点击「查看小程序分享页」后显示山水首页；这不替代真实微信的场景1154及跨账号验收。
- 原首页 `onShow` 无条件尝试恢复 `report_login_return`。当存在有效缓存且已登录时，会跳到旧报告。新首页分享显式携带 `from=share`，只在进入时清理已有的旧报告返回记录；同一首页实例后来产生的新登录返回仍可恢复报告。此项是代码可复现的条件路径，尚无证据证明就是用户线上本次异常的唯一原因。
- 分享标题由同一常量提供，好友路径和朋友圈当前页都指向首页。朋友圈菜单等待封面复制成功后开放，页面隐藏后异步完成不会改变其他页面菜单；好友首次分享通过promise等待。复制异常记录原因，朋友圈保持关闭，好友由微信使用当前首页截图，不冒充另一内容的封面。

## 系统性审计结果

现有58条路由中，菜单规则可能暴露25个朋友圈入口：14个品牌/目录/表单入口、6个公开详情、1个已发布版本阅读页、2个个人作品入口、1个邀请入口、1个个人中心。

| 问题 | 已确认的代码行为 | 解决方案 |
| --- | --- | --- |
| 部分页面卡片标题泛化 | tracking 默认朋友圈回调统一返回「甲第灵光 · AI建房助手」，不使用现有好友回调中的对象标题、封面 | 每类内容由同一个已加载对象生成分享描述，好友和朋友圈各自适配路径与参数；加载未完成时不开放内容分享 |
| 我的方案打开其他内容 | myplan 的朋友圈只带方案id，微信仍打开 myplan；该页不读分享id，而读取当前访问者自己的方案列表 | 已公开方案进入对应公开详情后分享；草稿及待审内容先生成显式分享快照，不能直接分享个人列表页 |
| 生成作品接收者打不开 | generatedetails 带私有 task_no；接收端按自己的登录态请求任务，后端严格限制任务所有者 | 增加普通用户有权创建的作品分享快照，只公开选中的标题与媒体，再由公开阅读页分享；保持私有任务接口原有鉴权 |
| 多图封面与首图不一致 | 生成作品及模板详情的封面取当前选中图，但参数仅有任务/模板id，接收端默认显示第0张 | 在分享版本中绑定稳定图片标识，打开后恢复同一张图；不要只依赖可能重排的数组下标 |
| 登录后丢失原内容 | 登录成功固定进入首页，没有普遍恢复目标内容的机制 | 公开阅读优先支持匿名；需要登录的操作保存经过校验的原内容目标，登录完成后恢复 |
| 个人中心与邀请奖励页不适合作公开落地 | 显式定义朋友圈回调的私有页面也会被开放，个人中心返回访问者自己的内容 | 个人中心进入公开主页再分享；邀请使用公开邀请落地页，只传邀请码与公开邀请信息 |

关键源码：

- `miniprogram/miniprogram/utils/tracking/index.ts`：默认分享、菜单条件、参数白名单。
- `miniprogram/miniprogram/pages/myplan/myplan.ts`：onLoad不读取方案id、onShareTimeline只传id。
- `miniprogram/miniprogram/pages/generatedetails/generatedetails.ts`：私有任务加载、当前图封面、朋友圈参数。
- `miniprogram/miniprogram/pages/templatesquaredetails/templatesquaredetails.ts`：加载时图片索引归零，分享未携带图片身份。
- `miniprogram/miniprogram/pages/contentreader/contentreader.ts`：已有 content_id + content_version 的公开版本阅读模式。
- `service/route/ai.go`：任务状态校验所有者。
- `service/route/share_tracking.go`、`share_tracking_materials.go`：现有公开版本阅读可复用，但创建/发布权限属于管理端，普通小程序素材接口仅提供读取。
- `service/tracking/legacy.go`：统计用元数据只有标题和封面，不是完整正文/媒体快照，不能冒充完整分享内容。

## 建议实施顺序

1. 先完成首页封面可读、标题固定、分享落地优先的修复。本轮已经本地验证。
2. 公开案例、工具和设计师详情补同源分享描述、多图恢复、加载就绪保护；测算页按用户已确认表现做对照回归。
3. 为个人作品提供显式的「创建分享」能力，校验所有权并产生固定内容版本；进入公开阅读页后再从该页分享到朋友圈。朋友圈分享使用当前页面与query，不能靠在朋友圈回调新增path切换落地页。
4. 验收逐项比对发送前的标题、选中图片、内容标识/版本，与接收者实际看到的标题、图片、内容；覆盖未登录、不同账号、第二张图片、内容撤回、首次分享和连续分享两份内容。

微信机制依据：腾讯云 CloudBase 官方文档 https://docs.cloudbase.net/recipes/add-share-with-params-miniprogram 。

目前只确认首页的本地修复与模拟器预览，其余审计项是明确待实施/验证的方案，不应宣称全站一致性已经完成。
