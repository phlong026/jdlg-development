# 管理后台 UX 六维度分析报告

- 日期：2026-10-07
- 方法：本地真实环境（种子数据）+ Playwright 对 26 个页面截图（桌面 1366px + 手机 390px）逐页视觉审计 + 全站代码扫描（技术文案、样式、交互路径）
- 分析维度：① 是否满足使用需要 ② 是否站在用户角度设计 ③ 是否容易操作 ④ 半年后开发者能否看懂 ⑤ 开发语言文字是否泄漏到前端 ⑥ 是否可再精简 ⑦ 是否对标同行优秀设计
- 总评先行：**导航与信息架构已经达到合格线（9 组导航、⌘K、灰度回退都对标了主流后台），但"页面内部"参差不齐——销售线索页是新标杆，AI 配置页仍停留在"程序员自用工具"水平。**

---

## 0. 六维度总览

| 维度 | 结论 | 依据 |
|---|---|---|
| ① 满足使用需要 | **基本满足，三个缺口**：总控台没有"今日待办"；财务对账缺导出闭环；客服缺工单提醒 | §1、§3、§6 |
| ② 用户视角设计 | **一半一半**：销售线索、订单中心已按角色场景组织；风控与增长仍是"功能堆放" | 各模块 |
| ③ 容易操作 | **高频路径顺，低频路径绕**：核心列表页 1~2 步可达；但充值配置藏在二级入口后无面包屑树、"返回订单中心"是唯一路径 | §3、§9 |
| ④ 半年后可懂 | **中上**：导航有分组说明、队列有数量角标、代码有中文注释与记录文档；风险点是 AI 配置的协议枚举、部分魔法数字（灵石）无解释 | §4 |
| ⑤ 开发文字泄漏 | **存在，集中在 AI 运营模块**：task_type/provider_code/protocol_type/json 编辑区直出；另有 7 处搜索框让用户"输入用户ID"、2 处 openid、全站唯一 emoji 图标 | §4 |
| ⑥ 可再精简 | **可以**：日志管理（空壳）、商机（占位）、报表导出与内容分析疑似重叠；页内重复的"刷新"按钮、双份分页信息 | §7 |
| ⑦ 对标同行 | **骨架对标了（企业微信/钉钉式导航），皮肤没对标**：主按钮蓝棕混用、边距两套、emoji 图标、空状态假文案，这些在成熟 SaaS 里不会存在 | §8 |

## 1. 工作台（/dashboard）

**① 使用需要**：展示了用户/订单/认证/工单四类统计、趋势图和系统入口，作为"日报墙"合格。**缺口**：没有"待我处理"清单——运营每天真正要做的事（待审认证 N 条、超时工单 N 条、超时线索 N 条）散在各页的角标里，总控台只给数字不给入口直达。同行做法（企微/飞书工作台）首屏就是待办列表 + 一键跳转。

**② 用户视角**：统计卡是"老板视角"（大盘怎么样），不是"操作者视角"（我今天要干什么）。10 人以上团队共用一个总控台，没有按角色定向。

**③ 操作**：图表区无钻取（点了柱子不能跳到对应订单列表），数字与行动断开。

**④ 可维护**：良好。卡片有中文标题与说明。

**⑥ 精简**：「系统入口」卡片列了一堆快捷跳转，与新导航重复——导航精简后它的历史使命已结束，是明确的可删项。

**改进**：把四个统计卡换成或补充"今日待办"清单（待审认证/超时工单/超时线索/待处理线索，每项带数量和直达链接）；删除"系统入口"卡；图表点击钻取留作中期。

## 2. 用户账号组（/users、用户 360、设计师、认证审核、会员运营）

**① 使用需要**：满足。列表 + 360 详情 + 关联线索跳转，覆盖了账号管理主流程。

**⑤ 开发文字泄漏（重点问题）**：搜索框文案是"搜索用户名、用户 ID 或手机号"——**让运营输入"用户 ID"是开发视角**，运营手里只有手机号或昵称；风险控制页同样让搜"设备 ID"，虚拟支付页让搜"openid"。手机号/昵称应为主搜索方式，ID 类字段保留但移入"高级筛选"。

**③ 操作**：用户列表页顶部有一段"当前显示 12 条，本页范围 1-12 / 12 建议：确认目标用户后，优先进入用户 360 继续…"的操作指导文字——**用小作文教用户怎么用页面，说明页面本身不自明**；分页信息出现了两遍（"第 1/1 页"和"当前显示 12 条"）。搜索图标是 emoji 🔍（全站唯一），与其它页的线性图标不一致且偏大。

**用户 360**：信息分区清晰（基础信息/订单/灵石/会员/关联线索），调整灵石已强制填原因——这两点对标了财务系统做法，好。缺口：调整灵石弹窗没有"当前余额"回显和单次上限提示（资金护栏的一半）。

**改进**：搜索主文案改"搜索手机号/昵称/用户名"，ID 移入高级筛选；删掉指导小作文和重复分页行；🔍 换成与全站一致的 `FiSearch` 线性图标；灵石弹窗加当前余额回显。

## 3. 订单与支付组（订单中心、虚拟支付、充值配置、会员计划）

**① 使用需要**：订单中心有状态/类型/渠道三维筛选 + "仅看异常单"开关 + 统计卡，满足运营日常。**财务缺口**：没有 CSV/Excel 导出按钮，对账只能截图或翻数据库（报表导出页在另一个分组，且两边口径是否一致未知）——这是财务角色最大的痛点。

**② 用户视角**：虚拟支付监控的搜索框让财务输入 "openid"（微信开发术语），应改为"微信用户标识（openid）"并在说明里解释，或提供手机号反查。

**③ 操作**：充值配置/会员计划收进二级入口后，返回路径只有右上角"返回订单中心"文字链，**没有面包屑**（用户 360 有面包屑，二级页没有，不一致）；从充值配置到会员计划要回退再进。

**⑦ 对标**：订单主按钮棕色、模板页蓝色（`#3b82f6`），同类操作两种颜色，成熟产品不会有。

**改进**：订单中心加"导出当前筛选结果（CSV）"；二级页加面包屑"订单与支付 / 充值配置"；统一按钮色。

## 4. AI 运营组（AI 任务中心、AI 工具、AI 配置）—— **全站问题最重的模块**

**⑤ 开发文字泄漏（重灾区，逐项列出）**：

| 位置 | 直出的开发概念 | 运营的理解成本 |
|---|---|---|
| AI 配置列表 | 协议类型列直接显示 `gemini_sync` / `toapis_async` | 无从理解 |
| 配置表单 | 任务类型 `ai_draw`/`ai_chat` 枚举值 | 高（列表页做了中文映射，表单里没有） |
| 配置表单 | 供应商编码 `provider_code`、API Key 位置 `header_bearer`/`header_custom`/`query`/`body` | 高 |
| 配置表单 | prompt_path / image_path（"提示词在 JSON 中的路径"） | 极高，等于要求会写 JSONPath |
| 计费配置 | `extra_config` 的裸 JSON 编辑框 | 极高 |

**这个页面的本质**：它是一个"AI 网关运维工具"，任何一项配错（比如 body_template 的 JSON 少个括号）任务就全挂，而界面没有"测试连接"按钮（改完只能等真实任务失败才发现）。**当前设计事实上要求使用者是半个程序员。**

**④ 半年后可懂**：如果半年后要换人来维护，靠界面本身推不出"这条配置管什么"——协议枚举、路径语法都没有解释文案。`ai-config.tsx:26-28` 已有 protocolLabel 中文映射函数，但只用在部分位置，映射没有铺满。

**改进（按投入排序）**：
1. **铺满中文映射**（半天）：表单里 `ai_draw`→"AI 绘画"、`gemini_sync`→"同步返回"，`header_bearer`→"请求头携带（推荐）"；每个技术字段加一句灰色说明。
2. **加"测试此配置"按钮**（1 天）：后端已有真实调用能力，补一个 `POST /ai/api/config/:id/test`，用 1 灵石跑一次最小请求返回成功/失败原因。这把"配错只能等炸"变成"配完立即验证"。
3. **JSON 字段改结构化表单**（中期）：headers/body_template 用键值对编辑器代替裸 JSON。
4. 明确这个页面的目标用户：如果只有开发者用，应在分组说明里写明"技术人员使用"，避免运营误入。

## 5. 内容运营组（模板、灵感、实用工具、内容分析）

**① 使用需要**：满足。模板卡有图、价格、状态、精选标识。

**③ 操作**：上架一个新模板的路径清晰（创建模板 → 填表 → 上架 → 精选），但**主按钮是蓝色**，与全站棕色冲突（`templates.scss:138` `background:#3b82f6`）；灵感素材页同为蓝色。

**⑦ 对标**：内容型后台（小红书创作者中心、有赞商品管理）的共同做法是"卡片网格 + 批量操作工具条"，模板页已具备卡片网格，缺批量上架/下架。

**改进**：统一主按钮颜色（删掉各页自定义，收敛到全局变量）；补批量状态切换。

## 6. 异常工单（/support-tickets）

**① 使用需要**：**不满足"客服第一屏"场景**。客服上班第一件事是"有哪些新工单要处理"，现在入口是搜索框 + 两个下拉，需要先点筛选才看到待处理列表；且没有"待处理数量"角标（导航上没有、页面里也没有）——与销售线索页的队列 Tab + 角标设计形成落差。

**⑥ 精简**："工单搜索"标题卡 + 说明文字占了首屏显要位置，**入口视觉权重高于内容**，可删（搜索框自带 placeholder 已说明用法）。

**改进**：照搬销售线索页的成熟模式——队列 Tab（待处理/处理中/今日新增/已超时/全部）+ 数量角标 + 默认落在"待处理"；删标题说明卡。

## 7. 销售线索组（线索、商机占位、客户管理）

**全站标杆**。入口三卡（客户/线索/商机）、简报、环形图、队列 Tab + 角标、与用户 360 互跳、CRM 未接入时灰态标注——这套结构与企业微信销售页同构，数据口径已对齐（数量与列表一致），手机端可用（卡片压缩但不重叠）。

**残留小问题**：① "未接入 CRM"/"未启用"的灰卡点击后仍会跳转（客户管理页/占位页），期望是置灰不可点或点击弹说明；② 商机是占位页，半年后开发者看到它需要查文档才知道"为什么存在"——建议在页面里写清"规划中，预计 XX 后启用"或干脆从入口移除。

## 8. 风控与增长（风控台、分销邀请、报表导出）

**② 用户视角**：分析报告已自我认定"三者关系较弱，是拼凑分组"（2026-10-05 反思记录第 4 条）。风控台是"查这个人有没有问题"（客服/风控场景），分销是增长运营，报表是财务——三个角色被迫共享一个入口。

**改进**：等 2 周访问日志数据后重新分组（这也是原计划的灰度校准动作）；报表导出与订单中心的导出能力合并（见 §3）。

## 9. 系统设置（AI 配置入口、OSS、日志管理）

**日志管理（空壳）**：空状态文案写"日志数据会在系统运行过程中自动记录"——**这是假的**（`logs` 表全工程无写入）。用户会以为"系统正常只是还没产生日志"，永远等不来数据。这是最典型的"界面撒谎"。方案：按《权限与审计设计方案》改为操作审计页；改之前至少把空状态文案改为"该功能尚未启用"。

**OSS**：上传已补大小/类型限制（本轮修复）；空表时表头居中与其它页左对齐不一致。

## 10. 改进方案汇总

### A. 速赢（1~2 天，零风险，建议立即排）

| # | 改动 | 涉及 |
|---|---|---|
| A1 | 全站主按钮统一为棕色主题（删 templates/inspirations/users 等页的蓝色自定义） | scss |
| A2 | 搜索框文案去 ID 化：主搜索改手机号/昵称/用户名，ID/openid 移入高级筛选并加说明 | users/riskControl/virtualPay/orderCenter/supportTickets |
| A3 | 删 🔍 emoji 换线性图标；删用户页指导小作文与重复分页行；删工单页标题说明卡 | users/supportTickets |
| A4 | 空壳日志页空状态文案改为"该功能尚未启用" | logs |
| A5 | 灰卡（未接入 CRM/未启用商机）置灰不可点，或点击弹窗说明 | customerLeadHub |
| A6 | 二级页（充值配置/会员计划）加面包屑，与用户 360 一致 | rechargeConfig/membershipPlans |

### B. 中期（1~2 周，按角色场景重组）

| # | 改动 | 价值 |
|---|---|---|
| B1 | 总控台加"今日待办"清单（待审/超时工单/超时线索，直达链接） | 10 人团队每天省 10 分钟找活 |
| B2 | 工单页照搬线索页队列 Tab + 角标模式 | 客服第一屏 |
| B3 | AI 配置页中文映射铺满 + "测试此配置"按钮 | 把运维工具变成管理员可用 |
| B4 | 订单中心加筛选结果导出 CSV | 财务对账闭环 |
| B5 | 灵石调整弹窗加当前余额回显 + 单次上限 | 资金护栏（配合审计方案） |
| B6 | 删除总控台"系统入口"卡；评估日志页→审计页改造 | 减负 |

### C. 待你决策

1. 「商机」占位入口：保留（写明规划）还是先移除？
2. 「风控与增长」分组：等访问日志数据再定，还是先拆？
3. AI 配置页目标用户是谁（只有开发者用，还是也要给运营用）？答案决定 B3 做到什么深度。

### 对标差距总结（维度⑦）

与企微管理后台/有赞/Shopify Admin 这类成熟产品比，当前差距不在骨架（导航、分组、⌘K 都有了），而在三件"皮肤"：**一致性**（按钮色/边距/图标/空状态四个统一）、**诚实的空状态**（不假装功能存在）、**行动闭环**（数字 → 待办 → 直达处理）。做完 A + B1/B2，整体观感可以从"内部工具"提升到"可交付给客户的产品级后台"。
