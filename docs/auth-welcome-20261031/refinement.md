# 登录布局第二轮优化

## 修改前判断与方案

原登录卡片按固定 900rpx 介绍区排列，在高屏底部留下大块空白；功能小标题与背景纹理相互干扰，卡片副文案偏浅。

用既有布局改为弹性分配空间，让登录区域贴近底部安全区，短屏继续自然滚动。调整现有渐变和文字颜色、行高，保留原版 Logo、图标、字体、文案和登录流程。不新增素材或依赖。

修改前已有 59 项欢迎页、登录与资料门禁回归通过。本轮样式变更以原生模拟器长短屏截图核验，继续运行现有测试。

## 实施与验证

- 修改 `styles/_auth-welcome.scss`、`components/login-guard/login-guard.scss`、`pages/login/login.scss` 三处样式。复用现有结构与素材，无逻辑改动。
- 介绍区使用弹性空间填充，卡片不压缩，底部仅保留 24rpx 与设备安全区。独立登录页的其他登录方式仍保留在操作区下方；合并重复安全区间距。
- 庭院随屏幕高度铺开；渐变重点衬托标题区。功能小标题由 25rpx 调整为 28rpx，登录卡说明由 24rpx 调整为 26rpx，使用深棕色并明确行高。卡片改为不透底的浅色背景，避免背景影响文字。
- 未增加字体、未修改 Logo 和图标；按钮仍使用品牌金棕色，加深底色并减弱阴影。
- 微信开发者工具：390×844 登录卡片靠近安全区，320×568 登录按钮和协议完整同屏；320×568 补资料状态可滚动到保存按钮。仅用本地组件状态展示，未提交资料或执行账号授权。
- 全量测试 755 项通过，0 失败、0 跳过；TypeScript、Sass 编译和差异格式检查通过；小程序生产依赖审计 0 漏洞。
- 本轮未新加样式断言测试，采用现有行为回归与原生长短屏视觉检查。现有 Sass 导入弃用提示不影响编译。
