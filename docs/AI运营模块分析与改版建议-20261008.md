# AI 运营模块分析与改版建议（2026-10-08）

> 范围：后台「AI 运营」分组（AI 任务中心 /ai-tasks、AI 工具管理 /ai-tools）及关联的「AI 配置」/ai-config（现挂系统设置组）。
> 代码基线：开发版 916（2026-10-08 已部署版）。

---

## 一、现状全景：现在的"AI 运营"是什么

### 1.1 业务逻辑（一条 AI 任务的完整生命周期）

```
用户在小程序发起（20+ 工具、10+ 场景）
  → 后端按 scene 查定价表扣灵石（如 ai_draw_single=N 灵石/张）
  → 写任务表 ai_task（status=pending）+ 灵石明细 + 订单
  → AITaskProcessor 轮询队列 → 取"当前启用"的 API 配置（DB 可配）
  → 失败自动降级：硬编码链 Gemini 3 Pro → Seedream 4.5（ToAPIs 链另有两条）
  → 成功：结果图传 OSS，回写 model/endpoint
  → 失败/部分失败：自动全额或按张退还灵石
  → 运营在「AI 任务中心」检索 → 看失败原因 → 转异常工单 → 标记已排查/已补偿/已回访
```

计费：纯静态定价表（计费配置页），场景 × 灵石数；小程序端实时拉 `/ai/pricing` 展示"本次消耗 X 灵石"。

### 1.2 三个页面各自的角色

| 页面 | 实际角色 | 面向谁 |
|---|---|---|
| AI 任务中心 | 任务检索 + 失败排障 + 转工单 | 客服/开发（事后处理） |
| AI 工具管理 | 工具 CRUD：默认提示词、风格卡片、预览图、上下线 | 运营（配置维护） |
| AI 配置 | 定价表 CRUD + 供应商接入配置（协议/模板/密钥/降级） | 开发（半个程序员才能用） |

小程序侧全景（用户端）：AI 绘画（4 类 20+ 工具）、AI 对话（建房顾问/建规快查）、AI 视频（1-4 分镜）、AI 造价、乡村别墅/建筑翻建/亲子等专题场景；灵石余额制计费，签到/邀请/充值获取。

## 二、核心判断：这不是"AI 运营"，是"AI 运维 + 配置"

**当前模块是全站唯一名字叫"运营"、但没有任何运营能力的分组。** 它回答不了运营最基本的问题：

| 运营要问的问题 | 现状 |
|---|---|
| 哪个工具/场景最受欢迎？趋势如何？ | ❌ 只有 usage_count 计数，无趋势、无漏斗 |
| AI 业务赚钱吗？每个场景毛利多少？ | ❌ 任务表无成本字段，只有灵石收入 |
| 降级链触发多不多？该换供应商吗？ | ❌ 降级硬编码在后端，后台看不到触发频率 |
| 失败率突然升高谁知道？ | ❌ 无告警，靠人刷列表发现 |
| 定价合不合理？要不要调？ | ❌ 无"灵石收入 vs API 成本"对比，定价是拍脑袋 |
| 生成内容合规吗？ | ❌ 后端零审核（仅前端提示词敏感词拦截） |
| 工具改了提示词效果变好还是变差？ | ❌ 无版本、无对比、无 A/B |

对照《后台UX六维度分析报告-20261007》的结论一致：AI 运营组是"全站问题最重的模块"，本质是一个"AI 网关运维工具"。该报告提出的 B3（中文映射 + 测试按钮）中"测试此配置"已上线，但那只解决了"配错会炸"的问题，没解决"运营"本身缺位的问题。

## 三、问题清单（按层次）

### 3.1 业务层缺失（最重）

1. **无成本与毛利视角**：`ai_task` 表只有 `stones_used`（灵石收入），没有每次调用的 API 人民币成本。即梦 15 秒视频成本从 0.6 元涨到 5 元逼出三连涨的教训（2026-04）说明：**积分定价必须锚定真实成本，且成本是波动的**。现在定价调整没有任何数据依据。
2. **无用量分析**：没有按场景/工具/模型的调用量趋势、成功率趋势、用户渗透率。总控台只有"今日任务量 + 成功率"两个数。
3. **无供应商健康度**：降级链（Gemini → Seedream → Flash）硬编码在 `ai_task_processor.go`，后台完全看不到：每家供应商的调用量、失败率、平均耗时、降级触发次数。换供应商、谈判、预算全靠猜。
4. **无告警闭环**：失败率突增、供应商持续超时、任务积压，都靠人肉发现。已有的"超30分钟未完成"标记是好的开始，但只显示在列表里，不推送。
5. **无内容合规审核**：AIGC 新规要求生成内容可追溯、标识；现仅前端 `promptReview` 拦提示词，生成图零审核、零抽检队列。对 B 端合作（加盟商品牌输出）是显性风险。

### 3.2 数据层缺陷

6. `Model` 字段靠"回填历史模型"按钮补——说明早期根本没记录，统计口径先天残缺（`backfillAITaskModels`）。
7. 摘要卡片（任务总数/待处理/处理中/失败）是**当前筛选条件下的计数**，不是全局看板口径，容易被误读。
8. 计费的 `extra_config` 是裸 JSON，改错一个键影响计费上限等行为，且无变更历史。

### 3.3 页面层问题（部分已由 UX 报告覆盖）

9. AI 配置表单仍是开发视角：`provider_code`/`header_bearer`/`prompt_path`/JSONPath 直出（B3 只做了列表映射和测试按钮，表单未改造）。
10. AI 工具管理：表单超长（一个弹窗塞了 8 个区块），无草稿/发布分离——保存即生效，误改提示词直接影响线上。
11. 任务中心状态枚举混用（pending/running/processing/queued/completed 并列出现在筛选里，是两套状态机拼在一起）。
12. 定价调整无生效时间、无历史版本，改错无法回滚。

## 四、对标：同行最优秀的 AI 运营方案长什么样

### 4.1 AI 网关管理台（One-API / New API，国内事实标准）

开源 AI 网关的管理后台是中小团队 AI 运营台的最佳参照，它的核心四件套：

- **渠道管理**：每个供应商一条渠道，权重/负载均衡，一键测试，失败自动禁用+告警；
- **用量看板**：按渠道/模型/用户/时间的调用量与成本报表（数据看板、调用统计、成本分析三张图起步）；
- **计费倍率**：每模型可配"分组倍率"，定价与成本倍率联动，毛利一目了然；
- **运营闭环**：单一后台完成"接入 → 监控 → 调价 → 充值"完整循环。

### 4.2 模型平台控制台（火山方舟 / DashScope / Portkey 等网关实践）

2026 年 LLM 网关的共识做法：**按请求打标签归集成本**（per-request cost attribution，用 metadata 标注用户/功能/场景）、**按渠道的成本与失败率路由**（多供应商 failover + 每路由成本看板）、**实时预算控制**而非事后报表。

### 4.3 积分经济运营（即梦 / 可灵）

- 定价紧跟真实算力成本波动（即梦因成本从 0.6→5 元/条被迫连续调价；可灵以高 ARPU 稳定定价）；
- 后台能实时看到"每次生成的成本 vs 积分售价"毛利，这是调价决策的唯一依据。

### 4.4 家装同行（酷家乐）

面向用户侧：AI 工具按"上传照片→选风格→出图→局部修改"漏斗组织，免费额度 + 会员制。其内部运营台不公开，但其工具矩阵的组织方式（场景化入口 + 效果对比 + 额度）与本平台小程序端已基本对齐——差距不在 C 端，在 B 端看不见数据。

### 4.5 对标结论

把上面抽象成一张"AI 运营台能力矩阵"，星标为我们当前状态：

| 能力 | 同行标准 | 我们现状 |
|---|---|---|
| 用量分析（场景/工具/模型/趋势） | ✅ 标配 | ⭐ 仅计数 |
| 成本与毛利（每次调用成本归集） | ✅ 标配 | ❌ 无成本字段 |
| 供应商管理（健康度/降级可视化/一键切换） | ✅ 标配 | ⭐ 配置可改但降级黑盒 |
| 定价运营（版本/生效时间/毛利联动） | ✅ 标配 | ⭐ 静态表 |
| 告警（失败率/成本/积压） | ✅ 标配 | ❌ 无 |
| 内容审核（抽检/合规标识） | ✅ B 端必需 | ❌ 仅前端拦提示词 |
| 提示词/工具效果迭代（版本/AB） | 🔶 进阶 | ❌ 无 |

## 五、改版建议

### 5.1 新信息架构（把"运维工具"升级为"运营驾驶舱"）

```
AI 运营（分组内 Tab 重组）
├── 运营总览（新增，落地页）     ← 用量看板：调用量趋势、场景分布、成功率、收入灵石 vs API 成本
├── AI 任务中心（现有，收敛）     ← 专注排障：队列 Tab 化（失败/超时/处理中/全部）+ 状态枚举统一
├── AI 工具管理（现有，增强）     ← 加使用数据列（近7日调用/成功率/贡献灵石）、草稿-发布分离
└──（系统设置保留）AI 配置        ← 拆成"定价管理 + 供应商管理"两个页面，均加版本/测试/健康度
```

### 5.2 分阶段落地

**P0 速赢（1~2 周，不动表结构）**
1. 任务中心加"队列 Tab + 角标"（照抄销售线索页标杆模式：失败待处理/超时未完成/处理中/全部）；
2. 统一状态枚举（两套状态机在前端归并为一个映射）；
3. 总览页 v0：用现有 `ai_task` 表聚合出"近 7/30 日：调用量按场景、成功率按模型（用回填后的 model 字段）、失败 Top 原因"——纯查询聚合，不新增写入；
4. AI 配置表单完成 B3 剩余项（枚举中文映射铺满 + 字段灰字说明）。

**P1 数据基建（2~4 周，动表结构，向后兼容）**
5. `ai_task` 增 `api_cost`（分）与 `provider` 字段：processor 已知道用哪家配置，落库即可，历史数据不回填、从上线日起累计；
6. 定价配置加版本表：每次调价留痕（谁改的、旧值新值、生效时间），支持一键回滚；
7. 供应商卡片：每条 API 配置展示近 7 日调用量/失败率/平均耗时/降级触发次数（数据源：任务表按 endpoint 聚合）；
8. 告警 v0：失败率超阈值（如 >10%）或"超30分钟未完成"任务数超阈值时，写入异常工单中心（复用现有工单闭环，不引入新消息渠道）。

**P2 运营进阶（1~2 月，按业务需要）**
9. 毛利看板：按场景算"灵石收入 vs API 成本"，给调价决策提供依据（对标即梦/可灵的定价纪律）；
10. 工具效果迭代：提示词改版留版本，版本间对比成功率/用户重试率；
11. 内容合规：生成图抽检队列（低比例随机抽入审核流，复用灵感素材审核的交互模式）+ 结果图统一加水印/标识（`video_watermark.go` 已有图片水印能力可复用）；
12. 免费额度/促销：新用户 N 次免费生成（获客），替代单纯签到发灵石。

### 5.3 一个需要决策的问题

**AI 配置页要不要保留给非开发人员用？** 建议拆开：定价管理给运营（做成像"会员计划"一样的业务配置页），供应商接入配置只给开发（留在系统设置，表单保持技术形态没问题，但要有"技术人员使用"的说明）。这直接回答了 UX 报告遗留的决策点 3。
