# 部署前事件补偿修复说明

## 修复范围

- `wecom_event_inbox.attempts` 统一定义为“补偿处理轮次”。worker 开始处理一条记录前先持久化加一，避免进程重启后重试计数归零。
- 达到 100 轮时，只将仍为待处理的报告或 CRM 下游标记为失败，已完成或已跳过的下游状态保持不变。
- 保留现有共享退避时间字段，不增加表字段或数据迁移。CRM 暂时失败按当前轮次计算 5–60 分钟退避。
- 14 天清理以 `updated_at` 为准，仅删除报告和 CRM 两侧都已完成或跳过的记录。待处理和永久失败记录保留，便于运维处置。
- 转发 Java `/iycallback/handle` 时恢复企微 XML 包装 `<xml><Encrypt>...</Encrypt></xml>`，请求类型改为 `application/xml`。签名仍使用 `Encrypt` 元素内的原始密文，未修改签名或加解密算法。
- 默认管理员创建成功日志不再输出错误的 `123456` 密码提示，密码认证逻辑未变。

## 验证

在独立 MySQL 8.4 容器中运行事件收件箱集成测试，覆盖：

1. CRM 转发失败后轮次计数持久化且设置退避时间。
2. 报告已成功、CRM 失败的记录达到上限时，报告成功状态不被覆盖。
3. CRM 已成功、报告待处理的记录达到上限时，CRM 成功状态不被覆盖。
4. 只清理已沉淀 14 天的双侧完成/跳过记录，保留 pending 和 failed 记录。
5. Java 端可从转发请求中解析 `Encrypt` XML 元素，并用其内密文验证重签名。
