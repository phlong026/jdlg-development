# Go 发布安全验证

## 结论

Go 服务发布包已改用 Go 1.26.8 构建，并将首次 `govulncheck` 报告的可达依赖漏洞升级到修复版本。最终扫描结果为可达漏洞 0 项。

官方 Go 下载页显示 1.26 系列当前补丁版为 [Go 1.26.8](https://go.dev/dl/)；本次通过 Go 自带的 toolchain 下载和校验机制获取，并把缓存放在交付工作目录，未覆盖系统 Go 安装。

## 修复版本

| 组件 | 修复前 | 修复后 | 说明 |
| --- | --- | --- | --- |
| Go 工具链/标准库 | 1.26.2 | 1.26.8 | 覆盖扫描要求的最低修复版 1.26.6 |
| `golang.org/x/image` | 0.35.0 | 0.45.0 | 修复 VP8L/WEBP/SFNT 解码的内存、panic 和 DoS 问题，参见 [GO-2026-6222](https://pkg.go.dev/vuln/GO-2026-6222) |
| `golang.org/x/net` | 0.48.0 | 0.57.0 | 0.55.0 是扫描给出的漏洞修复下限；`x/image` 0.45.0 要求至少 0.57.0 |
| `github.com/xuri/excelize/v2` | 2.10.0 | 2.11.0 | 修复恶意工作表行索引导致的内存耗尽，参见 [GO-2026-5960](https://pkg.go.dev/vuln/GO-2026-5960) |
| `github.com/quic-go/quic-go` | 0.54.0 | 0.59.1 | 修复 HTTP/3 QPACK 扩展导致的内存耗尽，参见 [GO-2026-5676](https://pkg.go.dev/vuln/GO-2026-5676) |

上述版本要求将 `go` 指令从 1.24.1 提升到 1.25.0。`go mod tidy` 把原已存在的 `miniredis` 和 `x/crypto` 正确重分类为直接依赖；本次未引入新模块或更换主版本。

## 修复前的实际利用前提

| 范围 | 实际调用面 | 需要同时满足的条件 |
| --- | --- | --- |
| 图片解码 | 用户上传图片、远程 AI 生成图、水印和报告素材会调用 `image.Decode`/`DecodeConfig` | 攻击者能提交或让受信任的远程服务返回恶意图片。报告素材路径只允许 PNG/JPEG 且限制 12MiB/6000px，会降低 WEBP 专属问题的暴露，但其他远程图片路径仍可触发解码 |
| Excelize 解析 | 当前成本文档代码仅使用 `NewFile` 创建新工作簿，未调用 `OpenFile`/`OpenReader` | 必须新增并调用“解析攻击者提供的 XLSX”路径才能利用；当前 `govulncheck` 的符号可达报告属于保守结果 |
| QUIC/HTTP/3 | 业务代码没有直接导入 `quic-go`/`http3`，Gin 通过 `Engine.Run` 启动普通 HTTP 服务 | 必须实际启用 HTTP/3，并接收恶意 QPACK 头或 trailer。当前部署路径没有这个入口 |
| 出站 URL/TLS/HTTP2 | AI 供应商请求、COS、微信、Redis/MySQL TLS 等会进入 `net/url`/`net/http`/`crypto/tls` | 需要攻击者控制可配置的远程端点，或控制拥有有效证书的对端，才能提供恶意 URL、TLS 握手或 HTTP/2 SETTINGS |
| 入站 HTTP | Go 进程用 `Engine.Run` 直接监听 HTTP | HTTP/2 明文探测问题需要攻击者能直连 Go 端口并慢速发送 h2c 头。前置 Nginx 且不暴露内部端口时可降低风险，但不替代工具链升级 |
| XML/ASN.1 | 企微回调 XML、COS 响应以及微信支付本地证书会进入标准库解析 | 企微事件需先通过签名和密文验证，ASN.1 路径读取本地证书；攻击者需控制对端或本地配置文件 |
| Windows `net` NUL 字节 | 扫描包含 Windows 专属路径 | 正式产物为 Linux amd64，该项在本产物上不可利用 |
