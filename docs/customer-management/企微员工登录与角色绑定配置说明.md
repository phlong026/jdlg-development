# 企微员工登录与现有后台角色绑定

适用范围：同一企业的老板、主管和员工共用当前管理后台。此功能新增登录身份绑定，复用 Go 后台账号、会话、平台访问权限和 Java 客户角色。不会根据企微姓名、职务或是否是企微管理员自动提权，也不会自动注册账号。真实企微联调和生产部署尚未执行。

## 1. 身份及权限规则

企业 CorpID + 员工 UserID → 唯一后台 user_id → 当前后台访问范围 → 当前客户管理角色及业务负责人。

| 配置 | 决定什么 | 配置人 |
| --- | --- | --- |
| 企微登录身份 | 该成员登录哪个后台账号；不改变客户归属 | 平台管理员 |
| 后台访问范围 platform_admin / crm_only | 能否进入原有订单、内容、系统管理等模块 | 平台管理员 |
| 客户角色 admin / staff | 客户主管管理范围或员工业务范围 | 平台管理员，沿用现有授权 |
| 客户业务员工 employeeId | 企微同步客户的员工归属；staff 开通企微绑定时必须匹配 | 平台管理员 |

老板可以设置为 crm_only + 客户主管，查看企业客户，而不取得原后台系统管理权限；负责维护系统的人才需要 platform_admin。普通员工沿用自己的客户及现有公海权限，企微登录不会扩大范围。手动报备客户仍使用现有后台账号归属，绑定不会迁移历史客户、报备、跟进或订单。

老板的登录 UserID 必填，但不要求其成为客户业务负责人。停用绑定仍保留该成员的唯一占用，不能将同一身份同时开给两个账号。改绑需要核对成员和原账号，旧账号成功改绑到另一真实成员后才会释放旧身份；没有提供随意删除绑定的入口。误绑时先停用，核对角色与业务数据后修正。

## 2. 上线顺序（宝塔）

本说明是《客户管理系统首次上线操作手册-宝塔版》的增量步骤。已有数据库、Go、Java、反向代理及桥接密钥配置继续使用。

1. 备份 Go 业务数据库并保留当前前端、Go 程序和 Java JAR。先保持 WECOM_LOGIN_ENABLED=false。
2. 确认已完成 service/sql/customer_management_bridge_up.sql。然后在宝塔数据库工具中，对 **Go 业务数据库** 执行 service/sql/management_wecom_identity_up.sql，一次即可。新增 management_wecom_identity、management_wecom_oauth_state 两张表；不向 Java 客户数据库导入此 SQL。
3. 发布更新后的 Java 客户服务（customer-management/phase1）：新增供 Go 签名调用的 /internal/management/v1/provision/identity。保持 CRM_DEMO=false，Java 的 WECOM_CORP_ID 必须与 Go 登录企业一致。运行项目原有数据库迁移，不手动重建客户表。
4. 发布更新后的 Go 服务。将 deployment/crm-wecom-login.env.example 中的变量合并到宝塔 Go 项目环境变量，不能覆盖原有数据库、会话密钥、报告服务或 CRM 桥接配置。普通 .env 文件不会被任意启动命令自动读取，需由实际启动方式加载。
5. 在 background 执行 npm run build，按原站点方式发布 dist。前端仍使用现有后台样式。前端 API 应走后台域名的同源代理。
6. 完成下述企微应用和 HTTPS 代理设置，设置 WECOM_LOGIN_ENABLED=true 并重启 Go。用原有平台管理员账号密码进入后台开通绑定。
7. 按第 5 节验收后，通知员工使用新的企微登录入口。

SQL 新表没有自动回填身份；不能用姓名相同、后台用户名相同来推断 UserID。回滚优先关闭 WECOM_LOGIN_ENABLED，企微会话在下一请求失效，再恢复应用版本；保留绑定及审计表便于复核，不删除生产数据。保留一个可用的平台管理员密码登录账号用于维护。

## 3. 企微应用和服务器设置

在本企业创建或选用自建应用，记录企业 CorpID、应用 AgentID、自建应用 Secret。应用可见范围应包含实际使用系统的老板和员工，并具备读取这些成员信息的权限。需要按企微应用后台实际要求完成网页授权可信域名、企业微信授权登录域名、域名校验及可信 IP 配置。

Go 使用自建应用 Secret 做成员登录核验；Java 的客户联系 Secret 继续用于客户同步。两种 Secret 用途不同，均仅放在服务器环境变量中，不写到 React 源码、浏览器或公开文档。

| Go 环境变量 | 示例与要求 |
| --- | --- |
| WECOM_LOGIN_ENABLED | true 才启用；默认关闭 |
| WECOM_LOGIN_CORP_ID | 本企业实际 CorpID，与 Java WECOM_CORP_ID 相同 |
| WECOM_LOGIN_AGENT_ID | 自建应用的正整数 AgentID |
| WECOM_LOGIN_SECRET | 自建应用实际 Secret |
| WECOM_LOGIN_CALLBACK_URL | https://后台域名/api/v1/management/wecom/callback |
| WECOM_LOGIN_FRONTEND_ORIGIN | https://后台域名，不带路径及末尾斜线 |

前端源地址和登录回调必须同一 HTTPS 主机及端口。固定回调地址不能携带查询参数。登录入口为 https://后台域名/api/v1/management/wecom/start；可以作为企业微信工作台应用主页。也可从后台登录页点击“企业微信登录”。

电脑浏览器入口跳转到企微扫码页；企微手机内置浏览器入口走成员网页授权。手机普通浏览器目前仍按扫码入口处理，不承诺一键唤起手机企微；移动使用应从企微工作台进入。界面继续使用现有响应式网页，不安装新的原生 App。

新增回调是“员工登录回调”，与 Java 客户事件回调 /iycallback/handle、原 Go 报告通知回调分别配置。**不要用它替换现有客户变更或报告事件回调。**

在既有后台 HTTPS server 中新增精确匹配规则，端口替换为原 Go 服务实际端口，执行 nginx -t 后再重载。不要暴露 Java 内部接口。

```nginx
location = /api/v1/management/wecom/callback {
    access_log off;
    proxy_pass http://127.0.0.1:REPLACE_GO_PORT;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Go 已跳过登录回调的访问日志，代理、网关、CDN 也不要记录该回调查询参数中的 code/state。原有 /api/ 代理继续处理 start、config、身份绑定及其他接口。

## 4. 后台操作

1. 平台管理员进入“客户管理 → 账号权限”，选择已有后台账号。
2. 先保存后台访问范围、启用状态及客户角色。员工如负责企微客户，选择本人业务员工。等待授权完成；授权同步失败或进行中会阻止启用绑定。
3. 在该账号下方“企微登录身份”填写企微通讯录中的准确 UserID，点击“核验并保存绑定”。姓名展示来自企微服务端，不接受浏览器传入姓名作为核验结果。
4. 系统核验成员已激活、可读取，并核对 Java 客户库企业及 staff 的业务员工。成功后显示成员姓名、UserID 和已启用状态。角色不会因保存绑定改变。
5. 员工通过企微登录后直接进入客户管理；未绑定、已停用、外部联系人或不符合企业应用范围的身份无法登录。

改绑或再次保存会增加绑定版本，已签发的企微会话下次请求失效。多位管理员同时编辑时旧版本会被拒绝，刷新后核对再操作。

“停用企微登录”只撤销企微入口及企微会话，不禁用密码登录。离职或需要撤销全部后台访问时，应同时停用该后台账号，并按现有客户交接流程处理客户归属。修改绑定本身不会转移客户。

## 5. 验收清单

- 老板以本人企微登录，进入已配置的客户主管账号；可见范围与该账号密码登录一致。
- 员工甲、乙分别登录，只能操作各自范围内客户；公海继续按现有规则开放。员工访问其他人的专属详情、附件、导出或原后台订单接口应被拒绝。
- 同一企微成员绑定第二个账号被拒绝；给员工甲账号填写员工乙的业务身份被拒绝。
- 未绑定成员、外部微信身份、已停用后台账号不能登录；角色不会自动升级。
- 停用绑定、改绑后，旧企微会话再请求被拒绝；密码登录是否可用以后台账号启用状态为准。
- 电脑扫码、企微手机内置浏览器各完成一次真实登录；登录跳转后前端无需刷新或补写 localStorage。
- 临时关闭 Java 服务时原后台可正常进入，客户模块提示故障；平台管理员仍可停用已有企微绑定。
- 原客户事件同步、报告回调、原后台密码登录、公海认领和手动报备继续正常。

本地已验证 Go 单元及隔离 MySQL 集成测试：唯一约束、并发抢绑、绑定版本、审计写入、角色变更冲突、浏览器绑定 state、回调一次性、过期与重放、会话撤销、员工平台权限隔离，以及失效 access_token 一次刷新。Java 内部身份元数据端点测试核对仅平台签名可读且不输出密码摘要。企微 HTTP 接口使用测试替身，不能代替真实企业应用验收。

## 6. 安全边界与排障

登录 state 只存哈希，绑定当前浏览器，5 分钟有效且仅用一次。登录完成复用 Go 的 Secure、HttpOnly、SameSite=Lax 会话 Cookie，企微会话最长 8 小时；每次受保护请求重新核对本地绑定状态、版本和后台授权。

企微成员是否激活在绑定和每次重新登录时查询。**仅在企微通讯录中停用成员，不会实时推送到本地登录会话**；本期未接入通讯录离职事件驱动的即时会话撤销。处理离职应立即停用本后台账号/企微绑定，不能只等 8 小时过期。已经发出的请求不会被追溯取消。

| 现象 | 检查顺序 |
| --- | --- |
| 看不到企微登录按钮 | Go 是否已更新、enabled 是否 true、6 项变量是否有效；config 接口是否正常 |
| 提示数据库升级 | 是否在 Go 业务库执行身份迁移，而非 Java 客户库 |
| 成员核验失败 | 自建应用 Secret、可见范围、成员激活状态、通讯录读取权限及可信 IP |
| 客户库企业不一致 | Java CRM_DEMO=false；Java WECOM_CORP_ID 与 Go WECOM_LOGIN_CORP_ID 一致 |
| 角色授权进行中 | 完成或重试原账号授权同步，再重新保存身份绑定 |
| 扫码成功却显示过期 | 从原浏览器重新发起；核对同源 HTTPS、Cookie、服务器时钟及域名配置 |
| 登录成功但不能管理客户 | 核对原账号的客户权限及 Java 服务，登录不会自动授权 |

源码入口：service/route/wecom_identity.go、service/sql/management_wecom_identity_up.sql、background/src/component/WecomIdentityBinding.tsx，以及 Java ManagementProvisionController 的身份元数据端点。身份变更审计复用 management_access_audit，action=wecom_identity。
