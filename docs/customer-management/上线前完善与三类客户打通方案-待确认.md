# 上线前完善与三类客户打通方案（已确认开发）

日期：2026-09-15。用户已确认继续开发；唯一明确调整为保留“记住密码”，不改成“记住账号”。完成情况以《需求验收与代码评审-20260915.md》为准，生产发布另按环境验收结果安排。

## 1. 本轮目标

1. 重排手机和电脑登录页面，增加密码显示/隐藏。
2. 按用户要求保留记住密码，完成本轮权限、业务和部署验证。
3. 打通手动报备、企业微信、小程序咨询三类来源，使用统一客户档案、归属、跟进和统计。
4. 将 90 天保护、公海、成交、交接和争议规则补齐，保持员工操作简单。

## 2. 登录页面

- 暖米白背景、暖棕主按钮，保留现有品牌标识，移除占空间的电脑/人物插画。
- 手机采用单列布局：品牌 → 登录标题 → 账号 → 密码 → 记住密码 → 登录按钮。短屏可自然滚动，键盘弹起时能滚动到操作区。
- 电脑使用居中窄卡片，表单最大宽度约 420px，与手机保持同一结构。
- 输入框和登录按钮高度约 48–52px，正文输入字号不小于 16px，左右留白约 20–24px，处理安全区及横屏。
- 密码框右侧内嵌眼睛按钮，点击切换显示/隐藏；默认隐藏，不清空内容、不移动表单、不触发提交。支持键盘操作及“显示密码/隐藏密码”辅助标签。
- 按最新明确要求保留“记住密码”的原读取、回填、保存及取消逻辑。浏览器自动填充保持兼容。
- 登录失败显示明确提示，重复点击受到控制，加载时说明正在登录；按账号权限进入平台主页或客户管理。
- 验证 320、375、390、430、768px 及常见桌面宽度；覆盖短屏、横屏、键盘、自动填充、密码切换和错误反馈。实际手机及企微浏览器另做真机验收。

## 3. 三类来源统一

### 3.1 一份客户主档，保留多条来源

现有 React + Go + Java 架构继续使用，以 Java 客户服务作为客户主档的统一写入入口。保留原小程序线索和企微关系作为来源记录，通过关联表连接到主档，不删除原始资料，不改写既有手动报备编号。

- 每位已确认客户一个客户编号、一名当前负责人、一套保护状态和一条综合时间线。
- 来源表保留首次来源、后续来源、原始记录标识、渠道、提交人及时间；渠道信息不能由浏览器任意指定来抢归属。
- 小程序留资继续调用原入口，服务端可靠记录同步任务；失败重试、重复投递不重复创建，管理端能发现未同步记录。
- 企微按已关联的外部联系人身份更新主档。好友关系变化不覆盖人工资料、负责人或保护期。
- 原小程序线索页保留来源查询能力；已关联客户的状态、负责人和跟进统一由主档管理，避免两套页面各自修改。
- 统计分别显示去重客户数和来源线索数，不直接相加。统一不意味着给顾问开放小程序账号、会员、订单等无关数据。

### 3.2 初始接待人和有效报备

| 来源 | 接入方式与归属建议 |
| --- | --- |
| 手动报备 | 填齐现有 5 项资料后，查重成功即绑定报备账号并开始保护 |
| 企微新增 | 自动保存，添加员工为初始接待人；匹配已有主档时不覆盖其受保护归属 |
| 小程序咨询 | 自动保存；可信渠道绑定可确定初始接待人，否则进入主管待分配列表 |

自动接入缺少面积、地址、时间等资料时，进入“待完善”状态，保留线索但不视为完成有效报备。补齐 5 项并通过查重后，锁定有效报备账号并开始 90 天保护。“接待人”与“已锁定归属”在界面上明确区分。

### 3.3 查重和关联

- 同一来源的稳定标识已绑定客户时，自动更新同一主档。
- 同手机号、微信或相似资料跨来源出现时，生成疑似重复提示；不只凭姓名、手机号或昵称直接合并。
- 手动报备命中保护中的同电话档案时拦截重复占用，并允许提交给主管核实共用电话/不同客户的例外；默认不向其他顾问展示受保护客户详情。
- 主管确认同一客户后，选择保留主档及冲突字段，归并来源、跟进和附件；保留原编号映射、来源记录和操作日志。
- 已有有效保护归属优先；存在两份有效报备时，按可核实的有效报备时间及证据由主管裁定，不能凭更早的原始线索时间抢占。
- 误关联可由主管解除来源绑定；已经归并的历史内容通过可追溯纠错处理，不删除原始记录。

## 4. 统一保护规则（建议默认值）

| 情况 | 建议规则 |
| --- | --- |
| 有效报备 | 5 项完成、电话校验及查重通过，系统绑定账号，开始 90 天保护 |
| 普通有效跟进/沟通 | 选择实际联系结果、填写具体结论；继续联系时安排下次时间，从有效记录时间重新计算 90 天 |
| 出图/报价续期 | 关联图纸、方案或报价附件并说明结果；上传附件后保存有效活动才续期 |
| 未接通、未回复、内部备注 | 可以保留记录，但不续期 |
| 资料编辑、重复添加企微、重复提交留资 | 不改变受保护归属，不续期 |
| 到期无有效活动 | 自动进入公海，原负责人不能补填记录恢复归属；已授权渠道账号可重新认领 |
| 公海重新认领 | 保留编号和历史，开启新的 90 天；多人同时认领仅一人成功；原负责人也可按相同规则重新认领 |
| 暂缓 | 继续计算 90 天，不无限期占有；预计很久以后建房不自动延长保护 |
| 已成交 | 增加简易“成交确认”：主管核实成交凭证后成为正式成交客户，退出公海回收规则；不把此确认当作财务已收款 |
| 成交待确认 | 员工可提交凭证申请，但未确认前原保护期继续计算，不能仅改状态取得永久保护 |
| 无效/明确拒绝联系 | 由主管确认归档，避免再次公开认领和反复联系；恢复时保留理由和历史 |
| 员工离职/停用 | 即时停用账号；客户进入主管交接列表，由主管转交或释放公海。停用本身不静默延长保护 |
| 主管转交 | 填写原因，保留剩余保护时间；真实有效跟进后才重新计 90 天；原负责人立即失去权限 |
| 归属争议 | 员工提交说明及证据，主管裁定并留痕；不让员工自行修改归属，不因申诉自动延长保护 |
| 无效跟进审核 | 主管可将活动标记为不计续期，保留原文、理由和审核记录，按最近有效活动重新计算到期日 |

“有效”通过结构化结果、附件和主管复核约束，本轮不声称系统能自动核实所有真实沟通，也不接入完整聊天存档。

## 5. 历史数据过渡

1. 先备份，生成三类来源数量、归属缺失、疑似重复和保护情况的预览清单。
2. 已有手动报备客户保留原编号及原保护到期时间，不因迁移续期。
3. 既有企微/小程序客户由主管核实归属、分类、成交情况及必要资料。
4. 对核实后纳入统一保护的历史活跃客户，建议从切换日起给予首个 90 天保护；这项过渡只执行一次。待完善、未分配、成交及无效记录分别处理，不能全部设成受保护。
5. 对疑似重复不强制自动合并；保留待核实队列，完成核实后计入确认去重统计。
6. 核对关联前后来源记录数、主档数、跟进数及附件；旧入口切到主档，防止旧接口继续绕过归属规则。

## 6. 本轮附带的上线必需能力

- 最小渠道身份：员工与渠道账号统一有稳定业务身份，企微员工绑定作为关联；经授权的渠道人员可在没有企微员工身份时手动报备。主管仍负责授权，不能自行注册获取客户权限。
- 最小附件能力：现场照片、图纸、报价文件、成交凭证，按客户权限访问，记录上传者及时间；文件数量/体积/类型限制，不使用永久公开链接。
- 消息提醒：先提供站内今日待办、逾期、保护到期前 7/3/1 天提醒、认领及交接结果；企微推送复用同一通知任务，配置接通后验收启用，避免重复发送。
- 登录安全、角色和接口越权、停用后的访问、重复提交、并发报备/认领、附件权限、审计记录及敏感信息日志检查。
- 正式 HTTPS、服务间认证、数据库迁移、备份恢复、发布回退和服务异常监测。
- 真实企微回调与历史同步、手机真机及企微内置浏览器验收；生产密钥仅在部署环境配置。

## 7. 页面保持简洁

员工侧保留：客户驾驶舱、客户档案、我的待办、客户公海。报备仍是 5 项，其他信息在详情补充。

主管增加待处理入口：待完善/待分配、重复核实、待交接、成交确认、归属争议。将原分散来源放在筛选和详情来源记录中，不再要求员工在三套列表间重复跟进。

## 8. 开发与验收顺序

1. 登录布局、眼睛按钮和记住密码兼容检查，先提供手机与桌面预览。
2. 统一身份/主档/来源关系，完成旧数据迁移预演和可靠同步。
3. 统一保护和权限，完成附件、成交确认、交接及主管纠错入口。
4. 接入提醒、补齐待办和统计，完成全链路回归。
5. 真实企微和真机验收、正式环境部署演练，提交验收结果后安排发布。

必须验收：同一客户三渠道进入可正确关联且不抢归属；重复通知不重复建档；无效活动不续期；有效活动续期；成交确认后不入海；离职交接后权限正确；旧接口不绕过新规则；迁移不丢历史；并发认领只有一个成功；手机键盘不挡住登录操作；密码显隐不影响输入且保持原记住密码行为。

## 9. 本轮边界及已确认默认值

本轮不建设完整合同回款/财务系统、完整报价计算器、渠道佣金、群发营销、AI聊天分析或完整聊天存档。附件和成交确认只满足保护规则及基本业务追溯。

用户已确认按以下默认值开发：

1. 三类来源统一，信息不全先待完善，完成有效报备才开始 90 天保护。
2. 普通沟通需真实联系结果；出图/报价续期需附件；未接通不续期。
3. 成交经主管确认后不再掉公海；无效客户由主管归档。
4. 交接不自动续期，归属争议由主管裁定。
5. 原手动报备期限保留，首次纳管的核实历史活跃客户从切换日起保护 90 天。

方案确认表示同意上述开发与本地验证范围；尚未提供或尚未验收的真实企业配置与生产发布不视为已经完成。
