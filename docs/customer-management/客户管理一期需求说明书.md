# 客户管理一期需求说明书

版本 V1.0　日期 2026年9月10日

适用范围：小程序管理后台中的客户管理模块。阅读对象：业务负责人、客户主管、顾问、产品、开发和测试人员。

本期将企业微信客户管理接入现有管理后台，让员工从一个入口完成客户查看、分配、分类、跟进和待办处理。企微客户无需先注册小程序；小程序咨询线索与企微客户分别保留，暂不进行身份合并、订单关联或收入核验。

本说明书保留V1.0业务基线。2026-09-12已按用户批准的任务清单实现现有后台整合及统一登录，并完成本地隔离联调；真实企微接入与正式部署仍待验收。实际字段、时间口径及已批准差异见[实施记录](实施记录.md)，交付验证见[整合验证记录](整合验证记录.md)。原DOCX/PDF为V1.0归档，未重新导出。

## 1 目标和成功标准

### 1.1 业务问题

客户添加企业微信后，接待员工需要知道哪些客户尚未联系、上次沟通了什么、何时应再次联系。主管需要看到客户归属、跟进进展和遗漏事项。现有后台已有小程序客服线索功能，应继续使用；新增的企微客户能力通过同一后台提供，避免员工反复切换入口。

### 1.2 一期目标

- 客户正式添加员工后进入管理名单，无手机号、无小程序账号、无渠道标识也能建档。
- 每位企微客户只有一份业务档案，并保留其与不同员工的企微好友关系。
- 客户有明确负责人，或明确显示为未分配；每次跟进有记录，继续联系有下一次时间。
- 员工能找到今日与逾期待办；主管能分配客户并处理同步异常。
- 使用现有后台登录，按员工职责授权；普通顾问不能因此访问订单、财务或其他后台模块。

### 1.3 完成定义

一期完成须同时满足：现有后台可用、统一登录和服务端权限通过、真实企微事件及初始化同步通过、电脑和手机主要操作通过、历史数据不受损、备份恢复可执行。独立演示可运行和模拟接口测试通过，仅代表已具备基础，不能代替上线验收。

## 2 范围和交付形态

### 2.1 使用形态

电脑浏览器是管理入口；手机浏览器提供客户查询、跟进填写和待办处理。部署后可把同一网址配置到企业微信工作台。系统是网页应用，不需要安装桌面客户端；一期不实现企微免登录，员工首次进入使用管理后台账号。

### 2.2 功能范围

| 编号 | 一期必交功能 | 范围 |
| --- | --- | --- |
| R01 | 统一后台入口 | 客户管理中提供小程序咨询线索、企微客户、企微待办入口 |
| R02 | 统一登录与权限 | 后台账号与客户管理账号、企微员工建立明确对应 |
| R03 | 企微客户入库 | 新增回调、初始化同步、定期补同步、失败可发现 |
| R04 | 客户去重与关系 | 单客户多员工关系，删除、重新添加不丢档案 |
| R05 | 客户归属 | 默认负责人、主管分配、未分配及不可接待员工处理 |
| R06 | 资料与分类 | 咨询类型、意向、联系方式、需求摘要 |
| R07 | 跟进记录 | 沟通结果、状态、下次跟进、历史查看、并发冲突提示 |
| R08 | 待办与统计 | 新客户、今日、逾期、未安排、未分配、人工成交数 |
| R09 | 导出与追溯 | 按当前筛选和权限导出客户与跟进，记录关键管理操作 |
| R10 | 同步管理 | 配置状态、任务进度、错误和重试 |
| R11 | 手机使用 | 适配窄屏的列表、详情、跟进和待办 |
| R12 | 部署与运维 | 环境隔离、备份恢复、试用验收、回退说明 |

### 2.3 一期不纳入的功能

不做小程序用户与企微客户自动身份匹配，不关联会员、订单、支付和方案报告，不合并两侧历史客户，不做跨企业管理、跨部门共享池、销售预测、自由标签体系、批量营销、聊天存档、AI 聊天分析、自动回复、企微免登和原生手机应用。

提醒采用系统内的到期待办列表，页面打开时刷新；不包含企微消息推送或手机系统通知。欢迎语可由企业微信现有配置承担。实际聊天继续在企微进行，员工手工填写沟通结论。

| 顾问数据范围 | 独立服务已有 | 统一登录后继续执行同一范围 |
| 原后台统一登录与账号对应 | 尚未实现 | 新增账号关联、服务间身份传递和授权 |

## 4 用户角色和权限

### 4.1 角色定义

系统管理员负责平台账号、客户模块授权和配置，可以拥有原后台权限，但不会仅因能登录后台就自动获得企微客户权限。客户主管在获授权的客户模块中管理全部企微客户、分配归属、查看同步。顾问只处理业务负责人为自己的企微客户。

平台访问范围和客户数据角色分别授权。客户主管、顾问可使用同一后台登录页，但默认只进入客户模块。系统管理员需要客户数据访问时，也必须关联对应的客户管理账号。

### 4.2 权限矩阵

| 操作 | 系统管理员 | 客户主管 | 顾问 |
| --- | --- | --- | --- |
| 平台账号和客户模块授权 | 可以 | 不可以 | 不可以 |
| 原订单等后台模块 | 按原平台授权 | 默认不可 | 默认不可 |
| 原小程序咨询线索 | 按原平台授权 | 默认不可 | 默认不可 |
| 全部企微客户 | 另有客户主管授权时 | 可以 | 不可以 |
| 自己负责的企微客户 | 按客户角色 | 可以 | 可以 |
| 调整业务负责人 | 按客户角色 | 可以 | 不可以 |
| 修改资料与记录跟进 | 按客户范围 | 全部 | 仅自己负责 |
| 客户与跟进导出 | 按客户范围 | 全部 | 仅自己负责 |
| 查看和重试同步 | 按客户角色 | 可以 | 不可以 |
| 查看未分配客户 | 按客户角色 | 可以 | 不可以 |

一期不扩展原小程序线索的普通顾问授权。未授权的人看不到对应页签，直接访问接口也必须被拒绝。账号关联或客户账号停用后，后续请求失效；顾问所绑定的员工不再可接待时，同样停止其客户访问。主管不要求绑定接待员工。改负责人后，旧顾问下一次访问即失去该客户权限。

## 5 页面和导航要求

### 5.1 客户管理入口

原后台增加统一客户管理入口，含“小程序咨询线索”“企微客户”“企微待办”。主管可进入“企微同步”；系统管理员可进入“客户模块授权”。按权限展示可用入口，默认进入本人能使用的第一个页面。

小程序咨询线索沿用原数据及操作；企微客户使用企微档案。两个来源的数量分别统计，不能相加后称为去重客户总数。未实现身份核实前，不提供自动合并或暗示已经关联的展示。

### 5.2 企微客户列表

展示客户名称、状态、咨询类型、意向、负责人、下次跟进、需求摘要。支持按名称、联系方式或需求搜索，按状态、咨询类型、意向筛选；主管增加负责人筛选。默认按资料更新时间倒序排列，分页展示，每页默认 20 条。

区分加载中、暂无客户、筛选无结果、服务不可用和无权限。加载失败时保留错误提示与重试入口，不能把失败展示成客户数量为零。切换账号后清空上一账号的客户、筛选、详情和统计。

### 5.3 客户详情

详情包含客户资料、跟进时间线、下次联系和企微关系。提供记录跟进、编辑资料、刷新操作。资料缺失显示待补充；同步未补齐昵称时显示待同步客户，不阻止后续补资料。

业务状态和好友关系状态分别展示。变更负责人时明确说明只调整系统中的业务归属，不转移企微好友关系。

### 5.4 手机端

窄屏采用客户卡片；搜索保留在首层，更多筛选可展开。主要按钮在屏幕内可操作，长需求与记录自动换行。弹窗不能横向溢出，保存时禁止重复提交，并显示成功或失败。

手机与电脑使用相同客户、记录、权限和统计口径。手机端验收以客户查询、详情、跟进、待办为主；批量管理和大型导出以电脑端为主。

## 6 完整业务流程

### 6.1 正式添加客户

客户添加企微员工后，系统校验企微事件并保存客户及关系。第一次出现的客户默认分配给添加他的员工，状态为新客户、分类为待确认、意向为中。随后补齐企微资料，在顾问列表和主管视图中可见。自动建档不要求手机号、小程序账号或渠道标识。

仅有点击客服入口、长按二维码、咨询留资、半添加事件，均不能直接判定为已成为企微好友。企业微信实际可读取的客户范围由企业授权决定。

### 6.2 初始化已有客户

主管发起全量同步，系统读取可接待员工及可访问客户。已存在的客户更新企微资料，不重复创建档案，不覆盖人工跟进。历史客户有多名添加员工时，以最早添加关系确定初始负责人；已人工指定的负责人保持不变。

### 6.3 首次及后续跟进

顾问查看需求并联系客户，填写沟通结果，确认状态。继续跟进时必须选择未来联系时间；保存后同时更新客户状态、最近跟进时间、待办和时间线。业务资料修改可以不安排时间，此时仍为活跃状态的客户进入未安排跟进列表。

资料调整和实际联系是两类记录。仅改联系方式或负责人不能刷新最近实际跟进时间。提交失败时保留员工输入；发生资料版本冲突，提示刷新核对后重新提交，不静默覆盖他人修改。

### 6.4 到期处理

顾问通过今日待办、逾期待办或未安排跟进列表找到客户，联系后再次记录。页面不会自动关闭未处理的待办。成交、暂缓、无效时结束当前待办；如果需要以后提醒，应保持跟进中并安排日期，暂缓状态本身不保留提醒。

### 6.5 删除和重新添加

客户删除员工或员工删除客户后，更新对应好友关系，保留客户档案及跟进记录，不自动判为无效、不自动换负责人。重新添加时恢复该关系，继续沿用原档案。一个客户添加第二名员工时，增加关系，不增加业务客户总数。

如果全量名单中缺少某关系，但没有明确删除事件，只显示关系待核实。员工离开接待范围后，主管仍能查看并重新分配客户，系统不自动删除或隐式转移客户。

### 6.6 异常补偿

客户资料读取失败时，已收到的事件和已建档客户保留，并自动重试。主管可查看失败原因、任务进度和重试入口。收到重复事件不重复建档；较旧的事件不能明显覆盖新的关系状态。全量任务部分失败要显示失败及已处理数量，不能把未读取完的名单当作客户全部删除。

## 7 数据和状态口径

### 7.1 核心资料

| 字段 | 来源及规则 | 必填要求 |
| --- | --- | --- |
| 企微客户标识 | 企业内稳定的外部联系人 ID，系统生成关联 | 自动取得 |
| 客户名称及头像 | 从企微补同步，允许暂缺 | 不阻止入库 |
| 业务负责人 | 有效企微员工，主管可调整 | 缺失须明确待分配 |
| 咨询类型 | 待确认、建房、设计、造价、合作咨询 | 有默认值 |
| 意向 | 高、中、低；默认中 | 有默认值 |
| 联系方式 | 员工补录，最多 80 字符 | 选填 |
| 需求摘要 | 员工补录，最多 2000 字符 | 选填 |
| 沟通结果 | 跟进时录入，最多 2000 字符 | 跟进必填 |
| 下次联系 | 指定日期与时间 | 活跃状态的跟进提交必填 |
| 操作记录 | 操作者、时间、客户、操作类型 | 系统自动记录 |

分类使用固定选项，不要求建设可自定义标签后台。电话和备注仅为业务资料，不自动作为跨系统合并依据。

### 7.2 业务状态

| 状态 | 含义 | 对待办的影响 |
| --- | --- | --- |
| 新客户 | 新进入或待进一步确认的客户 | 活跃状态，可进入今日、逾期、未安排 |
| 跟进中 | 正在持续沟通 | 活跃状态，可进入今日、逾期、未安排 |
| 已成交 | 员工人工确认已达成业务 | 清空当前下次联系时间 |
| 暂缓 | 当前暂停跟进 | 清空当前下次联系时间 |
| 无效 | 暂无有效跟进需求 | 清空当前下次联系时间 |

已成交不代表已收款。已成交、暂缓和无效可以重新转回跟进中，并重新安排联系。新客户状态不严格等于从未联系；如统计新客户，页面应命名为新客户，避免将状态数量误标为首次联系人数。

### 7.3 待办和统计

所有统计先应用当前账号的数据权限。企微与小程序来源分别统计。

| 名称 | 统计规则 |
| --- | --- |
| 客户总数 | 当前可见的企微业务档案数量，多员工关系只计一位 |
| 新客户 | 当前业务状态为新客户 |
| 今日待办 | 活跃状态，联系时间位于北京时间当日 00:00 至次日 00:00 之前 |
| 逾期待办 | 活跃状态，联系时间早于当前时刻 |
| 未安排跟进 | 活跃状态，下次联系时间为空 |
| 未分配 | 业务负责人为空，主管可见 |
| 已成交 | 当前状态为已成交，不统计收款金额 |

今日与逾期可以重叠，例如今天上午到期且还未处理的客户。原小程序“今日新增”不是企微“今日待办”，两个指标不得混用。

## 8 管理和运行要求

主管应能查看读取凭据与回调参数是否齐备、最近同步结果、处理数量、失败原因和未处理事件。配置齐备与实际连接成功必须分别表述。同步按钮重复点击不能无限创建同类任务，失败事件应支持人工重试。

导出须与页面使用相同筛选和数据权限；客户最多 20000 条，跟进记录最多 100000 条，超出时提示缩小范围。CSV 支持中文并处理可能被表格软件执行的公式内容。导出和账号授权等关键操作记录操作者及结果，不记录密码或密钥明文。

一期采用单企业、单个客户服务实例，演示与正式数据隔离。每天备份数据库，升级前额外备份；定期恢复到独立新库核对数量及历史记录。数据保留期限由公司指定，在确定前不增加自动清理客户或跟进的任务。

以下是待验证的工程目标，不是已有压测结果：在 1 万位客户、10 万条跟进、20 个并发使用者的测试条件下，列表和详情响应的 P95 不超过 2 秒；本地收到回调后的持久化确认 P95 不超过 1 秒。外部企微延迟单独记录；资料补齐不能承诺固定到账时间。

## 9 验收用例

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 原后台入口 | 原咨询线索功能仍可用；授权账号能切换到企微客户 |
| A02 | 登录和隔离 | 后台登录后不再输入独立 CRM 密码；顾问直接调用订单等接口被拒绝 |
| A03 | 顾问数据范围 | 列表、详情、统计、修改和导出均只覆盖自己负责的客户 |
| A04 | 普通加好友 | 无小程序账号、手机号和渠道 State，仍能自动建档并补资料 |
| A05 | 重复及多员工添加 | 重复回调不重复建档；添加第二员工只增加一条关系 |
| A06 | 跟进闭环 | 保存沟通、状态、未来时间后，记录与待办同时更新 |
| A07 | 状态与时间校验 | 活跃跟进缺日期或过去日期被拒绝；关闭状态清空当前待办 |
| A08 | 修改冲突 | 同时打开旧版本表单，后提交者得到冲突提示，旧记录不被覆盖 |
| A09 | 分配与停用 | 改负责人后旧顾问失去权限；账号或关联停用后下次请求失效 |
| A10 | 删除和重新添加 | 关系变化正确，客户需求、负责人及历史记录保留 |
| A11 | 同步失败 | 错误可见，任务可重试，未完成名单不导致错误批量删除 |
| A12 | 来源边界 | 小程序线索和企微客户不自动合并，不把合计当去重总数 |
| A13 | 手机使用 | 在实际手机浏览器与企微工作台中查询、写跟进、查看待办成功 |
| A14 | 数据持久化 | 应用重启后数据存在；备份能恢复到新库，数量及记录一致 |
| A15 | 导出 | 中文可读，筛选有效，无越权客户，公式内容被转义 |
| A16 | 服务异常 | 断线、失效登录、无权限和空数据有不同提示，无静默丢失输入 |

模拟企微事件的测试与真实企业测试要分别记录。A04、A05、A10、A11 的真实接入环节以及 A13 的企微内使用，需要企业管理员配合。

## 10 实施顺序和上线条件

先确定账号和访问范围，完成原后台权限边界与服务接入；再实现企微客户、详情和待办页面；随后配置真实企微、用少量员工和测试客户联调；最后导入历史客户并试用。各步骤的代码任务、接口和数据变更在开发文档中对应列出。

上线前需要业务方提供实际企微企业、可接待员工名单、主管及系统管理员名单、正式域名和服务器、测试客户、运维负责人及数据保留要求。密钥在部署环境填写，不在需求文档中保存。未完成真实联调与权限验收前，不宣布生产上线。

当前版本不承诺固定上线日期或工期；按权限接入、页面整合、真实联调、试用四个里程碑验收。新增小程序身份匹配、消息推送等需求单独评估，不作为本期默认工作。
