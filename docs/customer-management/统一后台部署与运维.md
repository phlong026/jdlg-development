# 客户管理统一后台部署与运维

企微员工登录增量发布请同时参照 [企微员工登录与角色绑定配置说明](企微员工登录与角色绑定配置说明.md)，包括新增 Go 数据库迁移和自建应用环境变量。


版本：V1.2 · 2026-09-12。适用于本次已批准的后台整合实现；正式服务器尚未部署。

宝塔首次上线的详细步骤、配置模板、验收与恢复操作见[首次上线操作手册（宝塔版）](客户管理系统首次上线操作手册-宝塔版.md)。

## 1 部署形态

管理页面继续在 **background** 编译，上传 `dist` 到原静态网站目录，访问路径为 `/admin/customer-management`。员工使用原后台账号，不需要安装桌面软件，也不需要另一份CRM密码。手机通过同一网页的响应式布局使用；企微免登不在本期范围。

首次上线包含四部分：

| 交付项 | 构建与部署位置 | 职责 |
| --- | --- | --- |
| React页面 | background：`npm ci`、`npm run build`，发布dist | 复用原侧栏、顶部栏、页签与样式 |
| Go服务 | service：`go test ./route ./model`、`go build -o service .` | 原登录、平台访问范围、CRM账号关联、签名转发 |
| Java服务 | customer-management/phase1：`mvn test package`，部署target下可执行JAR | 复用客户、好友关系、归属、跟进、同步与导出 |
| 数据升级 | Go新增SQL；Java Flyway V2 | 账号授权、关联、签名防重放、审计、添加时间来源 |

以后只改React页面时，仅更新dist；涉及接口、权限或数据结构时同步更新对应后端。构建机器和服务器架构必须一致，或按服务器目标交叉编译Go。独立Vue演示无需部署到正式后台。

## 2 网络与配置

浏览器 → 原HTTPS站点 → `/api/v1/management/crm/*` Go → 内网Java `/internal/management/v1/*`。

Java不开放公网管理端口。公网只按需转发企微回调 `/iycallback/handle` 的GET/POST；禁止把整个Java站点或 `/internal/` 暴露给浏览器。保留既有Go API代理配置。

| 配置 | 设置位置 | 要求 |
| --- | --- | --- |
| CRM_BRIDGE_URL | Go | Java内网源地址，例如 `http://crm:8080`；不能含路径或查询参数 |
| CRM_BRIDGE_KEY | Go、Java | 同一随机长密钥，至少32字符；从部署机密管理配置，不放前端或Git |
| CRM_BRIDGE_KEY_ID | Go、Java | 两端相同，默认v1 |
| CRM_BRIDGE_AUDIENCE | Go、Java | 两端相同，每个环境单独设置，避免跨环境请求 |
| CRM_ALLOWED_ORIGINS | Go | 逗号分隔实际后台源地址，如 `https://admin.example.com`；含协议和非默认端口，不带路径或末尾斜杠 |
| CRM_STANDALONE_ENABLED | Java | 统一后台正式部署必须false，关闭旧Java登录及/api管理入口 |
| CRM_DB_URL / USER / PASSWORD | Java | 指向已有或正式专用客户数据库；不要指向演示库 |
| CRM_ADMIN_PASSWORD | Java | 保留原启动参数；随机设置，统一后台不以该账号登录 |
| CRM_DEMO | Java | 正式false；原启动保护禁止将演示库直接切换为真实企业库 |
| WECOM_CORP_ID / CONTACT_SECRET | Java | 真实企业及客户联系权限配置 |
| WECOM_CALLBACK_TOKEN / AES_KEY | Java | 真实回调验签解密配置 |

两端主机保持时间同步，签名时间窗口为60秒。若跨主机且内网不可信，Go到Java使用HTTPS并保留证书校验。切换密钥时同步更新两端；当前实现同一时刻只接受一个key-id，不声称支持双密钥平滑轮换。

前端默认使用同源相对路径；生产构建不要残留指向演示站点的VITE_API_BASE_URL。开发时通过现有Vite代理接Go，CRM_ALLOWED_ORIGINS填写浏览器实际开发源地址。

## 3 首次发布顺序

1. 在预发布库验证备份可恢复；分别备份Go平台库和Java客户库，记录构建版本、环境变量版本和Flyway当前版本。
2. 核对需要保留后台访问的**所有现有管理账号ID**，明确首批platform_admin；不能按姓名猜测，也不能只迁移当前一个管理员而误锁其他原管理员。
3. 在维护窗口执行 `service/sql/customer_management_bridge_up.sql`；紧接着按核对后的ID写入初始 `management_access`。SQL注释中的ID占位符必须替换为经确认的真实ID。
4. 部署Java新JAR，由Flyway从V1增量升级V2。不得修改V1校验和，不使用ddl-auto=create，不删除已有客户或跟进记录。V2完成后确认表结构和历史行数。
5. 部署Go更新及内部接入配置，验证已有平台管理员 `/me`、原线索及关键原后台接口。发布background/dist并先限制为上线人员验收；HTML短缓存、带hash资源长缓存，保留上一个完整dist。
6. 平台管理员打开“账号与权限”，先为自己关联CRM主管角色，首次可不绑定企微员工；重新登录或刷新权限。确认Java任务消费开启后发起员工/客户初始化同步。
7. 初始化成功后，使用“账号与权限”关联顾问与企微员工。新建后台账号默认禁用，关联失败也不会启用CRM访问。不能在首次员工名单为空时先要求顾问完成关联。
8. 分别以平台管理员、客户主管、顾问验收；完成真实加好友/删好友/重加/重复回调/初始化/手机企微内打开测试后再开放正式使用。

**授权表一旦存在，Go即持续执行该表规则，即使清空CRM_BRIDGE_URL也不会将crm_only账号放行到订单、配置等模块。** 未登记、停用、未知scope均拒绝；数据库故障返回不可用，不降级为允许。原平台未安装授权表且未开启CRM时保留旧行为。

## 4 迁移细节和数据口径

- Go新增 `management_access`、`management_crm_link`、`management_access_audit`，不复制企微客户表。
- Java V2新增Account的managed模式及平台userId/revision、客户addedTimeSource、nonce和操作审计表。
- 平台userId对应固定 `managed-{userId}` CRM账号。员工映射复用原ownerId，因此原客户/跟进继续可见；不会按显示名称把旧独立账号自动合并。旧密码和旧Cookie不能用来访问managed账号，正式部署另关闭整个旧管理入口。
- 授权按版本更新：先禁用关联，再调用Java配置，成功后激活。失败或进程中断时保留failed/pending且禁用；刷新读取当前版本后重试，不手工将关联表改成active。
- 旧记录的添加时间默认unknown。后续有可信好友添加时间时由同步修正来源；未知记录不算今日新增/最近新增，详情和CSV显示待核实。不能将首次初始化发现的历史客户都算作今日新增。
- 平台登录查询兼容管理账号为空的OpenID/UnionID，不为后台顾问编造小程序身份。

## 5 回滚与运行检查

页面问题：切回上一个dist版本，Go/Java及新增授权表保持运行。客户服务故障：暂时隐藏入口或清空Go桥接地址并重启Go，**保留本次访问限制代码和授权表**，原平台管理仍按显式授权访问。

不允许直接回滚到只判断“已登录”的旧Go二进制并继续允许新增crm_only账号登录，否则会扩大权限。如必须整体回退，在维护窗口关闭管理入口、撤销新账号登录及旧会话，并明确保留的平台账号后再实施；不能仅删除授权表作为回滚。Java优先向前修复，V2为增量字段/表，不自动执行删表降级。

恢复数据库应在停写窗口恢复相互对应的Go/Java备份，并核对关联版本、权限、客户及跟进数。独立恢复其中一个库可能让关联状态不一致，应先禁用受影响关联再按页面重新配置。

运行检查包括：Go `/me`、CRM `/context`、`/dashboard`；Java同步任务与失败事件；nonce清理任务；两侧审计表容量及归档策略。同步参数“已配置”只表示参数齐备，真实连通以同步结果及事件验证为准。日志与备份不要包含明文密钥；审计保存账号、动作、资源、结果，不保存密码。

## 6 本地隔离演示

`integration-demo/compose.yml` 仅用于本地联调：端口绑定127.0.0.1:8091，Go/Java使用新建的独立数据库，所有密码和客户均为公开测试数据，**不得用于生产**。原8087演示不受影响。

启动前构建Go `service/.crm-build/demo`、Java JAR及background/dist，将Java JAR复制为 `integration-demo/artifacts/app.jar`（构建输出与运行文件分开），然后在仓库根目录执行：

```powershell
docker compose -f docs/customer-management/integration-demo/compose.yml up -d
python docs/customer-management/integration-demo/verify.py
```

测试脚本会配置两个测试账号、模拟资料更新/跟进/停用及恢复，保留可见的测试历史。只能运行于该固定本地隔离环境。初始化后访问 `http://localhost:8091/admin/customer-management`：主管crm_admin、顾问crm_advisor，测试密码均为 `LocalCRM!2026`。登录后主管默认仍进入原总控台；本隔离入口只加载CRM与线索接口，因此直接打开客户管理地址查看，不能把隔离环境总控台数据未加载当成生产回归结果。

停止时使用该compose的`stop`或`down`，不要加`-v`删除数据。生产使用原service入口，不使用 `cmd/crm-integration-demo`；该命令也拒绝连接非 `jd_crm_integration` 数据库。
