# 客户管理系统首次上线操作手册（宝塔版）

版本：V1.0｜2026-09-12｜适用代码：本仓库已完成的统一后台接入版本。

用途：供项目负责人和运维人员按步骤完成首次生产发布。本文是操作方案，尚未连接正式服务器或执行生产变更。

## 1 先说明白：这次需要部署什么

**后台页面仍在 background 编译，上传 dist；首次上线另外更新原 Go 服务，新增一个 Java 客户服务，并升级两套业务数据结构。** 用户继续登录现有后台，在“客户管理”中工作。

| 交付项 | 为什么需要 | 在宝塔中的操作 |
| --- | --- | --- |
| background/dist | 增加驾驶舱、客户、跟进、同步、账号权限页面 | 更新现有后台网站静态文件 |
| Go 可执行文件 | 复用原登录，限制顾问访问范围，签名调用 Java | 更新现有 Go 项目的程序和配置，重启原项目 |
| Java 可执行 JAR | 处理企微客户、好友关系、同步、跟进和客户数据 | 新建一个内部 Spring Boot 项目，使用 JDK 17 |
| 平台数据库升级 | 保存后台访问授权、CRM 账号关联和授权审计 | 在原 Go 平台库执行一次新增 SQL，并初始化管理员 |
| 客户数据库升级 | 保存客户业务及桥接认证、审计等数据 | 新建专用客户库，或升级本项目已有客户库；Java 启动时由 Flyway 执行 |

“两套数据库”指平台业务库和客户业务库，可共用现有 MySQL 实例，不要求新增两台数据库服务器。原平台库不复制客户库，原 Redis、支付证书及小程序配置继续沿用。

访问链路：浏览器 → 原 HTTPS 网站 → 原 Go API → 本机 Java 服务 → 客户数据库。企微事件通过网站的指定回调路径进入 Java。

## 2 本手册的环境边界与上线登记表

已确认现有 Go 由宝塔管理。以下按 **宝塔 Linux 面板、Nginx、Go 与 Java 同一台服务器** 编写。服务器系统、实际目录、域名、端口和宝塔版本尚未核实；表格应由运维在上线前填完。如实际使用 Windows、Apache、跨服务器部署，不能直接套用下面的 Linux 命令和回环地址。

示例 Java 端口为 18087；仅当未占用时使用。所有“填写…”、“实际…”和尖括号占位符必须替换，不能原样执行。不要在登记表填写明文密码或密钥，只记录其保管位置。

| 登记项 | 上线前填写内容 |
| --- | --- |
| 服务器 | 系统版本、CPU 架构、宝塔版本、运维负责人 |
| 正式后台 | 完整 HTTPS 源地址，例如 https://admin.example.com；实际访问路径 /admin/ |
| 现有网站 | 宝塔网站名称、网站根目录、/admin 的实际文件目录、Nginx 配置备份路径 |
| 现有 Go | 宝塔项目名称、启动命令、程序绝对路径、工作目录、运行用户、监听端口 |
| Go 原配置 | MYSQL_DSN、Redis、SESSION_SECRET 等配置所在位置；只登记位置 |
| 原平台数据库 | MySQL 主机、端口、版本、数据库名、备份账号与备份位置 |
| 客户数据库 | 新建空库 / 本项目已有 V1 / 本项目已有 V2；主机、端口、库名、账号 |
| 新 Java 项目 | 项目名建议 jd-crm；JDK 17 路径、程序目录、运行用户、内网端口 |
| 企微配置 | 企业 ID、客户联系授权范围、接入负责人、凭据保管位置 |
| 回调安排 | 完整回调 URL、现有回调是否被其他系统使用、切换负责人 |
| 首批管理员 | 经业务负责人确认的所有平台管理员 user_id，不按姓名推断 |
| 发布与恢复 | 版本号、维护窗口、两库备份时间、恢复点、回退决策人 |

服务器终端只读检查示例：

```bash
uname -srm
df -h
free -h
ss -lnt
date -Is
```

确认磁盘能同时容纳当前版本、新版本、日志和数据库备份；Java 内存额度根据现有 Go、MySQL、Redis 的实际占用确定。不要为了 CRM 顺带升级生产 MySQL、Redis 或重装原 Go 环境。当前 Java 按单企业、单实例运行，不启动多个副本同时同步同一客户库。

宝塔支持将可执行 JAR 创建为 Spring Boot 项目，并提供启动与日志管理。不同面板版本的入口名称可能不同，以当前安装的“Java 项目 / Spring Boot”界面为准。[宝塔官方项目说明](https://docs.bt.cn/api/java/create_spring_boot_project)

## 3 发布前准备：先产出完整发布包

### 3.1 构建和检查

在开发机或构建机完成构建；生产服务器只需运行环境。下面是 **Linux 构建机** 示例，各段分别在对应目录执行。Windows 开发机的前端和 Java 可照常构建；Go 必须产出与生产 Linux/CPU 架构匹配的二进制，不能把 Windows 的 exe 上传到 Linux。

前端要求与仓库 Vite 版本兼容的 Node.js，本手册使用 Node.js 22.12+。先检查构建环境及 .env.production，确保 VITE_API_BASE_URL 未指向本地或演示地址；本项目正式整合默认同源 API。

```bash
cd /实际源码目录/jd/background
node --version
npm ci
npm run build
tar -czf ../background-dist.tar.gz -C dist .
```

Go 的 go.mod 要求 Go 1.24.1 起；本次本地验证使用 Go 1.24.13。使用相同版本工具链构建本次发布产物，并保留测试结果。

```bash
cd /实际源码目录/jd/service
go version
go test ./route ./model
mkdir -p .crm-build
go build -o .crm-build/service .
file .crm-build/service
```

构建的是 service 原生产入口，**不是 cmd/crm-integration-demo**。Go 的 file 输出应符合生产系统与架构。当前本地已有 Linux amd64 产物，但正式发布仍应从锁定的本次源码版本构建并核对。

```bash
cd /实际源码目录/jd/customer-management/phase1
java -version
mvn --version
mvn clean verify
```

Java 使用 JDK 17。上传 target/iyque-customer-phase1-1.0.0.jar，不上传 .jar.original。当前项目的 Flyway 迁移会随 JAR 打包。前端 npm test 仍是占位脚本，不能把它记为已通过的自动化测试。

### 3.2 发布包清单

| 文件 | 用途 |
| --- | --- |
| background-dist.tar.gz | 前端 dist 内容的归档，解压后直接有 index.html、assets |
| service | 新 Go 生产程序 |
| iyque-customer-phase1-1.0.0.jar | Java 客户服务 |
| customer_management_bridge_up.sql | 从 service/sql 原样复制的平台库迁移 |
| 发布记录 | 源码版本或源码归档哈希、构建工具版本、测试结果、产物 SHA-256 |
| 本手册及配置模板 | 含 deployment 下示例文件；正式密钥单独配置 |
| 开源许可说明 | 随交付保留适用的上游 LICENSE 及来源说明 |

在发布包目录计算校验值，上传后再次核对。不要将 .env、真实密钥、客户数据或本地演示库装进发布包。

```bash
sha256sum background-dist.tar.gz service \
  iyque-customer-phase1-1.0.0.jar \
  customer_management_bridge_up.sql > SHA256SUMS
sha256sum -c SHA256SUMS
```

## 4 发布顺序总表

| 顺序 | 操作 | 允许进入下一步的条件 |
| --- | --- | --- |
| 1 | 记录现状、建立备份、验证恢复 | 程序、网站配置、两库备份均可用 |
| 2 | 配置 Java 运行环境和专用客户库 | JDK 17、库连接、运行权限、企微凭据已核实 |
| 3 | 维护窗口内停写，升级平台库并授予初始管理员权限 | 三张授权表完整，所有应保留管理员均已登记 |
| 4 | 启动 Java，自动执行 Flyway | V1/V2 成功，原客户数据未减少，无演示模式 |
| 5 | 更新原 Go 程序及桥接配置 | 原管理员登录、原业务接口及账号权限页可用 |
| 6 | 发布前端，限制为上线人员验收 | /admin/customer-management 可打开并刷新 |
| 7 | 首个管理员开通 CRM，再同步企微员工与客户 | 管理员可进入同步页，初始化任务成功 |
| 8 | 关联顾问、接通事件回调、完成验收 | 权限隔离、真实事件、原后台回归均通过 |
| 9 | 开放使用、观察运行、登记发布结果 | 负责人确认开放时间与观察记录 |

维护窗口会涉及原 Go 重启，可能短暂影响小程序 API。按现有业务的维护流程安排，不在交易高峰直接停服务；已有支付回调与重试机制须由原业务负责人确认。本手册不改造既有支付链路。

## 5 备份与恢复验证

### 5.1 宝塔操作

1. 在“网站”记录正式网站目录和配置文件，保存现有 Nginx 配置副本；备份完整后台静态目录，不只保存 index.html。
2. 在现有 Go 项目记录程序路径、启动参数、工作目录、运行用户、环境变量保管位置，备份当前二进制。证书和业务配置保持原路径。
3. 在“数据库”备份原平台库；如已有正式客户库，也备份客户库。新空库则登记“首次创建，无历史数据”。
4. 备份放在网站根目录以外，并按现有制度保存异机副本。对外静态网站目录不能存 SQL、配置密钥或数据库压缩包。
5. 在临时恢复库演练一次导入，核对表数和关键行数。仅看到“备份成功”不足以证明能恢复。

### 5.2 数据库较大时的命令方式

可使用宝塔备份，也可由 DBA 使用 MySQL 客户端。下面只是命令方式，库名须替换。mysql_config_editor 交互输入密码，避免将密码写在 shell 命令参数中；备份文件本身仍需按敏感数据保护。

```bash
mysql_config_editor set --login-path=jd-release \
  --host=127.0.0.1 --port=3306 \
  --user=实际备份账号 --password
mkdir -p /www/backup/jd-crm-release
chmod 700 /www/backup/jd-crm-release
```

以下两条中的库名替换为实际库名；没有历史客户库时跳过第二条。文件名应使用本次发布唯一时间戳，不能覆盖上一份备份。

```bash
mysqldump --login-path=jd-release \
  --single-transaction --routines --triggers --events \
  --no-tablespaces --set-gtid-purged=OFF \
  实际平台库 > /www/backup/jd-crm-release/platform-发布时间.sql
```

```bash
mysqldump --login-path=jd-release \
  --single-transaction --routines --triggers --events \
  --no-tablespaces --set-gtid-purged=OFF \
  实际客户库 > /www/backup/jd-crm-release/crm-发布时间.sql
```

检查命令退出状态、文件非空、备份日志。使用匹配 MySQL 版本的客户端；账号须具备导出所需权限。single-transaction 适用于事务表，备份期间不能同时执行 DDL；如有非事务表，交由 DBA 安排一致性备份。两库关联写入应暂停，记录同一个恢复窗口。

宝塔中新建临时恢复库后，指定临时库导入备份，核对 users、授权表和客户核心表的行数及抽样数据。恢复验证不覆盖正式库。完成后按备份制度处理含真实数据的临时库。

## 6 平台数据库升级：一次性手工执行

### 6.1 确认目标库和管理员

在宝塔数据库工具中选择 **原 Go 的 MYSQL_DSN 指向的平台库**。确认不是演示库，也不是新客户库。先执行只读检查：

```sql
SELECT DATABASE(), VERSION();
SELECT id, username, user_type
FROM users
WHERE user_type = 'management'
ORDER BY id;
SHOW TABLES LIKE 'management_access';
SHOW TABLES LIKE 'management_crm_link';
SHOW TABLES LIKE 'management_access_audit';
```

业务负责人逐项确认哪些现有账号保留平台管理权限。初始授权名单必须包括所有应继续使用原后台的管理员。未登记账号会被新 Go 拒绝，不能只处理当前操作员。

三张表都不存在才执行首次建表 SQL；如果都已存在，先核对结构和已有迁移记录，不重复运行。只存在部分表时停止发布、查明上次中断位置，由 DBA 修复，不能直接删表重来。该 SQL 不带 IF NOT EXISTS，MySQL DDL 也不会因事务回滚自动撤销。

### 6.2 执行 SQL 并初始化权限

进入维护窗口，停止原 Go 项目或按现有发布方案停止对应写入及后台访问。Java 尚未对外开放。在所选平台库中执行发布包内 customer_management_bridge_up.sql，执行结果应为三张新表成功创建。

紧接着执行以下初始化授权。**尖括号内替换为已核对的数字 ID 列表，例如实际有多个管理员时使用逗号分隔；不要照抄示例账号或虚构 ID。**

```sql
INSERT INTO management_access
  (user_id, scope, enabled, version, updated_by, updated_at)
SELECT id, 'platform_admin', TRUE, 0, id, NOW(6)
FROM users
WHERE user_type = 'management'
  AND id IN (<经确认的管理员ID列表>);
```

```sql
SELECT a.user_id, u.username, a.scope, a.enabled
FROM management_access a
JOIN users u ON u.id = a.user_id
ORDER BY a.user_id;
SELECT COUNT(*) AS crm_links FROM management_crm_link;
```

确认授权行数和名单与审批名单完全一致；首次空部署的 CRM 关联数为 0 是正常状态。初始化脚本不应重复执行；重复键报错时应检查已有记录，不能用 REPLACE 覆盖历史授权。

**不要通过删除授权表处理登录问题。** 新 Go 在表存在后持续执行权限规则，即使暂时关闭 CRM 桥接，也不会让顾问获得订单、配置等平台访问权。

## 7 Java 客户服务：宝塔新增内部项目

### 7.1 准备数据库与目录

在宝塔“数据库”中新建独立客户库，例如 jd_crm_prod，采用 utf8mb4，并创建仅访问该库的账号。平台库的 MYSQL_DSN 不变。Java 启动升级时需要执行 CREATE、ALTER、INDEX 等迁移权限；如采用迁移后收紧权限的制度，每次升级前需按流程恢复迁移权限。

如果已经有本项目 phase1 正式 V1 库，使用该库备份后升级。只有表结构和 Flyway 历史均属于本项目时才可直接升级；不能把其他版本的原始 Iyque 数据库直接接入，也不能把演示库改名当正式库。不要为 CRM 单独升级现有 MySQL 大版本。本地已在 MySQL 8.4 验证，本次 Flyway 版本会对该数据库版本给出兼容性提示；生产实际版本须先在预发布环境验证。

建议通过宝塔“文件”创建如下目录；路径为新 Java 服务示例，不改变 Go 原目录：

```text
/www/server/jd-crm/
  releases/本次版本/app.jar
  config/crm.env
  logs/
```

程序和配置不放在对外网站静态根目录下。选择一个专用、无登录权限的 Java 运行用户；给予它读取 JAR 和配置、写入日志所需权限。配置文件仅该用户与运维可读。安装并选择 JDK 17，不选择 JDK 8、11 或 Tomcat 项目。

### 7.2 Java 环境变量

随手册提供 deployment/crm-java.env.example。复制并填入真实值，存入服务器配置目录，再在宝塔 Java 项目中配置环境变量或配置文件加载。**把文件放在 JAR 旁边不会自动生效**；普通 java -jar 不会自动读取 .env。

| 变量 | 正式值或说明 |
| --- | --- |
| SERVER_ADDRESS | 同机部署为 127.0.0.1 |
| SERVER_PORT | 18087，先检查是否空闲 |
| CRM_DB_URL | jdbc:mysql://实际数据库地址:3306/实际客户库，带 UTF-8 和 Asia/Shanghai 参数 |
| CRM_DB_USER / CRM_DB_PASSWORD | 专用客户库账号与真实密码 |
| CRM_DEMO | false |
| CRM_STANDALONE_ENABLED | false，关闭独立 CRM 密码登录与旧管理 API |
| CRM_SECURE_COOKIE | true |
| CRM_ADMIN_PASSWORD | 必填，独立随机强密码，至少 12 字符；不作为员工登录密码 |
| CRM_BRIDGE_KEY | 与 Go 完全相同的随机密钥，至少 32 字符 |
| CRM_BRIDGE_KEY_ID | 两端相同，例如 v1 |
| CRM_BRIDGE_AUDIENCE | 两端相同、环境独立，例如 jd-crm-production |
| CRM_JOBS_ENABLED | 首次升级检查阶段设 false；第 10 节初始化前改 true 并重启 |
| WECOM_CORP_ID | 真实企业 ID，首次启动前填好 |
| WECOM_CONTACT_SECRET | 客户联系接口对应凭据，不使用小程序 Secret |
| WECOM_CALLBACK_TOKEN | 与企微回调配置相同 |
| WECOM_CALLBACK_AES_KEY | 与企微回调配置相同的 43 字符 EncodingAESKey |

桥接密钥可在受控终端使用 openssl rand -hex 32 生成；两端使用同一次生成结果。CRM_ADMIN_PASSWORD 和数据库密码分别生成。不要截取含密钥的面板截图，不把值发到聊天、前端构建参数或代码仓库。

CRM_JOBS_ENABLED=false 会暂停定时事件处理和同步队列消费，因此此时手工创建同步任务也不会被处理；它不是关闭全部写入的开关，已经开放的回调仍可能保存事件。数据库备份停写不能只依赖此配置。

### 7.3 创建项目并启动

1. 宝塔“网站 / Java 项目”或对应 Java 项目管理页，添加 Spring Boot 项目。
2. 项目名填写 jd-crm，选择本次版本目录中的 app.jar，JDK 选择 17，设置专用运行用户与日志目录。
3. 配置上一节环境变量，检查密码是否被截断，JDBC 地址中的 & 是否完整。
4. 启动命令采用下列形式。JDK 路径、版本目录替换为实际值；JVM 参数在 -jar 之前。

```bash
/实际JDK17目录/bin/java \
  -Duser.timezone=Asia/Shanghai \
  -jar /www/server/jd-crm/releases/本次版本/app.jar
```

5. 不给该项目创建整个 Java 站点的公网映射，不开放 18087 到公网；配置开机自启和项目日志管理，然后启动一次。
6. 不要同时让宝塔与另一个守护进程重复启动同一 JAR。若项目支持直接注入环境变量，使用上面的 Java 命令即可；若只有自定义启动命令，可使用随手册的 start-crm.sh 加载配置。

可选启动器方式：把 deployment/start-crm.sh 上传为 /www/server/jd-crm/start-crm.sh，保存为 UTF-8 无 BOM、LF 换行。在宝塔可配置自定义进程启动命令的位置填写以下命令，仍仅由一个宝塔项目管理；若当前 Java 项目不允许更改启动命令，由运维选用宝塔已有的进程管理功能，不能再额外启动第二份服务。

```bash
/bin/bash /www/server/jd-crm/start-crm.sh \
  /实际JDK17目录/bin/java \
  /www/server/jd-crm/releases/本次版本/app.jar \
  /www/server/jd-crm/config/crm.env
```

该启动器按字面读取 KEY=VALUE，不执行配置内容。使用模板格式：等号两边不加空格，值不加外层引号，不使用 export、变量替换或行尾注释；JDBC 中的 & 可以直接保留。脚本会拒绝未替换的 REPLACE_ 占位符，不打印配置值。此方式以文件中的值覆盖同名进程环境变量；Go 的 .env.local 优先级则按第 8 节处理。

### 7.4 Flyway 自动升级与启动验收

新空库：Java 首次启动自动执行 V1 和 V2。已有本项目 V1 库：自动执行 V2。已有 V2：校验后启动。保持 ddl-auto=validate，不手动执行 JAR 里的 V2 后又让 Flyway 执行一次。

在客户库查询：

```sql
SELECT installed_rank, version, description, success
FROM flyway_schema_history
ORDER BY installed_rank;
SHOW COLUMNS FROM crm_account;
SHOW COLUMNS FROM crm_customer;
SHOW TABLES LIKE 'crm_bridge_nonce';
SHOW TABLES LIKE 'crm_operation_audit';
SELECT COUNT(*) AS customers FROM crm_customer;
SELECT COUNT(*) AS followups FROM crm_followup;
```

应看到 V1、V2 成功；crm_account 含 authMode、managementUserId、managedRevision；crm_customer 含 addedTimeSource；已有客户与跟进行数和迁移前一致。新库客户数为 0 正常。

检查宝塔 Java 日志无迁移失败、连接失败或“数据库已绑定另一运行模式或企业”。出现绑定错误时检查是否选错库或企业，不修改 crm_setting 绕过保护，不删除 Flyway 历史或随意执行 repair。

```bash
ss -lnt | grep ':18087'
curl -s -o /dev/null -w '%{http_code}\n' \
  http://127.0.0.1:18087/api/auth/me
```

监听应限本机；在 CRM_STANDALONE_ENABLED=false 时旧接口预期返回 403。这个检查只证明进程可响应且旧入口关闭，完整可用性还需 Go 桥接和同步验证。当前没有约定的 /actuator/health，不能用该路径作为上线依据。

## 8 原 Go 后端更新：保留原项目，增加桥接配置

### 8.1 增加配置

使用 deployment/crm-go.env.example 中的五个参数，合并到原 Go 的受控配置，不覆盖原 MYSQL_DSN、SESSION_SECRET、Redis、支付或其他业务参数。

```dotenv
CRM_BRIDGE_URL=http://127.0.0.1:18087
CRM_BRIDGE_KEY=填写与Java一致的随机密钥
CRM_BRIDGE_KEY_ID=v1
CRM_BRIDGE_AUDIENCE=jd-crm-production
CRM_ALLOWED_ORIGINS=https://实际后台域名
```

CRM_BRIDGE_URL 只能是源地址，不能追加 /internal 或其他路径。CRM_ALLOWED_ORIGINS 填浏览器实际源地址，包括协议和非默认端口，不带 /admin/ 或结尾斜杠；多个源用英文逗号分隔。不要填 *。跨主机部署时回环地址不适用，应单独核实可访问的内网地址和访问限制。

Go 本次支持 .env.local：优先使用 JDLG_LOCAL_ENV_FILE 指定的文件；未指定时依次查找工作目录和程序目录下的 .env.local。已有进程环境变量优先，甚至空值也会覆盖文件值。修改配置后必须通过宝塔重启原项目；只在终端 export 不会改变已经运行的宝塔服务。

若原项目已经用宝塔环境变量管理，就在原处新增五项；若用 .env.local，就备份后合并并保持原工作目录。不要额外创建一份失效的 .env 或把示例文件直接覆盖全部原配置。

### 8.2 替换与启动

1. 在维护窗口停止宝塔中原 Go 项目；确认平台库迁移和初始管理员授权已完成。
2. 将旧 Go 程序备份到本次发布备份目录，记录 SHA-256、属主与权限。
3. 上传新 service 到暂存目录，核对校验值和 Linux 架构，再替换原项目实际使用的可执行文件，恢复原运行用户所需的执行权限。
4. 保持原项目启动参数、工作目录和证书路径不变，保存桥接配置，启动原项目。
5. 查看原 Go 日志，确认不是错误使用空库、演示库或缺少原业务依赖。不要为了让进程启动而删除原业务初始化检查。
6. 使用原平台管理员登录，验证原后台入口和关键只读页面；通过浏览器开发者工具检查 /api/v1/management/me 成功，再检查 CRM 账号权限接口。

初始平台管理员在未关联 CRM 角色前，可以管理“账号与权限”，但不应据此认为客户驾驶舱已开通。CRM 关联请按第 10 节完成。

## 9 前端与 Nginx：仍使用原后台网站

### 9.1 上传 dist

在宝塔“文件”打开原后台实际静态目录。将新包先解压到临时目录，确认包含 index.html 和 assets，再按原网站的发布方式切换。保留完整旧版本和旧 hash 资源，避免仍打开旧页面的用户遇到资源 404。

最终请求 /admin/index.html 必须能定位到这次的 index.html。不要多放一层 dist 导致实际路径变成 /admin/dist/index.html。如果原站点用了 alias、独立后台子目录或软链接，应沿用原映射，不能只按文件夹名称猜位置。

HTML 建议使用短缓存或重新校验；带 hash 的静态资源可长缓存。部署后用无痕窗口打开 /admin/customer-management 并刷新，不能只测试从首页点击跳转。

### 9.2 保留 Go 代理，只增加企微回调

原 /api/v1/management/ 仍由 Go 处理。不要将 CRM 浏览器接口直接代理到 Java，也不要改动原小程序 API 路由。

随手册提供 deployment/nginx-crm-callback.conf.example。以下片段放进**现有 HTTPS 网站的 server 块**；若同一路径已存在，应核对并修改原规则，不能添加重复 location。

```nginx
location = /iycallback/handle {
    proxy_pass http://127.0.0.1:18087;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 5s;
    proxy_read_timeout 15s;
    client_max_body_size 128k;
}
```

proxy_pass 此处不带新 URI，保留原回调路径和查询参数；不要加登录验证、修改 XML 正文、缓存响应或把 GET/POST 重定向到首页。回调无需浏览器跨域设置。不要把 /internal/ 或整个 Java 根路径代理到公网。

在宝塔网站配置中先测试配置，通过后平滑重载 Nginx。若使用终端，应使用该宝塔实例的 Nginx 可执行路径测试，不假定系统默认 nginx 就是实际服务。

如果原后台缺少 SPA 刷新支持，在核实静态 root/alias 后由运维添加相应回退。仅在“网站 root 下真实存在 admin/index.html”时，下面示例才适用：

```nginx
location /admin/ {
    try_files $uri $uri/ /admin/index.html;
}
```

宝塔现有伪静态与反向代理规则可能已有相同功能，先检查再改。不要用整个示例替换完整网站配置。

## 10 首次开通：先管理员，再同步，再顾问

这是首次空客户库最容易遗漏的步骤。企微员工列表依赖初始化同步，而发起同步需要 CRM 管理角色，因此应按以下顺序操作。

1. 暂只向上线人员开放新版后台。使用第 6 节已授权的原平台管理员登录。
2. 打开 /admin/customer-management?tab=access，进入“账号与权限”。
3. 为该管理员自己的后台账号启用 CRM 关联，CRM 角色选择“客户主管 / admin”，保持平台权限 platform_admin；首次员工列表为空时，主管可以不绑定企微员工。启用后台访问与 CRM 访问并保存。
4. 确认关联成功，而非 pending 或 failed。退出并重新登录，或刷新页面加载新权限，再检查是否出现驾驶舱、客户和同步入口。
5. 在宝塔 Java 项目将 CRM_JOBS_ENABLED 改为 true 并重启；确认企业凭据齐备。避免在仍暂停队列消费时反复点击同步。
6. 在“同步与异常”发起一次初始化同步，等待成功，核对员工名单、客户数、关系数和错误提示。已有任务时返回 409 表示不能重复创建，等待或检查原任务。
7. 回到“账号与权限”，为顾问创建或选择后台账号，平台访问范围选 crm_only，CRM 角色选 staff，并绑定准确的有效企微员工。按企微员工 ID 和实际身份确认，不能只看同名显示名。
8. 新建账号默认禁用，确认映射正确后按页面启用。关联失败时先修复配置，刷新读取最新版本后重试，不手工将数据库 state 改为 active。
9. 使用一个顾问账号登录，确认只能看到允许范围内的客户和跟进，不能进入原订单、配置和平台授权管理。

初始化会同步接口授权范围内的历史客户，不保证能读到企业中所有客户。没有可靠添加时间的历史记录显示待核实，不应全部计入“今日新增”。主管和顾问的初始数量可能不同，应按权限范围核对。

## 11 接通企业微信：以后自动接收客户变更

客户不需要每次手工导入。上线时做一次初始化；之后由有效企微事件触发更新，后台还会按当前实现约每 30 分钟调度一次全量补同步。事件处理是异步的，不能把“企微回调返回成功”直接等同于客户详情已经补齐。

### 11.1 配置和连通检查

1. 由企微管理员确认本企业的客户联系 API 授权、可读取员工范围及实际调用凭据；在当前企微后台按其要求配置服务器可信出口 IP 等访问条件。公网入口 IP 与服务器访问企微 API 的出口 IP 可能不同。
2. 检查现有接收事件服务器是否已经供其他系统使用。已有回调时先明确共存或迁移方式，不能直接覆盖后导致其他业务收不到事件。
3. 本系统回调地址设为 https://实际后台域名/iycallback/handle，Token 与 EncodingAESKey 必须和 Java 环境变量一致。
4. 保存企微回调设置，使用企微发起的 URL 校验确认通过。回调地址须可从公网经 HTTPS 到达，不经过后台登录、验证码或 WAF 人机挑战。
5. 检查服务器 DNS、外网 HTTPS 出口、证书和时间同步。内部桥接签名允许约 60 秒偏差，回调校验时间窗口为 5 分钟，时间漂移会使合法请求失败。

企微管理界面及权限要求以当前企业账号实际配置为准。本手册中的回调路径、参数长度和事件处理行为已对照本仓库源码；尚未代为完成真实企业授权或联调。

### 11.2 真实事件验收

由业务人员使用约定的测试客户完成一次添加，并确认好友关系真正建立。检查客户列表、所属员工、添加时间及同步状态。再在测试关系上验证删除、重新添加，保留跟进历史。不要拿真实在服务客户反复删加做测试。

本期处理 add_external_contact、edit_external_contact、del_follow_user、del_external_contact。并非所有企微事件都属于本期业务；其他事件可能应答 success 而不产生客户记录。

若 URL 校验成功但客户迟迟不出现，查看同步任务和失败事件：确认任务消费已开启、Secret 有效、员工在授权范围、回调被正确解密，修复后通过界面重试。不能通过手工插入客户来掩盖接入故障。

普通浏览器打开回调 URL 没有合法签名，返回 400/403 不代表回调部署失败。对外同步接口参数“已配置”也不等于企微 API 实际调用成功，必须有成功同步和真实事件证据。

## 13 常见故障与处理

| 现象 | 优先检查 | 处理方式 |
| --- | --- | --- |
| Go 启动失败 | 架构、执行权限、原工作目录、原业务配置 | 恢复正确部署路径和参数；看原 Go 日志，不换成演示入口 |
| 原管理员登录后 403 | management_access 是否包含其真实 user_id，enabled 和 scope | 核对已批准管理员名单，修正明确授权，不删授权表 |
| CRM 请求 502 | Java 进程、端口、桥接 URL、两端密钥与 audience、时钟 | 先查 Java 日志与本机连通，再核对受控配置并重启 |
| 查询正常，保存 403 | CRM_ALLOWED_ORIGINS 与浏览器 Origin 是否一致 | 修正协议、端口与域名；确认用正式同源前端 |
| CRM 关联 pending/failed | Java 配置失败、版本冲突或进程中断 | 修复原因，刷新当前状态再重试，不直接改 active |
| 员工下拉框为空 | 还未同步，或 Secret 无员工读取范围 | 先给主管不绑员工开通 CRM，再执行初始化 |
| 同步一直 pending | CRM_JOBS_ENABLED 是否仍 false | 改 true 并重启 Java，观察原任务，避免重复提交 |
| 同步因重启显示 failed | 运行中的任务被服务重启中断 | 确认服务稳定后重新发起同步，核对结果 |
| Flyway 校验或迁移失败 | 是否选错库、已有部分结构、V1 被修改 | 停止发布，保留错误和备份，由开发/DBA定位；不盲目 repair |
| 数据库企业绑定错误 | 演示库、旧企业库、WECOM_CORP_ID 错误 | 使用正确专用库；不修改绑定标记强行继续 |
| 回调校验失败 | URL、HTTPS、代理参数、Token/AESKey、企业 ID、时间 | 对照两端配置，在企微后台重新校验 |
| 回调成功但详情未更新 | 队列暂停、凭据无权、失败事件积压 | 恢复任务消费及 API 权限，界面重试并核对真实结果 |
| /admin 刷新 404 | 静态目录和 SPA 回退 | 核对原 root/alias 与配置优先级，不额外嵌套 dist |
| 管理页面白屏或旧资源 404 | 新旧 index 与 assets 不配套、缓存 | 恢复完整发布目录，保留旧 hash 资源并刷新 HTML |

排错记录只保留必要的请求时间、路径、状态码和脱敏错误。不要把数据库密码、桥接签名密钥、会话 Cookie 或完整客户数据粘贴到工单。

## 14 回退方案：按故障范围操作

### 14.1 只有前端问题

在宝塔将后台静态目录切回上一份完整 dist，保留对应 assets；恢复网站配置时只恢复本次相关改动，配置测试后重载。Go、Java 和已升级数据库保持，不执行数据库降级。

### 14.2 只有 CRM 服务异常

先暂停客户管理使用，保留 Go 新权限代码。可在 Go 配置中明确关闭 CRM_BRIDGE_URL 并重启原项目，以暂时停用桥接；注意进程环境变量优先级，不能只清空一个未生效的文件。原平台访问仍受 management_access 约束。隐藏前端菜单本身不能替代后端停用。

如果 Java 可运行且需要保留事件，可关闭 CRM_JOBS_ENABLED 暂停队列消费，继续记录回调；如果 Java 必须停机，记录企微事件可能无法接收的时间段。恢复后重新同步并核对客户关系，不假定补同步能重建所有未收到的历史事件。

### 14.3 必须回退 Go 或恢复数据库

**不能直接启动旧的“只检查已登录”Go 版本并继续让 crm_only 顾问登录，这会扩大其平台权限。** 优先修复当前版本。必须整体回退时，在维护窗口关闭管理入口，确认新 CRM 账号已不能登录、旧会话已失效，并由负责人明确旧版本允许访问的账号范围。仅隐藏菜单或清空桥接地址不能解决旧 Go 权限问题。

Java V2 是增量迁移，不提供自动删表降级。数据库恢复按以下顺序，由 DBA 执行，不在此提供可误覆盖正式数据的一键恢复命令：

1. 停止相关写入和账号授权操作，停止相关服务，记录最后成功写入及回调时间；保护当前故障现场备份。
2. 确认恢复点与可接受的数据损失。上线前备份之后的客户修改、跟进、权限变更不会自动出现在旧备份中。
3. 将平台与客户库对应恢复点先恢复到临时库，验证结构、客户和跟进行数、账号关联版本、授权状态。
4. 按既定切换方案恢复两库及兼容程序，核对 management_crm_link 与 Java managedRevision，保持异常关联禁用。
5. 按“平台管理员 → CRM 管理员 → 顾问”的顺序验证，修复后通过页面重新关联，不手工扩大权限。
6. 恢复回调与任务消费，补同步并核对停机窗口，登记无法自动恢复的历史数据。

若只恢复单个库，关联版本可能不一致，必须单独核对受影响账号并重新配置。不要删除授权表、客户历史或 Flyway 表来让服务“先跑起来”。

## 15 上线后的日常操作与后续发布

上线当日观察 Java/Go 异常重启、CRM 5xx、同步失败、事件积压、数据库连接、磁盘和内存；至少确认一轮周期补同步完成，再结束发布观察。次日检查一次客户新增、归属、跟进与企微实际情况。

宝塔中为平台库和客户库配置定期备份，频率和保留期按可接受的数据损失确定；初期建议至少每日备份，并保留异机副本，定期做恢复抽检。日志设置轮转，关注授权审计、操作审计及事件表增长，不未经评估直接清空表。

| 以后修改了什么 | 需要重新发布什么 |
| --- | --- |
| 页面、样式、纯前端交互 | background 重新构建并发布 dist |
| Go 接口、权限或桥接 | 更新 Go，检查对应配置；有新 SQL 时按迁移要求执行 |
| 客户同步、跟进等 Java 逻辑 | 更新 JAR，按版本迁移说明启动与验证 |
| 数据结构 | 先备份和预发布验证，再按该版本迁移计划上线 |
| 企微凭据或桥接密钥 | 更新实际生效的服务配置并重启验证；桥接密钥两端协调切换 |

当前桥接只接受一组 key-id 和密钥，轮换需要协调维护窗口，不能假定支持双密钥无缝过渡。停止服务使用宝塔相应项目的“停止”，不要使用 killall java 或停止整台 MySQL 影响其他业务。
