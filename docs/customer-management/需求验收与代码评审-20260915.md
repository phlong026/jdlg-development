## 确认口径

用户已确认继续开发，并明确要求**保留“记住密码”**。因此原待确认方案中的“改成记住账号、清除密码缓存”不执行。本轮保留原本地读取、回填、保存与取消记住逻辑，仅调整布局和密码显隐。

## 验证证据

- Java：集成测试覆盖报备、并发认领、保护、资料修改、三类来源合并/重放、历史迁移、审批、交接、附件和签名边界。最终 **47 项通过，0 失败、0 错误**；详见 `phase1/target/workflow-verification.log`。
- Go：`go test ./route ./model ./function ./processor ./component` 通过（processor 无独立测试文件），覆盖网关路径、签名、权限、原线索模型及 Unicode 边界；演示服务与正式 Go 主程序构建均通过。
- React：`tsc --noEmit`、`npm run build` 通过；浏览器检查登录断点、显隐、记住密码、主管工作台和五项报备表单。
- 真实本地链路：`integration-demo/verify_workflows.py` 在 localhost 8092 执行通过，验证 Go → Java → MySQL，包括小程序可靠接入/重放、历史跟进去重并且不计续期、主档关联、旧入口阻断、附件、转交、成交、恢复及公海。
- 数据库：MySQL 8.4 完成 V3 → V4 → V5 升级；新增历史记录键使用 V5 独立迁移，不改已部署的 V4。升级前演示备份恢复到独立库，客户 10/10、跟进 5/5 一致。

## 代码评审结论与修复

本轮为静态代码检查结合自动化回归，并未声称经过另一位独立审阅者审核。

| 发现的问题 | 修复与验证 |
| --- | --- |
| 原后台默认弱密码与旧 MD5 存储 | 新库不再自动种入 123456；新账号 bcrypt、旧密码兼容验证并升级；登录限流及会话配置加固，单元测试及实际旧账号登录验证 |
| Spring 事务代理外直接访问字段会取空值 | 改为方法访问仓库，新增控制器/工作台/测试恢复正常 |
| 主管代补资料可能把客户归到自己 | 使用已分配的有效负责人开始保护，专项用例验证 |
| 旧接口可直接改成交或独立跟进 | Java 阶段变更统一受审批约束，Go 旧写入口关闭，前端原线索仅查询 |
| 关联档案可能绕过保护或成交状态 | 保护客户优先保留；不同归属须先有主管处理；已确认成交/归档不能借关联恢复开发 |
| 合并后的审批及历史记录可能不可见 | 通过原档案映射汇总；审批解析当前主档后重新校验版本和归属 |
| 报备、认领、到期回收、来源合并可能互相竞争 | 统一业务锁并校验版本；事务中刷新锁定实体；并发测试通过 |
| 后台工作台可能返回过量记录并重复查账号 | 批量加载账号/员工映射；每类 200 条、重复组 100 组且显示真实总数，处理后刷新下一批 |
| 接入内容含 emoji/长文本可能超过 Java 字段长度 | Go 按 UTF-16 边界限制摘要长度；原数据保留；历史每批最多 5 条保证请求体界限 |
| 历史小程序跟进未进入主时间线 | 增加来源记录唯一键与持久化游标；导入记录明确不计续期 |
| 登录页与“记住密码”明确指示不一致 | 恢复密码读取/保存及标签，实际回填验证；保留其他既有企微登录入口 |

3. 在真实手机、企微内置浏览器验证软键盘、安全区、自动填充和登录。当前完成的是浏览器视口模拟。
4. 正式域名 HTTPS、服务器密钥、数据库权限、备份计划、恢复演练、容量/负载及外部监测告警。当前备份恢复和迁移只在隔离演示库验证。
5. 业务主管核实真实历史客户归属、重复电话、成交状态与资料。代码提供工作台，不替业务人员虚构审核结论。

未纳入本轮：财务收款核销、完整合同系统、渠道佣金、聊天存档、群发营销。成交确认不等于财务到账。

## 发布和回退要点

1. 暂停入口写入及自动任务，分别备份 Go 和 Java 数据库，保留现有二进制及前端构建。正式 Go 必须设置独立 `SESSION_SECRET`（至少 32 字符），新库需设置 `INITIAL_ADMIN_PASSWORD`（至少 12 字符且最多 72 字节）。
2. 先升级 Java（Flyway V4/V5），再升级 Go（来源检查点表及历史游标），最后更新前端；用演示脚本等价步骤验收后恢复任务。
3. **不能只回退旧二进制继续写新数据。** 若需回退到统一规则前，先停止写入，保留失败现场，恢复升级前备份到新库并切换成对版本；升级后的新增数据须单独核对迁回。
4. 企微消息默认关闭：`WECOM_NOTIFY_ENABLED=false`；应用 Secret 与客户联系 Secret 分开配置。站内提醒无需外部推送配置。
5. Go 来源失败每 5 分钟重试；来源页面显示接入状态。原始线索即持久化待投递来源，成功应答后才推进检查点；历史每轮每客户最多 5 条。

## 交付范围与版本控制

工作区根目录原无 Git 仓库，本轮建立本地仓库收录 React/Go 源码基线及本轮集成改动；Java 保留 `customer-management` 原独立仓库，分别提交。本轮未推送远端，也未发布生产。真实密钥、证书、`.env.local`、构建产物、运行缓存及数据库备份不纳入提交。其他原始业务 SQL 与小程序源码保持原状。根仓库首次纳入 357 份源码/配置样例/文档，不代表本轮重写或逐项审计了全部既有平台模块。

限制：旧账号哈希仅在正确登录后升级，未登录账号以及超过 bcrypt 72 字节限制的历史密码仍保留兼容路径；正式启用前应核实历史弱密码账号。当前登录限流按服务进程计数，多实例部署应在入口叠加统一限流。

最终本地验收结果：2026-09-15，Java 47/47；Go 相关包测试与正式主程序构建通过；TypeScript 与 Vite 构建通过；MySQL Flyway 1–5 均成功；两位公开演示管理账号成功由旧哈希兼容升级。未检出暂存文件中的常见私钥/API Key 格式，真实环境文件和证书目录均排除。
