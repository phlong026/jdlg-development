# 线索移交与跟进入口约定

生效：2026-09-16。本文是团队执行规矩，不是系统功能说明；对应的系统拦截能力已由代码实现（旧线索写接口在统一接入启用后返回 409，前端只读）。

## 1. 唯一跟进入口

1. 客户**加了企业微信之后**，销售跟进一律在「客户管理」的统一客户档案进行；客服线索工作台对该客户**不再新增跟进和状态变更**，只作历史查询。
2. 客户**尚未加企微**（仅小程序咨询）时，仍在客服线索工作台承接与联系；推动客户添加企微，是移交的前置动作。
3. 不允许两边同时跟进同一位客户。发现两边都有待办时，以本约定第 2 节流程移交后，只保留 CRM 侧待办。

## 2. 移交流程（人工核对，系统不做自动合并）

1. 核对身份：小程序线索与企微客户是否同一人，以**电话**为准核对；企微不返回手机号时，通过聊天或来电确认，不按昵称/姓名猜。
2. 在 CRM 侧补齐：确认归属顾问，补齐 5 项资料（姓名/微信、电话、镇村地址、面积与需求、预计建房时间），资料齐全且归属确认后开始 90 天保护。
3. 在旧线索侧收尾：把该线索状态更新为已转化/已移交的对应状态，备注"已移交 CRM，客户编号 KHxxxx"，原跟进历史保留，不删除。
4. 移交后如小程序侧再来新咨询，按新线索正常登记，CRM 侧在原档案继续跟进；主管在重复核实工作台处理同电话提示。

## 3. 主管职责

1. 定期（建议每周）检查"账号与权限 → 归属绑定完整性"：有名下客户但未绑定后台账号的员工，要么建号绑定，要么转交客户。
2. 定期检查"待完善报备"队列：企微自动接入的客户以"待同步客户"占位入库，需补资料、确认归属后才起算保护期；长期不完善的按无效或公海处理。
3. 移交争议按现有"归属争议"申请流程处理，不在旧线索工作台改状态解决。

## 4. 边界说明

- 系统不按手机号自动合并小程序线索与企微客户档案；同电话会拦截重复报备，例外走主管核实。
- 手动报备客户与企微客户是同一主档的两个来源时，由主管用"关联同一客户"合并，原记录与历史全部保留。
- 本约定不改变权限模型：顾问仍只能操作本人归属客户；渠道账号即使不绑定企微员工也可报备与认领公海。
