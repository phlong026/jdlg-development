# 客户快速报备与公海

## 使用入口

统一后台 `客户管理` → `新增客户报备`。客户档案和公海的空列表也提供“创建新客户”。电脑和手机浏览器共用响应式页面。

报备仅需 5 组资料：

1. 客户姓名、微信号（微信选填）。
2. 联系电话：大陆手机号或带区号固定电话。
3. 详细镇村地址。
4. 建房面积（平方米）及需求：新建、翻建、改造、装修。
5. 预计建房时间，支持“明年春天”等文字；尚未明确时可填“待定”。

补充备注选填。姓名、联系电话、地址、面积、需求和预计时间由服务端校验。手机号自动去空格、括号、连字符及 +86 / 0086 前缀；手动报备客户以规范化电话唯一约束和事务锁防重复。

## 归属与保护

- 报备成功由服务端生成 `KH` 开头的唯一客户编号，绑定当前登录的 CRM 账号，客户端不能指定负责人。主管未绑定企微员工也可报备，归属仍为主管账号。
- 本次规则适用于**手动报备客户**。已有企微同步客户继续沿用原负责人分配和访问规则；小程序咨询线索不自动合并。此增量避免在升级时把历史客户直接转入公海。
- 初次报备保护 90 天。保存非空的“跟进、沟通、出图、报价”记录后，从服务器记录时间起重新计算 90 天。继续跟进沿用现有下次联系时间要求。
- 改资料、改状态、调整联系计划、查看档案均不续期。保护期内不能通过原分配接口调整手动报备客户的归属。
- 无有效跟进达到到期时间，即可在客户公海查看，原负责人不能继续修改或补记跟进。服务端每分钟按批清理过期归属并记录历史；即便任务尚未运行，接口也按准确到期时间执行公海权限。
- 已授权进入 CRM 的各渠道账号均可认领公海客户。认领保留客户编号、报备资料、原跟进历史，绑定新账号，恢复新客户状态，并开始新的 90 天保护。
- 沿用主管查看全部客户、顾问查看本人客户的权限；公海客户对已授权 CRM 账号开放。重新认领后原顾问失去该客户访问权限。
- 当前没有按成交/无效状态豁免保护期到期规则。企微聊天未自动接入；有效活动需在系统内手动保存记录。

## 接口与部署

Go 公共前缀 `/api/v1/management/crm`，对应 Java 内部前缀 `/internal/management/v1`：

| 接口 | 用途 |
| --- | --- |
| `POST /customers` | 5 项快速报备，返回完整客户及编号 |
| `PATCH /customers/{id}/report` | 编辑报备资料，提交 `{version, report}` |
| `GET /customers?queue=pool` | 公海列表，沿用搜索和分页 |
| `POST /customers/{id}/claim` | 提交 `{version}` 重新报备认领 |
| `POST /customers/{id}/followups` | 新增 `kind`：followup / communication / drawing / quotation；旧客户端省略时按 followup |

本次实现页面位于 `background/` 统一 React 后台。`phase1/ui` 是原独立 Vue 演示入口，本次新报备功能以统一后台为准。

发布时需要同时更新 React 构建、Go 服务、Java 应用。Java 启动自动执行 Flyway `V3__manual_customer_reporting.sql`，新增字段、索引及报备串行锁记录，不重写已有客户归属。上线前按现有流程备份数据库。

报备客户后再加企微时，目前不会按手机号自动合并手动档案和企微档案（企微常不返回手机号），需由主管核实，避免误合并。现有企微档案的规范电话若与报备电话完全一致会阻止新报备；历史自由文本格式电话尚未做批量规范化。
