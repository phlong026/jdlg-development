# 管理后台 28 天保持登录

## 问题与原因

旧登录页的“记住密码”只向 `localStorage.background_remembered_login` 写入账号和明文密码，再次进入时回填表单。登录请求没有携带记住选项，服务端不知道需要延长会话；勾选不会自动登录。缓存被清除、换浏览器或切换站点来源时，回填也不存在。

`component/session.go` 在配置 CRM 桥接时固定使用 28,800 秒（8 小时）。未配置桥接时则继承 Redis 库默认的 30 天，两者都不随勾选变化。旧登录页也不根据已经验证的会话跳转。因此“保存密码”“会话有效期”“打开登录页自动进入”此前没有接通。

## 本次行为

- 选项更名为“28 天内保持登录”，默认不勾选。
- 勾选后成功登录：同一浏览器的 Cookie 和 Redis 会话固定保留 2,419,200 秒（28 天），访问不会无限续期。
- 不勾选或旧客户端未传字段：固定 28,800 秒（8 小时），不再依赖是否接入 CRM。
- 直接访问登录页时复用现有 `/me` 核验；核验通过自动进入总控台或客户管理，保留账号的权限范围。核验期间显示等待提示，失败可重试或登录。
- 不再保存、读取明文密码。访问新版登录页时清理旧缓存；缓存清理异常只记录警告。
- 主动退出删除 Redis 会话并让浏览器 Cookie 立即过期。后台停用或更改权限仍在每次请求中校验。
- 企业微信登录仍按其现有 8 小时流程；小程序认证不受本次登录选项影响。

28 天依赖同一浏览器和站点、Cookie 未清除、Redis 会话仍存在、服务器会话签名密钥保持一致。主动退出或账号停用后不继续免登录。升级前签发的 8 小时会话不会自动延长，需要在新版勾选后登录一次。

## API 变化

`POST /api/v1/management/login`：在现有 `username`、`password` 外新增可选布尔字段 `remember_me`。`true` 为 28 天；`false` 或省略为 8 小时。字符串等错误类型返回 400。响应字段不变。

`GET /api/v1/management/me`：成功响应新增 `Cache-Control: no-store`，仍由服务器核验身份和最新权限。

`POST /api/v1/management/logout`：成功时删除服务器记录并返回过期 Cookie，旧 Cookie 重放返回未登录。

复用既有 Redis 会话库；按请求设置 Cookie 和 TTL，没有增加依赖、数据库迁移或新认证令牌。HTTPS 请求使用 Secure，Cookie 同时设置 HttpOnly、SameSite=Lax。当前依赖版本的签名解码上限为 30 天，可覆盖 28 天；Redis 按单次登录期限拒绝到期会话。实现参考 [RediStore 文档](https://pkg.go.dev/github.com/boj/redistore@v1.4.1#RediStore) 及锁定版本源代码。

## 发布与回滚

需要同时发布 `background` 构建和 Go 服务。单独更新前端不能延长服务端期限，单独更新后端也不会让旧前端发送勾选状态。沿用现有服务器环境与 SESSION_SECRET，不覆盖配置或 Redis 数据。

上线验收：重新勾选登录一次，确认 `sessionid` 的 Max-Age 为 2,419,200、Redis 对应 TTL 一致；关闭并重新打开浏览器后进入后台；退出后重开登录页应要求登录。另用未勾选及 crm_only 账号验证期限和落地页。

代码可以整体 revert，无数据库迁移。回滚代码不主动删除已签发的 28 天 Redis 记录；如需立即撤销本浏览器长会话，先退出再回滚。批量撤销涉及其他在线用户，应单独安排，不能直接清空共享 Redis。
