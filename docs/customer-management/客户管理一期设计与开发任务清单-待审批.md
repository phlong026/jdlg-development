## 1 本次审批的方案

在现有小程序管理后台 background 中增加客户管理模块，沿用现有 React 页面框架、Go 登录入口和视觉样式，调用已实现的 customer-management/phase1 Java 客户业务服务。

- 复用企微自动建档、客户去重、员工关系、业务归属、跟进、待办、同步重试和导出，避免在 Go 再做一套客户业务。
- 保留原小程序咨询线索页面、Go 接口及数据；企微客户与小程序线索分别管理，不合并身份、订单或支付。
- 原平台总控台继续使用；新增客户驾驶舱作为客户模块首页。主管查看团队，顾问查看本人。
- 正式页面使用现有 React + SCSS；独立 Vue 演示保留作参考和验证，不嵌套运行两套后台。
- 图册12张作为业务布局参考。现有后台组件、实际接口约束和本清单批准后的差异处理优先于图片中的控件与文字。

## 3 效果图与现有实现的差异处理

以下建议包含在本次审批中，审批后作为实现依据，避免开发人员照图擅自新增功能。

| 差异 | 当前源码事实 | 建议处理 |
| --- | --- | --- |
| 驾驶舱“今日新增” | overview只有all/new/today/overdue/unplanned/unassigned/won；new是阶段数量，today是今日联系 | 保留今日新增，扩展现有统计服务；禁止用new或today冒充。设计时核对createdAt来源并确定缺失时间口径 |
| 驾驶舱“最近新增” | 现有列表按updatedAt降序，并非添加时间排序 | 新增受控的添加时间排序/小列表查询；不能直接把当前列表改标题 |
| 团队跟进概况 | 无专用团队聚合接口 | 在Java现有筛选和权限规则上增加按负责人聚合；Go仅转发，浏览器不逐顾问循环查全量 |
| 沟通方式选择 | Follow DTO和crm_followup没有独立沟通方式字段 | 一期取消独立必填选择；员工可在跟进内容写“电话沟通：……”；不为此增建字段或统计 |
| 编辑“客户称呼” | Edit DTO无name，昵称与头像由企微补同步维护 | 昵称只读，继续编辑电话、需求、分类、意向；若以后需要独立备注称呼另列需求 |
| 编辑资料不展示阶段/时间 | 当前Edit是完整字段提交，且会校验已有下次时间 | 设计明确的资料编辑边界：保留阶段和时间，解决已逾期客户仅编辑资料时被旧时间校验阻塞的问题；复用服务并补回归，不静默清空待办 |
| “验证连接”按钮及状态 | 有配置齐备标识、同步任务和失败事件，无专用验证接口 | 一期使用现有“发起同步/查看结果”确认连通；不单做重复验证接口。未验证、失败、最近成功分开展示 |
| 同步结果的新增/更新数量 | 图中数字不代表现有任务DTO已返回这些字段 | 以现有SyncRun返回字段制作展示映射，缺少的细分指标不伪造；非必要统计不扩表 |
| 平台权限勾选框 | 原平台还没有图中对应的细粒度授权体系 | 一期按platform_admin/crm_only与CRM角色分离设计，不为几张图扩展完整通用RBAC平台 |
| 数据范围下拉框 | 顾问范围由服务端按ownerId约束 | 显示为只读说明，不能由前端任意改成全部客户 |
| 未安排与未分配文案 | unplanned=新客户/跟进中且nextFollowupAt为空；unassigned=ownerId为空 | 两队列可重叠；删除图中“未安排必然已分配”的暗示 |
| 字数计数及必填星号 | content/demand上限2000，phone上限80；手机号可缺失 | 以实际DTO和业务规则校验，不采用图片里的27/500等示例计数 |

时间口径须特别核对：ImportService.accept使用事件时间设置createdAt；snapshot首次创建时优先使用最早好友添加时间，缺失时才回退读取时间。因此此前图册补充说明中“createdAt等于首次入库时间”的简化描述不准确，应在设计任务S02中修订。今日新增不能将初始化发现的历史客户全部算作当天加好友；无法判定真实添加日期的记录应明确显示未知，必要时只补时间来源标记，不另建客户档案。

### 样式一致性的具体标准

1. 复用现有Layout、Sidebar、Topbar和Bookmark，不再画一套独立顶部栏。现有侧栏220px、折叠72px、顶部栏56px，优先于图片示例尺寸。
2. 背景与语义色优先使用App.scss现有变量；侧栏延续暖白、浅棕选中态，Logo沿用现有琥珀色。
3. 内容区域沿用layout.scss当前背景及桌面20px/24px留白；小屏沿用16px/12px规则。
4. 驾驶舱参考现有dashboard.scss卡片、圆角和阴影；列表/表单参考customerLeads.scss。图片中的统一6px圆角不作为设计系统。
5. 继续使用现有图标及兼容层、字体、按钮、表格和表单交互，不为客户模块安装另一套全局UI框架。
6. 现有样式并非全部组件化：只抽取明确复用的小部件并限定作用域，不开展全后台样式重构，不用全局选择器改变其他页面。
7. 同一角色的菜单、选中态、面包屑、页签和返回行为在各页面保持一致。主管专属控件不出现在顾问界面。
8. 审批后以现有后台真实页面截图对照验证；本轮只完成样式源码核对，尚未做运行界面验收。
