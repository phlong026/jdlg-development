# 客户管理一期开发文档

版本 V1.0　日期 2026年9月10日

阅读对象：前端、Go 后端、Java 后端、测试及部署维护人员。配套文档：《客户管理一期需求说明书》。

目标架构采用现有 React 管理后台和 Go 登录服务作为统一入口，源雀衍生的 Java 客户服务负责企微客户档案、好友关系、跟进和同步。两个业务数据来源独立保存，通过后台页面和接口统一使用，不做小程序客户身份合并或双向数据复制。

本文件保留V1.0设计基线。2026-09-12已按用户批准的任务清单完成统一后台代码整合及本地隔离验证；下文原“目标”描述不再用来判断当前完成状态。实际接口、字段及权限以[实施记录](实施记录.md)为准，构建与部署见[统一后台部署与运维](统一后台部署与运维.md)，验证边界见[整合验证记录](整合验证记录.md)。未修改正式环境配置，原DOCX/PDF为V1.0归档。

## 2 目标架构与数据归属

### 2.1 请求路径

浏览器先访问现有管理后台。原小程序线索请求继续进入现有 Go 线索接口；企微客户请求进入新的 Go 客户网关，由网关校验会话和账号关联，再携带服务端身份调用 Java 内部接口。

企微回调通过专用公开路径直接进入 Java 的验签入口。Java 后台任务调用企微接口，更新自己的客户数据库。浏览器不直接调用企微，不持有客户联系 Secret，也不使用共享管理员 Cookie。

| 调用方 | 入口 | 处理方 |
| --- | --- | --- |
| 浏览器 | /admin/customer-management | React 客户管理页面 |
| 浏览器 | /api/v1/management/customer-leads | 原 Go 小程序线索服务 |
| 浏览器 | /api/v1/management/crm | 新 Go 客户网关 |
| Go 客户网关 | /internal/management/v1 | Java 内部客户接口，待开发 |
| 企业微信 | /iycallback/handle | 现有 Java 回调验签及持久化入口 |
| Java 同步任务 | 企微客户联系接口 | 由 WxJava 读取授权范围内客户 |

### 2.2 唯一写入位置

| 数据 | 权威存储 | 允许的写入方 |
| --- | --- | --- |
| 小程序咨询线索与其历史 | 原 Go 数据库 | 原线索服务 |
| 企微客户、归属、跟进、关系 | Java 客户数据库 | Java 业务服务 |
| 平台登录、后台访问范围、账号关联 | 原 Go 数据库 | Go 账号与授权服务 |
| CRM 数据角色和企微员工对应 | Java crm_account、crm_employee | 受控账号管理接口 |

Go 只做代理和平台授权，不直接更新 Java 客户表。企微跟进不复制进原 customer_lead_followups。两个库之间不建数据库外键，不把两侧 ID 填进对方主键。部署保持单企业、单个 Java 工作实例，避免引入多租户与分布式任务协调。

### 2.3 页面整合方式

正式入口新增 React 页面，按已有后台风格实现企微客户、详情与待办。复用原页面中的搜索、列表、抽屉、跟进表单交互及样式，业务数据适配单独编写。Vue 演示保留作本地验证，不作为一期正式入口中的 iframe，不在 React 内挂载完整 Vue 工作台。

### 3.2 数据适配

原线索状态使用 new、contacted、converted、invalid；企微使用 new、following、won、paused、invalid。两个 DTO 独立定义，不能通过全局替换状态字符串兼容。原 assigned_to 是文本，企微 ownerId 是员工标识；原 user_id 不等于企微 externalUserid。

原概览的 today_new_count 代表今日新增；企微 today 代表今日联系。整合页分别展示，不输出跨来源去重总数。企微 new 指状态数量，建议标为“新客户”，纠正独立演示中“待首次跟进”的标签歧义。

### 3.3 交互与异常

列表请求采用请求序号或 AbortController，避免快速切换筛选后旧响应覆盖新结果。账号变化时清除列表、总数、概览、详情、管理设置及请求状态。详情修改带 version；收到 409 保留输入并提示刷新核对，不能自动覆盖新版本重试。

区分 401 登录失效、403 无权限、空数据和服务错误。登录失效跳到 `/admin/login`；returnTo 仅允许站内已授权路径。文件导出单独处理二进制响应，错误响应仍解析统一 JSON。手机下先展示搜索与客户卡片，复杂筛选可展开；表单保存按钮禁止重复提交。

当前 Java 接口把资料编辑视为完整的可编辑字段提交，即使 HTTP 方法为 PATCH，也不能只发送被修改的一个字段。前端须从详情构造完整 Edit DTO，不传名称、头像等企微同步字段。

## 4 登录与授权接入

### 4.1 账号对应关系

使用“后台用户 ID → CRM 账号名 → 企微员工 ID”的显式关系。后台 user_type 必须为 management；CRM 账号的 role 为 admin 或 staff。顾问必须关联有效、可接待的企微员工；主管可不绑定员工。

平台访问范围使用 platform_admin 与 crm_only。前者维持原平台授权能力，后者只能进入被授予的客户模块。该字段不自动决定 CRM 角色；能管理平台不等于可查看全部企微客户。无关联、关联停用、CRM 账号停用，均拒绝访问；staff 还必须绑定当前可接待员工，admin 不要求绑定员工。

由系统管理员创建或核对管理账号，并建立 CRM 关联。一期一名后台用户只关联一个 CRM 账号，一个 CRM 账号只关联一个后台用户；普通顾问原则上一员工一账号。新账号默认不授予平台全权限。现有管理账号的访问范围迁移须先核对名单并备份，不能根据姓名或用户名猜测角色。

### 4.2 原后台权限门禁

目标新增统一的管理访问中间件，在读取当前数据库账号和平台权限后再进入具体管理 API。需覆盖 `route/index.go` 中 managementAuth 以及 `route/management.go` 内部创建的 auth 路由组，避免只保护其中一个入口。

crm_only 仅允许自身 me、logout 和获授权的 crm 路径；旧 customer-leads、users、orders、AI 配置、报表等接口均拒绝。具体白名单按路由与方法匹配，不能用包含字符串等模糊判断。平台权限或关联被停用后，后续请求重新检查数据库即失效，不依赖等 Session 到期。

所有使用 Cookie 的客户变更请求应检查 CSRF。目标网关要求自定义请求头 `X-CRM-Request: 1`、JSON Content-Type，并检查已知站点 Origin；不得对任意跨站来源开放携带凭据的 CORS。测试及代理环境使用显式域名白名单，不接受任意来源。

### 4.3 服务间身份传递

新增 Java `/internal/management/v1` 入口，仅在可信内部网络可达。Go 根据已验证会话查出 CRM 账号，使用服务端共享密钥对每次请求签名。浏览器提供的内部认证头必须删除，role、employeeId、CRM 用户名均不能由浏览器决定。

Java 验证服务签名后，重新查询 crm_account 和 crm_employee，构造当前操作者，继续调用现有 CustomerService 和数据范围校验。不能因为服务签名正确就跳过客户归属检查，也不能默认切换成 admin。

签名协议是本项目内部新协议，不是企业微信官方回调协议。建议 V1 固定以下规则，Go 和 Java 共用测试向量：

| 字段 | 规则 |
| --- | --- |
| X-CRM-Key-Id | 密钥版本标识，服务端配置；用于轮换 |
| X-CRM-Audience | 固定部署标识，区分企业及环境 |
| X-CRM-Subject | Go 查得的 CRM 账号名 |
| X-CRM-User-Id | 当前后台账号数值 ID，用于审计 |
| X-CRM-Timestamp | UTC 秒级时间，允许时钟偏差 60 秒 |
| X-CRM-Nonce | 至少 128 位随机值，同一密钥下不可重复 |
| X-CRM-Signature | HMAC SHA256，Base64URL 编码且无填充 |

待签名字符串按下列顺序用单个 LF 连接，末尾无换行，编码 UTF-8：

```text
CRM-BRIDGE-V1
keyId
audience
subject
managementUserId
timestamp
nonce
HTTP_METHOD
escapedInternalPath
encodedQuery
hexLowercaseSHA256Body
```

Go 按白名单匹配外部路由、校验参数并构造内部路径；签名中的 escapedInternalPath 与实际发送的 URL 编码路径完全一致。查询参数统一以 Go url.Values.Encode 的结果发送及签名，Java 使用收到的原始查询串验签；无查询时为空字符串。请求体使用实际发送的字节计算摘要，不在签名后重新序列化。参数和头禁止 CR、LF；不接受路径穿越、额外路径片段或未支持的方法。

Java 常量时间比较签名，验签成功后原子写入 nonce；重复 nonce 拒绝。Nonce 保存至少 180 秒，再由清理任务删除。仅设置时间窗不等于防重放。内部认证失败由 Go 转换为服务连接错误，不能混同浏览器 Session 过期而反复退出用户。

### 4.4 管理账号与退出行为

统一入口不向浏览器签发 Java CRM_SESSION。浏览器退出 Go Session 后，就无法发起新的企微客户请求。目标为绑定到正式统一入口的账号增加 managed 登录模式，禁止继续用独立 CRM 密码或旧 CRM Cookie 绕过平台停用。

新 managed 账号由受控内部接口创建，员工不需要再维护第二份密码；旧密码登录入口拒绝 managed 账号。保留的运维应急账号仅可从运维网络使用，并单独审计。主管不能通过编辑角色、请求头或账号关联给自己扩大平台权限；平台账号、CRM 角色与关联的管理入口由系统管理员控制。

账号开通跨两个服务，不使用跨库事务：先建立 disabled/pending 关联，完成 CRM 账号校验或创建，再启用关联。按固定用户 ID 和唯一 CRM 账号重试；失败保留禁用状态和处理记录，不留下可用的半配置授权。

## 5 数据结构与迁移

### 5.1 现有表

| 表 | 关键标识 | 作用 |
| --- | --- | --- |
| 原 customer_leads | 数值 id、user_id、session_no | 小程序咨询线索 |
| 原 customer_lead_followups | lead_id | 原线索跟进历史 |
| 原 customer_service_events | lead_id、session_no | 原客户行为事件 |
| crm_customer | id 为外部联系人 ID，version | 企微客户业务档案 |
| iyque_customer_info | eId 为客户 ID 与员工 ID 拼接 | 原源雀关系实体 |
| crm_followup | id、customerId、operatorId | 跟进或资料调整历史 |
| crm_employee | id | 企微可接待员工 |
| crm_account | username、employeeId、role | CRM 身份及客户数据角色 |
| crm_event | SHA256 事件 id | 持久化回调与补资料任务 |
| crm_sync_run | 自增 id | 全量同步进度及结果 |
| crm_setting | id | 企业绑定、导入锁、关系时间水位 |
| crm_session | 令牌摘要 id | 独立模式会话，整合模式不向浏览器使用 |

crm_customer 的业务字段为 ownerId、stage、category、intent、phone、demand、nextFollowupAt、lastFollowupAt；name、avatar 由企微同步维护。单个数据库绑定单个企业，若日后支持多企业，必须重新设计包含 corpId 的唯一性，不能复用当前裸 ID 结构混放。

### 5.2 目标新增结构

以下结构尚未实现。Go 数据库采用原工程的显式 SQL 迁移方式；Java 使用新的 Flyway V2，不修改已经应用的 V1 校验内容。

| 结构 | 主要字段与约束 |
| --- | --- |
| Go management_access | user_id 主键；scope 为 platform_admin 或 crm_only；enabled；version；更新人与时间 |
| Go management_crm_link | user_id 主键；crm_username 唯一；state 为 pending 或 active；enabled；version；更新人与时间 |
| Go management_access_audit | 操作者 user_id；目标用户；动作；变更前后范围及关联；结果；request_id；时间 |
| Java crm_account 扩展 | authMode，standalone 或 managed；迁移默认 standalone，绑定后切换并撤销旧会话 |
| Java crm_bridge_nonce | nonce 摘要主键；expiresAt 索引；重复写入原子失败 |
| Java crm_operation_audit | managementUserId、crmUsername、动作、对象 ID、结果、requestId、时间；导出记录数量和筛选条件 |

授权变更表使用 version 防止旧表单覆盖新授权。审计不保存密码、Secret、签名密钥或完整 Cookie；客户正文按最小必要记录，资料变更的业务历史继续保留在 crm_followup。操作账号在历史记录中保持稳定，不通过重命名账号改写旧操作者。

### 5.3 保留原数据

新增表和新路由采用增量方式上线。小程序线索表不改主键、不改原状态、不回填企微客户 ID。Java 服务使用独立数据库，不直接连接已有源雀生产表或小程序库运行 V1 建表脚本。

当前没有实际客户迁移授权和身份核实数据，因此本期不提供“按昵称合并”“按电话自动认领”或双向同步历史功能。未来若增加手工关联，应另建可撤销的关联表及证据记录，不影响本期开发。

## 6 接口规范

### 6.1 当前 Java 接口与目标代理

当前接口前缀为 `/api`，使用独立 CRM Cookie。目标 Go 前缀为 `/api/v1/management/crm`，目标 Java 内部前缀为 `/internal/management/v1`。下面后缀相对各前缀；内部业务 Controller 应复用业务服务，不能把内部请求先伪装成密码登录。

| 方法及后缀 | 功能 | 权限与适配 |
| --- | --- | --- |
| GET /customers | 列表 | 全范围或本人；Page 转为 list 分页对象 |
| GET /customers/{id} | 详情 | 返回 customer、relations、followups |
| PATCH /customers/{id} | 修改资料 | 必须带 version；顾问不能改 ownerId |
| POST /customers/{id}/followups | 追加跟进 | 必须带 version、内容与有效安排 |
| GET /overview | 概览 | all、new、today、overdue、unplanned、unassigned、won |
| GET /employees | 员工 | 主管全部；顾问仅自己 |
| GET /sync | 同步状态 | 客户主管；配置齐备与成功结果分别返回 |
| POST /sync | 入队全量同步 | 客户主管；已有任务返回 409 |
| POST /sync/events/{id}/retry | 事件重试 | 客户主管 |
| GET /export/customers | 客户 CSV | 同一筛选、同一数据范围 |
| GET /export/followups | 跟进 CSV | 同一筛选、同一数据范围 |

当前 `/api/accounts` 为独立 CRM 管理员使用。整合后账号及角色变更需要额外校验系统管理员，不能简单向所有客户主管开放该代理。目标 Go 新增 `/crm/context` 返回 CRM 角色、运行模式和可用页签；`/crm/access` 管理访问范围与账号关联，仅系统管理员可访问，内部账号开通由其受控调用。

旧 `/api/auth/login`、`/api/auth/logout`、`/api/auth/me` 只属于独立模式，不映射成新的浏览器 CRM 登录接口。公开企微回调路径仍为 `/iycallback/handle`，不套用后台 Session 认证。

### 6.2 查询参数

| 参数 | Java 当前规则 | Go 目标对外规则 |
| --- | --- | --- |
| keyword | 匹配 name、phone、demand，转义通配符 | 透传校验后的文本 |
| stage | new、following、won、paused、invalid | 同值，空表示全部 |
| ownerId | 企微员工 ID | 仅作为筛选，不能决定当前身份 |
| intent | high、medium、low | 同值 |
| category | 固定咨询类型 | 同值 |
| queue | all、new、today、overdue、unplanned、unassigned | 同值；权限仍由服务端收窄 |
| page | 从 1 开始 | 从 1 开始 |
| size | 默认 20，上限 100 | 对外命名 page_size，网关转换 |

目标网关对错误枚举、非法分页、过长关键词返回 400，不静默变成全量查询。Java 当前部分筛选直接按值查询，目标校验应同步到内部 Controller，避免不同入口行为不同。

### 6.3 响应和示例

JSON 统一沿用原后台 `{code,msg,data}` 外壳。Java 客户字段保持 camelCase，原线索 DTO 保持 snake_case，两者在前端分别定义。

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "list": [{
      "id": "sample-external-id",
      "name": "示例客户",
      "ownerId": "sample-employee",
      "stage": "following",
      "category": "建房咨询",
      "intent": "medium",
      "version": 3,
      "nextFollowupAt": "2026-09-11T02:00:00Z"
    }],
    "total": 1,
    "page": 1,
    "page_size": 20
  }
}
```

该列表是目标代理响应示例，当前 Java 原始响应使用 Spring Page 的 content、totalElements、number、size，number 从 0 开始，需明确转换。客户示例字段为节选，真实 DTO 还包含联系方式、需求、资料时间等。

资料修改请求示例：

```json
{
  "version": 3,
  "ownerId": "sample-employee",
  "stage": "following",
  "category": "建房咨询",
  "intent": "high",
  "phone": "",
  "demand": "确认地块尺寸后继续沟通",
  "nextFollowupAt": "2026-09-11T02:00:00Z"
}
```

跟进提交请求示例：

```json
{
  "version": 4,
  "content": "已沟通需求，约定明日上午继续确认布局",
  "stage": "following",
  "nextFollowupAt": "2026-09-11T02:00:00Z"
}
```

两种变更均返回更新后的 Customer，前端替换 version 并刷新详情与列表。时间使用带时区的 ISO 8601，存储语义为 UTC；列表及今日口径使用 Asia/Shanghai，页面明确显示北京时间。当前原关系 addTime 是源雀的北京时间格式字符串，整合 DTO 应统一为带时区的时间后再格式化。

| HTTP 状态 | 前端处理 |
| --- | --- |
| 400 | 显示字段或筛选错误，保留表单 |
| 401 | 仅 Go 会话失效时跳转后台登录 |
| 403 | 已登录但无数据或功能权限 |
| 404 | 目标不存在，关闭失效详情或提示刷新 |
| 409 | 版本冲突或同步任务已存在，不自动覆盖重试 |
| 429 | 登录或请求限流，提示稍后尝试 |
| 502 | 客户服务调用或内部认证异常，显示服务错误 |
| 503 | 未配置、暂不可用或尚未接入 |

Go 保留客户服务的业务错误语义，内部签名错误对外映射为 502；响应不带 Java 堆栈、内部地址和密钥。CSV 原样流式转发 Content-Type 与 Content-Disposition，不套 JSON 外壳；不能只因下载接口返回 200 就把 JSON 错误保存成 CSV。

### 6.4 网关运行约束

使用固定配置的内部地址，不接受浏览器指定上游 URL。方法和路由采用白名单；常规请求体上限建议 64 KB。连接超时建议 3 秒，常规总超时 20 秒，导出单独设置上限并支持取消。不得自动重试写操作；响应丢失时先刷新详情核对 version 和历史记录，再决定是否重新提交。

## 7 企微同步和业务一致性

### 7.1 回调链路

现有实现先校验配置、签名参数和时间，再限制原始请求体大小，解密并检查密文接收企业和 XML ToUserName。XML 禁止外部实体和 DOCTYPE。支持 add_external_contact、edit_external_contact、del_follow_user、del_external_contact；半添加及其他不在范围内的事件不创建正式客户。

业务事件成功持久化后才返回 success。新增事件先建立最小客户与员工关系，补资料在后台执行，因此外部读取失败不会直接丢失已接收事件。事件 ID 使用企业与解密原文摘要去重；即使上游原文出现差异，客户及关系唯一主键也必须防止重复建档。

回调与内部网关签名是两套机制，Token、EncodingAESKey 和内部桥接密钥不得共用。当前回调时间窗为 300 秒，请求体上限为 128 KiB；真实企微重投行为需在联调中核实，不把本地时间窗当作企微官方重试承诺。

### 7.2 补同步与失败

现有后台每约 1.5 秒扫描最多 30 条到期事件，新增和编辑事件读取完整客户详情。单事件累计失败达到 8 次后标为 failed；此前采用退避等待，管理员可重试。当前退避公式的实际等待通常为 30、60、120、240、480、900 秒，后续不超过 900 秒；失败任务不丢弃。

全量同步持久化排队，每约 5 秒检查一次任务；每 30 分钟自动尝试创建补同步任务。逐页读取客户详情，分页游标异常必须失败，不能静默漏页。单次名单读取全部完成后才核对该员工缺失关系；任何中途失败保留失败任务及已处理数。

任务调度不是准点 SLA，外部 API 耗时及服务器负载会影响实际开始时间。当前单实例使用内存互斥防止同时全量执行，数据库设置行锁保护导入；不能直接扩为多个 Java 实例。服务重启后 pending 事件继续执行，running 全量任务改为失败供重新发起。

### 7.3 更新规则

企微同步可以更新名称、头像及关系；仅首次建档时设置默认负责人和业务初值，之后不能覆盖 ownerId、stage、category、intent、phone、demand、nextFollowupAt 或 lastFollowupAt。人工修改与跟进使用数据库事务、行锁和 version；跟进记录与客户状态要么一起成功，要么一起回滚。

删除只改关系状态，不删档案、不抹除历史、不自动改业务状态。关系状态 0 为正常，1 为客户删除员工，2 为员工删除客户，3 为名单缺失待核实。已知删除原因不得在后续名单缺失时改为不明原因。重新添加恢复关系，不覆盖人工负责人。

已有关系时间水位可以阻止明显更旧的更新，但企微事件时间精度及读取最终一致性仍存在边界。测试应包含乱序、同秒事件、先删后加、重复投递、同步与回调并发；无法从事件顺序可靠判断时，以后续读取核对并显示待核实，不声称做到任意场景严格有序。

## 8 部署和配置

### 8.1 环境结构

正式部署使用同一业务域名：`/admin` 提供前端，`/api/v1` 转给 Go，`/iycallback/handle` 精确转给 Java。`/internal/management/v1` 不应由公开反向代理暴露；Java 业务端口仅内网访问。现有 `/api` 独立 CRM 接口和 Vue 演示不作为公开生产入口。

前端通过同源 Cookie 登录；服务器启用 HTTPS。若 Go 和 Java 跨主机，内部连接需使用 TLS 及访问控制。原生产配置和小程序对外 API 路径不因整合而更换。现有开发代理默认可能指向线上 API，整合开发必须显式设为本地或测试服务，防止测试写入正式数据。

### 8.3 发布与回退

发布前备份原业务数据库、Java 客户数据库和配置，记录版本。先应用增量权限表与 Java V2，部署关闭整合开关的 Go 和 Java，再发布前端。核对现有管理员范围、配置首个管理员关联，验证权限后逐步开通测试主管和顾问；最后启用真实企微并导入存量客户。

回退优先关闭整合开关和新页面，保留旧小程序线索入口及新增数据库记录。不要删除新表，也不要让旧无权限门禁版本对 crm_only 账号开放全部后台；若回退到不理解访问范围的 Go 版本，必须先停用这些账号并撤销会话。停止企微同步前保留待处理事件，后续恢复需补同步核对缺口。

备份恢复沿用 `phase1/scripts/Backup.ps1` 与 `Restore-ToNewDatabase.ps1`，并补上 Go 授权及关联表。恢复只写新库，核对客户、关系、跟进、授权和失败任务后再人工切换。跨库备份应在暂停授权变更的窗口完成，并记录同一批次，避免恢复成错配的账号关系。

## 10 测试计划与质量门槛

### 10.1 分层测试

Go 测试应使用模拟 Java 服务，覆盖授权范围、路由白名单、参数转换、非 JSON 错误、下载响应、超时和 Session 失效；不能把真实企业凭据放进单元测试。Java 保留现有集成测试，补内部签名、nonce 重放、managed 账号和授权审计测试。前端验证角色菜单、来源切换、查询、表单冲突、错误提示和窄屏布局。

### 10.2 必须新增的安全和回归用例

- 未登录、无关联、关联禁用、CRM 账号禁用均拒绝客户访问；staff 绑定员工不可接待也拒绝，admin 不因未绑定员工被误拒绝。
- crm_only 直接访问旧 users、订单、配置、导出与 customer-leads 路由均拒绝，覆盖两处原 auth 路由注册。
- 顾问伪造 ownerId、subject、role、服务签名头或目标 URL 均不能扩权。
- 签名过期、主体被改、请求体被改、查询被改、部署 audience 不符、nonce 重放均失败；合法跨语言向量通过。
- 旧 CRM Cookie 不能登录 managed 账号；Go 退出及权限撤销后无法继续操作。
- 同一客户多员工关系、重复和乱序回调、同步中断与并发人工编辑不丢人工数据。
- 两个客户来源保持原 ID、历史和统计；旧小程序提交线索流程不受影响。
- CSV 数据范围、BOM、中文、换行及公式转义正确，超限有明确提示。

### 10.3 运行命令与证据

Java 独立服务在 `customer-management/phase1` 下运行 `mvn test`；React 在 `background` 下运行 `npm run build`，原线索还应运行已有 `scripts/check-customer-leads-v2.js` 检查。Go 在 `service` 下运行相关包测试；需启动外部依赖的测试使用隔离配置。新增测试命令与工具版本随任务提交记录，不能声称当前已经运行了尚未编写的整合测试。

性能验收采用需求书中的假设数据量：1 万客户、10 万跟进、20 并发，记录硬件、索引、P95、失败率及导出耗时。列表与详情 P95 目标不超过 2 秒，本地回调持久化确认 P95 目标不超过 1 秒；当前没有相应压测报告，不将此作为实测性能宣传。

现有构建有完整 Element Plus 包体积提示；正式 React 接入不需要重复加载这套 Vue 包。Flyway 9.22.3 对 MySQL 8.4 提示高于其声明测试范围，已有实际迁移验证，但后续升级必须复测，不能只凭编译成功判断数据库兼容。

### 10.4 上线门槛

需求书 A01 至 A16 应逐项记录环境、账号角色、步骤、预期、实际结果与证据。权限绕过、数据丢失、重复建档、丢跟进、错误删除、未验证的真实回调属于阻断项。正式发布需要测试和运维负责人确认实际部署结果，不以文档完成或独立演示通过替代。
