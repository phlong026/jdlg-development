## 2. 对原分析报告的修正

| 原判断 | 本方案采用的结论 |
| --- | --- |
| 前端和 tracking 白名单加三个页面即可 | 至少覆盖页面生命周期、请求错误拦截、HTTP 门禁、tracking 接收规则，以及业务 handler 和媒体权限 |
| 所有项目笔记都可以当公开详情放开 | 普通公开营销笔记与 `pns` 定向笔记不能混同；后者保持当前权限，除非另有明确决定 |
| 跟踪能力零损失、历史行为全部自动归并 | 能保留匿名采集能力，但未登录者无法保证实名；现有关联有会话、客户端和时间条件，离线未上传事件也可能被隔离 |
| SDK 首次会弹同意框，隐藏即可 | 当前存在默认静默开启；需要同步处理告知、选择记录、撤回入口与服务端使用边界 |
| 用户登录就是销售联系授权 | 账号、头像昵称、联系方式及销售联系目的分别处理 |
| 已转线索代表本渠道新转化 | 当前查询是账号是否曾有线索，并非渠道新增，更不是成交 |

## 3. 核心访问规则（推荐方案）

**按内容与动作划分权限，不按“正常入口／分享入口”划分登录门槛。** 同一份公开模板，通过首页、搜索、转发、扫码或外部链接进入，都允许完整浏览。`st` 仅用于来源归因，不能赋予内容权限；`pns` 是定向分享凭证，不能作为跟踪同意或项目成员身份。

| 类别 | 阅读 | 动作 | 跟踪 |
| --- | --- | --- | --- |
| 已公开模板、灵感、设计师公开作品及主页 | 匿名或资料不完整账号均可读公开投影及预览媒体 | 收藏、关注、个人保存按账号；付费下载仍校验权益 | 按所选访问分析规则记录 |
| 已发布的公开营销笔记、公开项目合集 | 完整公开正文、图集、视频可匿名读 | 普通复制和转发不强制开启分析；编辑、后台访问仍受保护 | 来源与内容版本保留，身份允许未知 |
| AI 公开介绍与输入表单 | 延续 8.0.7 匿名预览 | 真实生成、上传、余额、任务、下载要求账号，头像昵称非必要前置项 | 不采集提示词、私有参考图、个人结果 |
| 定向项目笔记 `projectnoteview` | 本轮保留有效 `pns`＋有效账号＋现有头像昵称完整资料门槛，直至 D3 明确调整；不新增“必须已入项目”要求 | 确认仍校验指定确认人和成员身份；反馈、打开回执分别校验 | 不因匿名分析放宽业务权限 |
| 私密资料包、项目附件、草稿、个人结果、订单、钱包、后台 | 延续各自账号／所有者／项目／角色权限 | 原权限不变 | 原来排除的个人历史、结果等继续排除 |
| 造价分享报告、定向设计方案 | 在产品确认其公开／定向属性前保持保护；不能只因页面叫“详情”而公开 | 资料补全仅在业务用途明确时要求 | 不把阅读登记强行等同销售授权 |

“公开”必须由服务端发布状态、发布范围、当前版本与撤回状态共同证明；客户端标记、分享卡片可见、资源 ID 可猜测均不能证明公开。公开模板预览不包含收费原图、内部提示词、未发布资产或客户私有信息。公开合集不能把其中一个私有条目洗成公开。

## 4. 业务决策与实施分界

以下是**建议值，尚未替代既有产品决定**；工程准备、测试和公开模板修复不依赖私密内容改为公开。

| 编号 | 建议值 | 未确认时的边界 | 影响 |
| --- | --- | --- | --- |
| D1 内容分类 | 已有明确公开发布语义的模板／灵感／主页／营销内容先开放；定向笔记、资料包保持保护 | 没有公开依据的资源不开放；分享报告逐类确认 | 决定新增匿名详情范围，不改变项目成员流程 |
| D2 账号画像分析 | 推荐把可关联账号、向业务人员展示轨迹并用于意向分析的处理设为用户自主选择；公开阅读不以此为条件 | 不擅自改变用户先前“默认开启”的决定；完整跟踪上线需先定稿此项 | 可能改变采集率；不能宣称总访问和已识别人数均不变 |
| D3 身份展示与联系 | 登录不强制头像昵称才能读公开内容；主动咨询／申请等动作告知用途并收集必要资料；销售联系另有依据 | 保留私有动作现有资料要求，不从登录推导新的营销授权 | 影响实名覆盖率、线索可联系率 |
| D4 告知与保存 | 按实际字段、可见人员、用途及现行保留／删除能力制定告知；处理范围实质变化时重新评审同意版本与存量迁移 | 不沿用“只改文案、不升版本”的旧任务结论覆盖新用途；不虚构保存天数 | 个人轨迹、账号关联、意向分析与线索处理上线前定稿 |
| D5 渠道报表 | 先把旧口径准确标为“历史已有线索账号数”；新增渠道转化另用明确来源、时间窗、去重和有效状态 | 不倒推历史缺失来源；不把历史有线索改称本次新增 | 渠道评价及 CRM 归因 |

D2 与 D4 未定稿时，可以完成独立的浏览修复开发。若先行发布浏览修复，必须对新开放访问范围关闭尚未定稿的新增匿名／账号画像处理，并由服务端约束旧客户端，不能随浏览白名单自动扩大默认采集；否则等 D2/D4 定稿后整体发布。不得将整套个人轨迹方案标为已验收或据此重新提交审核。新隐私行为必须检查旧客户端，不能只修改新包的默认值。

## 5. 跟踪与线索口径

1. **匿名访问**：安装级随机标识对应当前客户端，不是微信身份，也不保证跨设备一致；后台显示“未识别访客”，不推测真人或手机。
2. **账号访问**：`u:` 表示已识别账号；展示资料不等于实名核验。匿名到账号关联只沿现有可验证会话进行，不扩大成全部历史、跨设备或跨用户的追认。
3. **现有关联限制**：相同客户端、有效旧会话、最近活跃小于 30 分钟、未携带新的分享归因等条件；账号切换和退出清理上下文。未上传匿名队列不承诺无损合并。
4. **指标**：内容点击是入口动作；正文可见且页面前台、内容已就绪并允许分析后才形成有效阅读；停留与视频播放时长分别度量。分析拒绝、禁用或故障不阻塞正文和播放。
5. **归因**：`st` 尽力生成；当前存在 1.8 秒超时退回普通链接，不能用分享点击数充当送达数，不能承诺每次转发都带来源。
6. **CRM**：匿名、资料缺失、拒绝相应用途的账号不能伪造实名线索。普通访客列表不增加手机号；复用账号历史手机号须验证联系依据、用途、角色权限及撤回规则。自动转线索开关需只读核查线上状态，不能由本地默认值推断。
7. **撤回**：停止新的可选事件和账号关联，清理待发送队列；历史查询、删除、意向缓存及派生线索按所选规则执行。安全／审计日志如有独立必要用途，单独说明，不混入销售画像。

## 6. 验收底线与不做事项

- 入口一致：不能采用“审核或普通入口放行、分享入口强制登录”的两套公开阅读规则。
- 数据一致：正文、图片、视频、版本与撤回权限一致；不以整站关闭 `MINIPROGRAM_PROFILE_GATE` 代替精确修复。
- 身份隔离：账号 A→退出→匿名→账号 B；A 的数据、媒体缓存、轨迹、输入与上传不得串到 B。
- 明确关闭分析后仍可阅读、复制、分享、播放；匿名用户可以直接到达选择入口。
- 不改现有视频导入大小上限、不扩大抓取范围；本轮只确保新增匿名阅读不破坏已经修复的 Range／票据／撤回链路。
- 本轮是文档交付；后续代码提交、后端部署、开发版上传、体验版验证、审核和正式发布分别留证。
