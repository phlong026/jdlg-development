## 2. 与改造前相比的变化

### 可见变化（1 处）

顶栏标题前的图标。旧版因书签状态未就绪，所有页面都回落到同一个"显示器"图标；现在显示路由表里为各页面配置的图标（用户管理显示"用户"图标）。这是路由表 `icon` 字段的本意。
证据：25 页顶栏差异像素的合并包围盒为 x 72–89、y 18–36，**全部且仅在这个 18px 图标方块内**；标题文字与其余像素完全一致。

### 行为变化（均为改进）

| 变化 | 说明 |
|---|---|
| 侧栏 / 顶栏只挂载一次 | 以前每次站内跳转都会重建；折叠状态现在跨页面保持 |
| 不再重复请求 `/me` | 以前每个页面的顶栏都请求一次，现在直接用会话上下文 |
| 页面加载时外壳保持 | 懒加载页面时侧栏和顶栏仍在，只有内容区显示"页面加载中…"，不再整屏变空 |
| 内容区高度 +44px | 书签栏占用的高度还给了内容区 |
| 切换页面后回到顶部 | 内容区现在是同一个元素，由 `AdminLayout` 手动复位（`scrollTo(0)`），行为与以前一致 |

### 移除的功能

书签标签栏（含"刷新"和"全屏"两个按钮）。它切换页面时整页卸载重载，**并不保留筛选条件、页码和滚动位置**，实际只是另一个跳转入口，与侧栏重复。浏览器自带的刷新与全屏可替代。

## 4. 测试过程中发现的问题

| 问题 | 性质 | 处理 |
|---|---|---|
| 生产构建上首个 UI 登录超时，后面一片失败 | **测试脚本缺陷**：后端登录限流是固定窗口、每账号 5 分钟 20 次（成功登录也计数），脚本每次登录 8 次左右，连跑几次就用光额度。日志里有 `429` 为证 | 浏览器检查只登录一次并复用会话状态；限流时给出明确提示而不是一堆超时。顺带说明后端限流在正常工作 |
| 重定向后立即断言内容为空 | **测试时序**：布局先渲染、页面代码块再懒加载，瞬间只有"页面加载中…" | 断言改为等待内容就绪 |
| 刚跳转就去滚动，页面还没渲染够长 | 同上 | 等页面确实变长再滚动 |
| 第一个被访问的路由报 `API请求失败: Failed to fetch` | **测试时序**：登录落地的总控台同时发 3 个接口请求，测试不等它们结束就跳走，旧页面把被浏览器取消的请求记进控制台，被下一个路由的检查误认成自己的错误。两个环境表现一致，与新旧布局无关 | 登录后先等网络空闲再开始巡检；加了等待后两个环境都稳定 57/57，验证了这一解释 |

> 顺带的产品观察（低优先级）：`request.ts` 对**被取消的请求**也 `console.error('API请求失败')`，用户快速跳转时控制台会有无害的噪音。
