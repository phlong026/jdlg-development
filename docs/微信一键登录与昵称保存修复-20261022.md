# 微信一键登录与昵称保存修复

## 行为与原因

现有登录页已经支持“微信一键登录/注册”：用户同意协议后点击按钮，客户端调用 `wx.login`，服务端用 code 识别本小程序账号，无需输入账号密码。已有昵称的老用户进入首页；缺少昵称时弹出资料填写框；新用户先完成已有的身份选择。

`wx.login` 不返回可见微信号、昵称或手机号。微信当前的昵称能力是用户在 `input type="nickname"` 中点选键盘提供的微信昵称，再由小程序保存。可以保留一键登录和资料弹窗，但不能在用户交互前展示自动读取的真实昵称。

官方依据：

- [小程序登录](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)
- [头像昵称填写](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/userProfile.html)

本次复现了两处阻碍保存的问题：

1. 昵称框依赖 `input` 事件缓存，按钮直接读取缓存。微信点选昵称未同步缓存或安全检测清空输入后，可能提交空值、旧值。现在按官方建议使用命名表单字段，以提交时最终值为准。
2. 选填头像上传失败后临时文件状态未清空，昵称保存一直提示等待上传。现在以真实上传状态拦截，失败后可以继续保存昵称；上传期间禁用重复选择并在事件层拦截，避免并发上传提前解除等待。

复用已有登录、昵称 PUT、后台展示及分享资料解析逻辑，没有新增接口或依赖，也没有改写历史匿名访问身份。

## 开发版上传前发现的渲染异常

用户随后要求上传新开发版，并提供 `this._getData is not a function` 渲染错误。开发者工具 2.02.2608080、基础库 2.32.3 下已复现：从首页切换设计师中心、再到“我的”，未登录且昵称弹窗未打开时出现两条渲染错误。

最小清理方案是删除“我的”页中未使用的 `device-fingerprint-canvas` 节点，保留已有设备指纹算法、缓存、离屏 Canvas 与昵称表单。该节点没有业务引用；真实指纹函数使用 `wx.createOffscreenCanvas`，无需 WXML Canvas。清理前先用真实 TS/JS 和现有 CryptoJS 测试锁定离屏指纹行为。

本机官方 2.32.3 基础库缓存包 SHA-256 为 `3868945a661551450c3f8ccf6ad7af200744768b8e0af44ee63ebdbff58de37d`，包内 `/WAWebview.js` 的 Canvas 更新区段存在四处 `this._getData()` 调用，而该区段无相应方法定义，包含 `canvasUpdated` 调用。该证据与未使用页面 Canvas 的错误触发位置一致。

- 新测试先得到 2 通过、1 失败；删除节点后，设备指纹、登录、昵称、首页补检合计 **37/37 通过**。
- 移植到 `origin/main` 后的完整小程序测试 **337 项：332 通过、2 失败、3 跳过**；失败仍为上述两个客服基线问题。
- 完整 TypeScript、JS 语法、差异检查和独立代码审查通过。没有新增依赖、接口或权限变更。
- 正确项目的模拟器复测和开发版上传仍需完成。微信会话刷新后，官方 CLI 返回 `登录用户不是该小程序的开发者（code 10）`；已请求用户切换到有此 AppID 开发权限的账号，未绕过权限检查。
