## 1. 部署前置条件（不满足会直接影响可用性）

| # | 条件 | 原因 |
|---|---|---|
| 1 | **管理后台域名必须配置 https**（SSL 证书） | 会话 Cookie 已强制 `Secure`，纯 http 下浏览器/客户端不回传 Cookie，**后台无法保持登录**。企微登录路径此前已要求 https，本次是把密码登录拉齐到同一标准 |
| 2 | 环境变量按 `service/env.example` 补全：`SESSION_SECRET`（≥32 字符）、`ENV=production`；`SM4_KEY`/`SM2_PRIVATE_KEY` 按双端同步计划配置（见 env.example 中"生产切换步骤"） | `SESSION_SECRET` 非开发环境强制校验；SM4 未配置时启动日志会输出 `[安全][严重]` 警告 |
| 3 | 周知团队：管理端会话有效期从 30 天改为 **8 小时** | 每个工作日需重新登录一次（P1-2 修复的一部分） |
| 4 | 上传功能使用者周知：单文件 ≤50MB，类型限图片/文档/音视频/压缩包（html/svg/可执行文件被拒绝） | P1-5 修复 |

## 2. 部署后验证步骤（服务器上执行，约 10 分钟）

```bash
# ① 会话 Cookie 属性：应看到 Set-Cookie 带 Secure; HttpOnly; SameSite=Lax; Max-Age=28800
curl -ski https://<后台域名>/api/v1/management/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"<管理员>","password":"<口令>"}' | grep -i set-cookie

# ② 会话有效期：同上响应里的 Max-Age 应为 28800（8 小时）

# ③ AI 密钥掩码：登录后查询，api_key 应形如 sk-t****wxyz，不得出现完整密钥
curl -s https://<后台域名>/api/v1/management/ai/api/config \
  -H "Cookie: <上面拿到的会话Cookie>" | python3 -m json.tool | grep api_key

# ④ 会员计划引用检查：删除一个有用户持有的计划应返回 409
curl -s -X DELETE https://<后台域名>/api/v1/management/membership-plans/<有引用的计划ID> \
  -H "Cookie: <会话Cookie>"

# ⑤ 管理账号改密：新口令 <12 位应被 400 拒绝；≥12 位修改后仍能正常登录

# ⑥ 浏览器走一遍：登录 → 侧栏导航 → AI 配置页（密钥输入框显示"已配置 ****，留空保持不变"）→ 保存不改密钥 → 密钥仍在
```

## 3. 自动化回归（e2e/smoke.py）的运行方式变化

- 现状：脚本入口护栏只允许对 `127.0.0.1/localhost` 运行（防误伤线上），且会写数据
- 影响：本地 http 下 API 段（38/78 项）因不回传 Secure Cookie 而 401；**浏览器段 40 项全部通过，可继续在本地跑**
- 服务器方向的两种选择（需要你定）：
  - **A（推荐）**：在服务器上以 `E2E_API=https://127.0.0.1:<端口>` 对本机 https 监听运行（需放开护栏允许显式 https 目标，我可以改）
  - **B**：建一个 https 测试环境域名，脚本护栏增加"显式环境变量放行的 https 域名"
- 在你选择之前，脚本保持原生语义，不做任何环境特判
