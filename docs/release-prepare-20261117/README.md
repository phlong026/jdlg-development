## 部署顺序与注意事项

1. **冻结候选和受保护构建。** 所有端从同一干净候选提交构建。后端通过 `service/scripts/build-protected-release.sh` 注入既有私有认证源码，强制小程序JS→Go签名契约与最终ELF认证匹配。仓库中的占位后端源码不能用普通 `go build` 直接发生产。私有源码、环境快照、数据库备份和含认证材料的产物放权限0700目录，不提交或发到聊天。
2. **备份程序、环境和数据库。** 每次用新私有目录；保留11月16日的备份。当前 `binary_release.py prepare` 备份程序及环境，不能将它等同数据库备份；AI结构变更前另做数据库备份并确认可恢复。不替换 `.env`、`.env.local` 或CRM配置。
3. **先处理AI增量结构。** 润色新增 `prompt_optimize_json` 可空列、任务/费用/人工核对三张表。检查列、表、唯一键和现有迁移登记后，才选择增量SQL或应用初始化路径。裸 `ADD COLUMN` SQL不可重复执行；应用初始化捕获重复列1060并用 `CREATE TABLE IF NOT EXISTS`，可重复执行，但它不是 `app_data_migrations` 白名单自动文件迁移，不能混为一谈。
4. **保持AI润色默认关闭。** 模型、供应商/凭据、按次正整数价格及运营开关核对后再开启。视频与润色共享总并发容量，当前默认3。`uncertain/submitting` 或仍预留费用的任务必须依据真实供应商结果核对，不得靠换请求键重发、直接退款或删除记录来清理。
5. **先后端和管理台，再小程序。** 装修v5分享和AI润色新页面依赖新后端；仅上传小程序会产生接口不匹配。管理台使用manifest核对后通过 `web_release.py admin` 发布，保留旧哈希资源。本轮没有Nginx配置改动，不需要为发布后台顺便替换配置。
6. **验收后记录终态。** 核对单一新PID、运行/磁盘ELF哈希、后台manifest和公共200/私有401，随后做授权账号只读业务巡检。401只证明鉴权入口存在，不能代替完整业务验收。小程序上传成功、体验版指向、提审、正式发布和真机结果分别记录。
