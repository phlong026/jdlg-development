## 2. 实现方式（为什么风险低）

- **页面网址一律不变**，24 个样式文件零改动；Tab 直接指向原有网址。
- **子导航条放在顶栏与内容区之间**（原书签栏的位置），内容区本身不变。
- 导航数据只在 `navConfig.ts` 一处维护；旧导航数据保留，供回退使用。
- 路由一致性脚本新增"**导航覆盖**"检查：每个路由都必须归属某个分组，否则页面会从导航里消失。已反向验证：临时去掉 `/oss` 的归属，脚本立即报错。

## 4. 过程中修正的测试问题（均非产品缺陷）

URL 先变、界面后渲染，所以"跳转后立刻读 Tab""整页刷新后立刻读内容区"这类即时断言会偶发失败；已改为等待元素就绪，并用连续两次运行确认稳定。另一处：`react-icons/fi` 的类型声明是项目手写的子集，补上了 `FiArrowLeft`。

## 5. 未覆盖 / 待你决定

- **权限仍是两档**：新导航按 `platform_admin` / `crm_only` 显示，角色（运营 / 客服 / 财务）与按角色收缩菜单属于阶段 4（权限与审计），**尚未开始**，需要评审；
- **"日志管理"仍是空壳**（`logs` 表无人写入，见联调问题记录 D-8），只是现在藏在"系统设置"里；
- **分组是否合理需要真实使用者确认**：尤其"风控与增长"（风控台、分销、报表）关系较弱；页面使用频次仍是推断，建议灰度期间收集反馈或用访问日志校准；
- `AI 配置`页自带"计费配置 / 接口配置"两个内部 Tab，与分组 Tab 是两层，视觉上已区分但未做专门设计；
- 手机宽度只验证了抽屉导航与跳转；子导航条在手机上是横向滚动，没有逐页验证；
- ⌘K 搜索"设计"这类词会同时命中整个"用户与设计师"分组（分组名也参与匹配），略嘈杂，可按反馈调整。
