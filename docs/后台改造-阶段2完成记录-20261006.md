## 2. 实现方式（为什么风险低）

- **页面网址一律不变**，24 个样式文件零改动；Tab 直接指向原有网址。
- **子导航条放在顶栏与内容区之间**（原书签栏的位置），内容区本身不变。
- 导航数据只在 `navConfig.ts` 一处维护；旧导航数据保留，供回退使用。
- 路由一致性脚本新增"**导航覆盖**"检查：每个路由都必须归属某个分组，否则页面会从导航里消失。已反向验证：临时去掉 `/oss` 的归属，脚本立即报错。

## 4. 过程中修正的测试问题（均非产品缺陷）

URL 先变、界面后渲染，所以"跳转后立刻读 Tab""整页刷新后立刻读内容区"这类即时断言会偶发失败；已改为等待元素就绪，并用连续两次运行确认稳定。另一处：`react-icons/fi` 的类型声明是项目手写的子集，补上了 `FiArrowLeft`。

## 6. 验收后修正（2026-10-06）

使用者验收时指出两个问题，均已修复：

| 问题 | 原因 | 修复 |
|---|---|---|
| 客服线索工作台被放进分组 Tab（相当于三级页面） | 我把它与异常工单合成"客户与工单"，并在启用 CRM 时隐藏 | 恢复为**一级入口**；异常工单也单独成一级；不再按 CRM 隐藏 |
| 风控台等页面的卡片排版异常（无内边距、图标贴边、部分连边框都没有） | **早就存在的缺陷，与导航改造无关**：`section-card` 的完整样式原本只写在 `dashboard.scss`，靠"全局泄漏"让其它页面正常；9 月 15 日样式按路径限定作用域后，用到它却没自己定义外观的 **9 个页面**（用户管理、设计师、分销、内容分析、风控台、异常工单、报表导出、AI 任务、会员运营）就坏了 | 在全局样式里给这 9 个页面补上默认外观（优先级为 0，页面自己的定义始终优先）；虚拟支付页缺少的刷新按钮样式在本页补上 |

**仍未覆盖**：这类"靠泄漏才正常"的缺陷，只有"类完全没有样式"（已扫描，仅 `btn-view` 的悬停色）和"卡片没有内边距"（已覆盖）两种能自动发现；其它"只缺个别属性"的情况需要人眼逐页看。我逐页看过全部 25 页的截图，没有发现其它明显问题，但小瑕疵可能遗漏。

## 7. 第二轮排版排查（2026-10-06）

## 8. 「用户账号」与「销售线索」的区分（2026-10-06）

**问题**：验收时指出两点：① 客服线索工作台这一组只有一个页面，没有分类；② 「用户与设计师」和「客服线索工作台」名字相近，容易被误解。

**业务上的区别**（依据 `customer_leads` 表：姓名 / 电话 / 微信 / 需求摘要 / 房屋层数 / 风格 / 地块尺寸 / `user_id`）：

| | 用户账号 | 销售线索 |
|---|---|---|
| 是谁 | 已注册小程序账号的人（用户、设计师） | 在智能客服里留了联系方式、有建房需求、待销售跟进的人 |
| 谁处理 | 运营、审核 | 客服、销售 |
| 做什么 | 账号、认证、会员、灵石 | 判断意向、分配负责人、定时跟进 |

线索表里的 `user_id` 可以关联到用户账号，但两者不是一回事；启用 CRM 后，客户管理是「线索 → 客户」的下一步。

**改动**：

| 项 | 做法 |
|---|---|
| 名字与定义 | 「用户与设计师」→「**用户账号**」（说明：已注册的小程序用户）；「客服线索工作台」→「**销售线索**」（说明：留了联系方式，待跟进）；侧栏分组名下带一行灰色小字，悬停有提示；顶栏标题同步 |
| 补分类 | 线索页原有的 6 个队列升级为子导航 Tab：待处理 / 今日新增 / 高意向 / 超时未跟进 / 未分配 / 全部线索；待办类队列带数量角标；队列由地址 `?queue=` 决定（可收藏、可分享），**页面路径不变**；页内不再重复显示队列卡片 |
| 互相跳转 | 用户 360 → 「查看关联线索」（只看该用户，顶部有过滤提示条，可清除）；线索行 / 详情 →「查看用户账号」；匿名线索显示「未关联用户账号」 |
| 去掉重复入口 | 启用 CRM 时，「客户管理」不再在侧栏单列，改为挂在「销售线索」右侧入口（线索 → 客户），二级页有「返回销售线索」 |
| 后端 | `GET /customer-leads` 新增可选参数 `user_id`；不传或非法值视为不过滤，原有调用不受影响 |
| 本地种子 | `dev.sh seed` 增加 5 条虚构线索（含同一用户 2 条、匿名 1 条），可重复执行 |

**顺带修的一个缺陷**：`SubNav` 在二级页只有 1 个页面时整条不渲染，「返回」链接随之消失；以前二级页都有 ≥2 个 Tab 所以没暴露，是这次把"启用 CRM 的导航"补进自动化测试时发现的。

**验证**：`tsc` 零报错；路由一致性通过；回归 **71/71**（新增 5 项：侧栏说明、队列 Tab 与角标、线索 ⇄ 用户互跳与清除过滤、启用 CRM 时的导航、`user_id` 过滤的 API 契约）；后端新增 1 个单测（红 → 绿）；手机宽度下页面无横向溢出，队列 Tab 可左右滑动；内容区像素比对只有线索页与客户管理页有差异，且客户管理页的差异仅为种子数据让数字从 0 变 4。

**「启用 CRM」的导航首次得到测试**：用浏览器拦截 `/me` 把 `crmEnabled` 改为 `true` 来模拟（本地没有真实 CRM 接入，页面里的 CRM 数据请求会 503，与导航无关）。

**未做 / 待你决定**：

- 「异常工单」仍是单页分组（与线索原来的问题相同）；它是客服的售后处理，和销售线索不同对象，建议先不动；
- 用户管理页的「用户管理」标题与侧栏「用户账号」不完全一致，没有改（路由标题影响面较大，若要统一再改）；
- 旧导航（`?nav=old`）保持原样，仍显示旧名字，便于回退对照。
