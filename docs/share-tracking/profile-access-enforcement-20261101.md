# 登录与完整资料强制门禁整改

## 已确认问题

2026-10-31 21:10–21:17 的五次模板访问以匿名账号写入；同客户端后续会话于21:18:10关联到有昵称、无头像的账号。旧模板路径允许公开浏览；服务端无登录仍可进入追踪。已有小程序完整缓存提前放行，也不满足先服务端核验的要求。本轮不修改历史访客归属。

## 调整任务与验收

1. 服务端默认保护小程序业务API；只对登录、个人资料补全及必要启动接口保留精确例外。无登录401，资料不全428，核验故障503；不因资料不全注销有效账号。
2. 昵称、头像校验与现有小程序标准一致，先验证服务端资料再加载业务或追踪；关闭完整缓存提前放行。
3. 补齐普通业务页、分享直达页及服务端428的统一引导；保留分享来源、页面参数、有效昵称与账号隔离。
4. 网页分享改为打开小程序的登录引导，关闭匿名正文、媒体与新增访问上报旁路；保留原始分享目标。
5. 分别验证未登录、过期登录、缺昵称、缺头像、伪完整缓存、完整资料、网络错误、换号迟到响应与补全恢复；保证资料读写和头像上传不被门禁锁死。
6. 完成服务端、小程序相关测试和静态检查，审查业务路由覆盖与资源加载兼容；提交、推送并按已有授权发布可部署部分。服务器、小程序上传与真实手机验收分别记录。

## 清理边界

复用现有身份认证、login-guard与nickname-guard。网页端复用已有原生分享跳转，不新增网页登录体系。先用回归覆盖旧匿名正文入口，再删除不再可达的匿名网页业务处理，不按随机客户端标识批量合并历史用户。
