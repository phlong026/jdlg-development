# 登录后资料核验异常：诊断与修复记录

## 当前结论

手机体验版 7.2.19 报告点击微信一键登录后立即出现“登录已过期，请重新登录”，重复点击仍失败。开发者工具现场也观察到同一轮 `POST /login` 返回 200，随后 `GET /profile` 返回 401。本记录不把本地测试通过等同于生产登录恢复。

## 已确认并修复的两个问题

1. 仓库 `utils/parameter.js` 与 TypeScript 源码漂移：生成文件仍带签名参数占位符。按现有 TypeScript 源码重新生成，增加生成检查、JavaScript 与 TypeScript 一致性测试，以及 JavaScript 到 Go 完整验签测试。没有修改既有签名协议，也没有新增凭据或依赖。项目启用了 TypeScript 编译插件；这些测试不能证明 7.2.19 真机最终选择哪个产物，不能据此断言生产 401 的根因。
2. 资料门禁可能一直显示“正在核验登录资料”：同一会话的业务 428 先启动资料核验，另一业务 401 随后清除会话；原来的忙碌标记阻止新状态接管，旧资料回包又因会话变化被丢弃。现在按当前会话复用核验，并由检查版本号管理忙碌标记，旧请求不能覆盖新检查。组合回归验证恢复原地登录卡、没有放行内容、没有第二次跳转。

## 验证

- 官方 WXML 编译器参与的全量小程序测试：911/911 通过，0 跳过。
- 门禁专项测试：18/18 通过；TypeScript、签名及追踪生成检查、72 条路由一致性检查通过。
- JavaScript 到 Go 验签：2 个主测试、6 个请求子用例通过；`CGO_ENABLED=0` 下 Go route 测试、vet 和模块校验通过。
- 小程序生产依赖审计：0 项漏洞。变更未新增外部凭据、私钥或依赖。
- 本机 Go race 受 Go 1.26.2/macOS 的既有 cgo 初始化崩溃影响，未能运行；不能据此声称远端 CI 已通过。

## 尚待确认的生产问题

线上只读负向探针使用随机且不存在的会话，发送六个非空签名头：返回 401“参数不合法”；独立查询参数排除同 URL 缓存后结果相同。故意缺少 `sin` 的对照返回“Sin参数不合法”。这证明至少 token 和 token-signature 已进入前置检查，但尚不能证明全部头的值未被代理改变。

源码中 GET profile 跳过全局资料完整性门禁，仍受原有完整签名认证。随机会话在进入会话查询后应返回“无效的session_id”，因此应继续核实服务实际收到的请求头、HMAC 匹配和 token 解码结果。生产错误会把多种原因统一为“参数不合法”，不能仅凭 401 认定用户会话过期。

当前电脑工具间歇性报告 `noWindowsAvailable`，右侧浏览器连接超时；已有 SSH 认证被拒绝。未读到生产拒绝的独立原因，未切换后端，未上传新体验版本，也未宣称手机登录验收通过。

## 保持的业务规则

- 未登录：登录成功后读取服务器资料，再补全缺少的头像或昵称。
- 已登录且资料不全：直接补全，保留已有字段，不要求再次微信登录。
- 已登录且资料完整：核验后回到原分享内容，保留分享来源。
- 核验失败、过期或资料未完成：不加载受保护内容、不写入匿名浏览记录。
