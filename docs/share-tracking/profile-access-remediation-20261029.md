# 分享访客昵称、头像与访问记录整改（2026-10-29）

## 本次规则

新用户与历史用户采用相同规则：服务器确认当前登录有效，且同一账号的昵称和头像均已保存，才显示公开分享页面。历史用户已有昵称但缺头像，也必须补头像；已有完整资料无需重复填写。昵称为空、超过 32 个码点，头像为空、占位图、临时文件或非公开 HTTPS 域名地址，均不视为资料完整。上传服务和微信头像的正常 HTTPS 地址可用；本地地址、IP 地址、带凭据或片段的地址需重新上传。

本规则替代此前文档中的“可以跳过资料完善后继续浏览公开内容”。访问分析仍按独立的开关与用户选择执行：拒绝分析不会产生行为采集，也不能跳过资料完善。原有 37 个私有、账号、隐私等排除页面不纳入分享采集。

## 代码中确认的断点与修复

| 断点 | 修复后的行为 |
| --- | --- |
| 首页、模板详情、测算首页等页面未共用完整资料门禁 | 22 个公开页面统一由 `utils/profile-access` 阻断业务和跟踪生命周期；首次核验前不加载正文、不创建访问记录 |
| 旧门禁仅判断本地 token，无法证明服务端账号、昵称、头像有效 | `login-guard` 每次进入或返回均请求真实 `/profile`，失效登录重新登录，网络/服务错误保留拦截并提供重试 |
| 昵称补全提示晚于报告加载；完整昵称但缺头像也可能放行 | 共享资料校验要求昵称与头像同时完整，保存后 GET 回读同一账号，确认后才发出放行事件 |
| 登录后丢失尚未消费的入站分享参数 | SDK 仅在匿名首次登录且该页尚未建立访问时保留入站分享；账号 A→B、已消费访问、离开/替换页面仍隔离来源 |
| 默认转发处理器没有走统一分享创建流程 | 默认与定制分享处理器共用分享 token 创建，记录后续转发的直接分享关系 |
| 热启动新分享提前在旧内容上产生访问，或扫码解析的新 token 丢失 | App 先暂存入口，页面资料确认后再加载新素材；内容请求序号与阅读器入口序号保持递增，迟到响应不能覆盖新内容 |
| 关闭分析后无 token 的新报告入口没有刷新内容 | 素材切换按完整入口参数处理；没有分析 token 也能核验资料并显示正确报告 |
| 再次核验时销毁页面内容树会打断既有组件和观察器 | 首次放行后保留内容树，核验时用不透明门禁遮挡并暂停跟踪，成功后恢复 |

重点入口覆盖：`pages/index/index`、`pages/templatesquaredetails/templatesquaredetails`、`pages/aicost/aicost`、`pages/aicostshare/aicostshare`。其他公开入口按 `utils/tracking/routes` 清单一并接入；测试核对全部 22 个页面的 WXML 与组件声明，防止新增入口漏接。

登录、补全与重试均保留原页面参数。用户在资料弹窗选择头像并确认昵称；不将 `wx.login` 等同于自动取得微信昵称。头像先上传、保存并回读，昵称再保存并回读；跨账号的迟到上传和保存响应不能写入新账号缓存或放行页面。已有昵称会预填，缺头像时无需重新输入有效昵称。

微信、手机、密码登录以及身份选择还校验页面生命周期和原账号上下文。离开登录页、组件卸载或切换账号后，旧请求不能覆盖登录状态、清除新账号或触发迟到跳转。

## 后台显示与历史记录

后台已有的访客资料解析通过可信 `user_id` 读取当前数据库昵称、头像，本次复用该接口及显示逻辑，不增加第二套名称字段。新版本在资料核验后使用有效登录发起跟踪请求；在分析启用且已同意时，记录的身份可关联到该账号资料。

同一可信账号已有访问记录可在查询时读取最新资料。没有身份关联的历史匿名记录不能凭昵称、设备或时间猜测为某人；本次不批量合并、回填或迁移生产历史记录。

服务端公开内容与旧版客户端接口保持兼容。本次门禁随新小程序版本生效，不能宣称尚未更新的旧客户端也已强制补全。分析停用、用户拒绝、请求失败或内容不可用时，不承诺产生访问记录；分享触发也不等于微信已送达。
