# 管理后台四批整改与验收记录

日期：2026-10-11。范围：`background` React 管理后台。

## 页面范围与真实入口

本轮共 17 条已注册路由（16 条主要业务路由 + 1 条旧版兼容路由）。页面数量以路由为准，不以文件数量计数。

| 分组 | 路由与用途 |
| --- | --- |
| 工作台（1） | `/dashboard` 总控台：待办、概览与业务下钻 |
| 用户账号（5） | `/users` 用户检索；`/user-workbench` 单用户详情与处理；`/designer-center` 设计师管理；`/certification` 认证审核；`/membership-operations` 会员运营 |
| 订单与支付（5） | `/recharge` 订单与退款；`/virtualpay` 虚拟支付监控；`/pricing-config` 定价配置；`/recharge-config` 旧支付方式配置；`/membership-plans` 下载会员计划 |
| AI 运营（6） | `/ai-overview` 运营概览；`/ai-tasks` 图片/视频任务；`/ai-content-audits` 内容抽检；`/ai-tools` 工具管理；`/ai-pricing` 定价与供应商；`/ai-config` 旧版兼容配置 |

单用户详情从用户列表、待办等入口进入；支付与会员配置包含分组二级入口；旧 AI 配置保留兼容。四组不是一条强制串行流程。原生小程序的后台入口使用 WebView 承载该管理端，窄屏问题首先归于同一 React 后台；本轮未改原生小程序或独立客户 Vue H5 工程。

## 每批整改与业务结果

### 第一批：结构与弹窗

- 修复 AI 任务表头把条件文本直接放在 `tr` 下的无效结构，避免浏览器修复 DOM 后表头与表体错位。
- 订单、认证抽屉与 AI 自定义弹窗补动态视口高度、可滚动内容区、稳定操作区与底部安全区。
- 明确抽屉与后续确认弹窗的层级，保留退款、审核等原有业务操作。
- 第一批本地提交：`79b07f9cf3e581c777f2e77b1b783b334f45956a`。

### 第二批：响应式布局

- 17 页表格均使用独立滚动容器，标题、筛选与动作不再跟随整块面板横向滚动。
- 小屏保留用户、订单、AI 任务与会员表格的操作列，不删除金额、状态等业务信息。
- 工作台与 AI/资金指标网格可收缩；AI 场景小屏卡片保留“调用量、成功率、灵石收入”标签。
- 修复订单/虚拟支付样式作用域提前结束导致的跨页样式污染。
- 第二批本地提交：`d6f375f219bc9ba4b5bb8c618392e208ef88c550`。

### 第三批：业务文案与状态

- 常用入口统一为“用户详情”；AI 技术原始状态、接口、外部任务 ID、原始错误和请求/结果记录移至默认折叠的技术诊断区。
- 灵石消耗、退款记录、正常状态、失败说明、处理动作及服务成本估算口径仍可查看。不再笼统承诺所有失败任务均已退款。
- 资金口径说明从仅鼠标悬停可见改为可点击/键盘展开，公式与技术服务费信息保留。
- 页面重试成功仅清除对应数据来源的错误，不能抹去另一项尚未恢复的数据故障。
- AI 运营数据未加载时不呈现“0 收入/无异常”的结论；用户详情各模块失败与真实空数据分开，成功模块继续可用。
- 设计师、用户详情、支付配置和会员计划切换绑定当前对象；失败时不展示旧对象表单供新对象提交。
- 调价保持二次确认，确认快照绑定场景、旧价、新价与备注；未改价可以直接关闭，历史读取失败可重试。
- 用户封禁/解封、合并预检错误在当前弹窗反馈并保留输入。退款预览可在加载中取消，迟到结果不能复活；响应订单身份与最终提交对象再次核对。
- 保存/删除及关键写操作加入同步防重保护。删除失败仍保留已编辑表单，后端拒绝理由不改写。
- 第三批本地提交：`19e8549548d993ca7a365c3abc846a4910e17e57`；该批 `npm test` 79/79 通过。

### 第四批：导航、键盘与全量复核

- 当前分组标签应滚动到导航容器内可见，不牵动整页位置。
- 页面弹窗的焦点、Tab、Escape 与焦点归还控制仅在本轮 17 条路由启用；嵌套弹窗只处理最上层，正在提交的原有禁关闭保护继续生效。
- 分组导航与全站共享搜索面板属于共享组件：导航可见性改进作用于使用该导航的分组；搜索面板的 Tab 圈定和捕获阶段 Escape 修复作用于所有路由，避免同时关闭搜索面板与侧栏，纳入共享组件回归。
- 可点击 KPI 使用原生按钮，保留原入口和过滤条件。
- 最终审查额外发现并补测 AI 图片/视频任务的复合身份：详情加载期间不能按错误类型转工单，URL 视频入口、列表来源与动作类型一致。
- 认证详情、完整材料与审核动作绑定同一申请；关闭后旧材料不得写入新申请；揭示完整材料只用于当前详情，列表各行继续使用自己的脱敏字段。
- 上述修复只改变界面与请求生命周期，不更改审核结论规则。

## 业务规则与变更边界

本轮没有修改 `service` 后端、API 客户端协议、角色授权表、支付金额换算、退款资格/金额、会员权益规则或审核通过/拒绝条件。界面只能对已成功加载且归属正确的对象执行原有操作。真实后端仍须独立校验权限、金额、状态与幂等性；前端防重复不能替代后端幂等保障。

所有运行测试均使用固定虚构数据或假 API；没有执行生产退款、调价、审核、封禁、合并、配置保存或其他真实业务写入。

## 自动化证据的范围

- `npm test` 包含 TypeScript、31 条全站路由检查及 `scripts/*.test.mjs`。
- 表格结构和标签使用 TSX AST 检查；响应式样式使用编译后的 Sass/CSS 检查，包含全部 17 页的样式隔离。
- 业务回归执行生产组件/handler，替换 React hook 存储和 API I/O，控制请求乱序、取消、错误、对象变化与同帧重复调用。关键缺陷另用修复前基线反证。
- 键盘与滚动策略使用受控 DOM 进行确定性验证。
- `npm run build` 验证生产构建；`git diff --check` 验证补丁格式。

这些结果不是浏览器实际排版或真实设备验收。受控 hook/DOM 测试不覆盖完整 React 渲染调度、CSS 真实布局、WebView 内核、软键盘或后端事务。
