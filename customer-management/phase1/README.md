# 第一期客户管理系统

基于源雀 Iyque-SCRM 的独立网页应用。电脑浏览器管理客户，手机浏览器记录跟进；部署后可将同一网址配置为企业微信自建应用的工作台入口。第一期使用系统账号登录，尚未接入企微免登。

本期只处理“客户添加企业微信以后”的管理，不接入小程序会员、订单、支付或聊天存档。

## 立即体验

需要 Docker Desktop / Docker Engine 和 Compose。在本目录运行：

```powershell
docker compose -f compose.demo.yml up -d --build
```

打开 <http://localhost:8087>。

| 演示账号 | 密码 | 权限 |
| --- | --- | --- |
| admin | DemoAdmin!2026 | 管理全部客户、账号和同步 |
| advisor1 | DemoAdvisor!2026 | 张顾问负责的客户 |
| advisor2 | DemoAdvisor!2026 | 李顾问负责的客户 |

示例库内有 8 位虚构客户，页面有演示标识。演示模式关闭所有真实企微调用和回调，不发送消息。数据保存在独立的 `demo-database` Docker volume 中，应用重启不会重置录入的跟进。该端口仅绑定本机，不可直接从手机访问；手机实际使用需完成下方服务器部署。

```powershell
# 查看运行状态
docker compose -f compose.demo.yml ps
# 查看应用日志
docker compose -f compose.demo.yml logs --tail 100 app
# 停止；保留数据库
docker compose -f compose.demo.yml stop
# 重新启动
docker compose -f compose.demo.yml up -d
```

## 已实现的日常流程

1. **新增客户入库**：接收 `add_external_contact` 回调，验签、解密、验证企业后，先持久化客户关系与事件，再响应成功。没有渠道 `State` 的普通加好友同样入库；半添加事件不当作正式客户。
2. **补齐客户资料**：后台异步读取客户昵称、头像、跟进员工与关系添加时间；支持客户详情分页。接口失败会保留任务重试，不把读取失败显示为成功。
3. **明确负责人**：新增客户默认由添加该客户的员工负责；全量导入时按最早添加关系确定初始负责人。一个企微客户一份业务档案，可对应多个员工好友关系。管理员可调整业务负责人。
4. **分层与需求**：维护咨询类型、意向、联系方式、需求说明，按名称、电话、需求、负责人、状态、意向、类型筛选。
5. **跟进闭环**：填写沟通内容，更新新客户／跟进中／已成交／暂缓／无效状态。继续跟进必须安排未来联系时间，成交、暂缓、无效结束当前待办。
6. **查找待办**：首页显示待首次跟进、今日待办、逾期未跟进；另有未安排跟进、未分配列表。页面每 30 秒刷新列表，打开系统即可查看。今日统计按北京时间，逾期按具体截止时间判断，因此今日待办和逾期可能重叠。
7. **保留历史**：跟进记录只追加，不提供删除入口；资料调整另记操作记录，不算一次实际联系。不因删除好友而删除客户档案，重新添加后延续已有资料。
8. **异常和导出**：管理员可查看同步任务及未处理事件、重新发起同步或重试。支持按当前筛选和权限导出客户、跟进 CSV。

“调整业务负责人”只改变本系统的归属和访问权限，不会在企微转移好友。跟进记录是员工手动填写，聊天仍在企业微信中进行。原生欢迎语可在企微配置，本程序未实现群发、自动回复或消息提醒。

## 权限与数据规则

| 项目 | 管理员 | 顾问 |
| --- | --- | --- |
| 客户列表、详情、跟进、导出 | 全部 | 仅自己负责的客户 |
| 客户分配／调整负责人 | 支持 | 不支持 |
| 员工账号、同步管理 | 支持 | 不支持 |

权限在服务端执行，直接调用接口也按同一范围检查。修改客户须带资料版本，旧表单遇到别人已修改会返回冲突，刷新后再编辑。密码使用 BCrypt；登录令牌只在 HttpOnly Cookie 保存，数据库仅存令牌摘要，8 小时到期。账号停用或更改后旧会话失效；员工离开可接待范围后，关联顾问账号不能继续访问，客户仍保留给管理员处理。

当前是**单企业、单应用实例**。不同企业必须使用独立数据库；启动时校验数据库绑定的企业和演示／正式模式，防止混用。仅企微接口允许访问的员工及客户可以同步，无法越过企微授权范围。客户手机号通常需要顾问主动补录。

## 连接真实企业微信

### 1. 准备正式环境

使用服务器上的全新数据库，不要直接连接已有小程序库或源雀生产库。先停止同端口演示应用，或在 `.env` 中修改正式端口。

```powershell
Copy-Item .env.example .env
```

在服务器本机编辑 `.env`，填写独立数据库密码和管理员初始密码；密码至少 12 字符。实际密钥不要提交进 Git，也无需发到对话中。`.env` 已被 Git 和 Docker 构建上下文忽略。

| 环境变量 | 用途 |
| --- | --- |
| CRM_DB_PASSWORD | 应用数据库账号密码 |
| MYSQL_ROOT_PASSWORD | 数据库管理密码 |
| CRM_ADMIN_PASSWORD | 首次创建 admin 的密码，后续修改在“员工与权限”完成 |
| CRM_PORT | 本机监听端口，默认 8087 |
| CRM_SECURE_COOKIE | 正式 HTTPS 使用 true；本地 HTTP 调试才设 false |
| CRM_STANDALONE_ENABLED | 独立应用入口的自带登录开关，本 compose 默认 true；统一后台部署不使用本 compose（见宝塔版上线手册） |
| WECOM_CORP_ID | 企业 ID |
| WECOM_CONTACT_SECRET | 有客户联系权限的 Secret，不是任意应用的 Secret |
| WECOM_CALLBACK_TOKEN | 在企微客户联系事件回调中配置的 Token |
| WECOM_CALLBACK_AES_KEY | 同一回调的 43 位 EncodingAESKey |

```powershell
docker compose up -d --build
```

应用仅暴露 `127.0.0.1:CRM_PORT`，数据库不暴露宿主机端口。在服务器使用 HTTPS 反向代理转发到该端口，域名例如 `crm.your-company.example`，然后通过正式域名登录。

### 2. 配置企微回调与客户读取权限

在企业微信管理后台中配置客户联系可用范围、接口权限和可信服务器 IP，并按后台当前要求完成域名验证。客户联系事件接收地址为：

```text
https://你的正式域名/iycallback/handle
```

该地址同时支持 GET URL 验证和 POST 加密事件。代理需保留查询参数及原始请求体，不能对这个回调路径增加网页登录拦截。服务器需要准确时间，回调验签时间窗口为 5 分钟。

`WECOM_CONTACT_SECRET` 负责客户读取；Token / AESKey 负责回调，两者都要配置。界面“已配置”只说明本地参数齐备，不代表远端连接成功。配置完成后在“企微同步”发起一次同步，以结果确认权限和连通性。后台随后每 30 分钟补同步；新增回调接收后立即入库、异步补资料。

接口通常不自动提供员工真实姓名；如凭据不能读取通讯录，会以企微员工 ID 显示，不会因此中断客户同步。

### 3. 开通员工使用入口

管理员在“员工与权限”中新增顾问账号，关联已同步的企微员工。在企微自建应用中设置应用主页为系统的 HTTPS 地址，并设置可见员工范围，即可从企微工作台进入同一系统。

本期员工首次打开仍需输入本系统账号密码，未实现企微 OAuth 免登录，也未实现会话侧边栏和原生手机 App。普通手机浏览器也可访问同一网址。

### 4. 真实接入验收

代码交付时未取得贵司企微凭据，以下检查仍需真实企业环境完成：

- 回调 URL 验证成功。
- 普通加好友（无渠道 State）能新增客户并自动补齐昵称。
- 同一客户再添加另一员工，客户总数不重复，企微关系新增一条。
- 删除好友后关系标记正确，档案和跟进记录仍在；重新添加可继续管理。
- 顾问账号只能访问自己的客户；调整负责人后旧顾问失去访问权限。
- 手动全量同步成功，任务显示实际处理数量；企微授权范围与预期一致。
- 手机企微工作台打开、登录、保存跟进成功。

## 同步的处理方式

事件先写入 `crm_event`，事务成功才回复企微。重复的同一回调不会重复写入；客户以企业外部联系人 ID 唯一，员工关系复用源雀的 `externalUserid&userId` 主键。

新增、编辑事件会补读企微详情，失败最多自动尝试 8 次，间隔逐步增加至约 15 分钟；达到上限后保留为失败事件，管理员可手动重试。服务重启后待处理事件继续执行，中断的全量任务标记失败，需重新发起。同步任务和回调处理分别运行，**当前不要水平扩展多个应用实例**。

全量同步只在某员工的列表与客户详情全部读取成功后核对缺失关系。单凭列表缺失无法判断哪一方删除，显示“关系待核实”；已有删除回调说明则保留删除原因。关系时间戳用于阻止明显较旧的回调或同步覆盖新关系状态；企微时间精度及最终一致性可能仍需后续同步核对。

企微同步更新昵称和好友关系，不覆盖人工负责人、意向、咨询类型、需求或跟进安排。回调原文和 welcome_code 不落库；仅保存处理所需的客户 ID、员工 ID、类型、时间、渠道 State 和处理状态。

## 备份与恢复

Windows / PowerShell 7 可使用以下脚本。Linux 可通过容器中的 `mysqldump --single-transaction --no-tablespaces --set-gtid-purged=OFF` 执行同等操作。

```powershell
# 正式库（备份会输出文件路径）
./scripts/Backup.ps1
# 演示库
./scripts/Backup.ps1 -ComposeFile compose.demo.yml
```

文件及 SHA256 校验值存入 `backups/`，该目录不入 Git。备份含客户资料和密码哈希，应按公司数据权限保存，并复制到独立存储；建议每日备份、升级前额外备份，定期演练恢复。

恢复脚本只创建一个**新库**，不会覆盖原库或自动切换应用：

```powershell
./scripts/Restore-ToNewDatabase.ps1 -BackupFile './backups/你的备份.sql' -TargetDatabase iyque_restore_20260910
```

演示恢复追加 `-ComposeFile compose.demo.yml`。目标名须以 `iyque_restore_` 开头，且不能已存在；脚本校验备份摘要、恢复表结构与数据、清空恢复库中的旧登录会话，并输出客户与跟进数量。

确认恢复数据后，运维人员再为应用数据库用户授权该新库、把 `CRM_DB_URL` 改为新库并重建应用容器。正式切换前暂停录入并备份最新数据；原库保留用于回退。Compose 的示例 URL 在 `app.environment.CRM_DB_URL` 中。

## 开发与验证

- Java 17、Maven 3.9，Spring Boot 2.7 / JPA，WxJava，MySQL 8.4。
- Vue 3、Element Plus、TypeScript、Vite。
- 数据库结构由 Flyway 管理；实体使用 `ddl-auto=validate`，应用不会自行改写旧表结构。
- 当前 Docker 是独立应用 + MySQL，不需要 Redis、向量库或模型服务。

有 Java / Maven 时：

```powershell
mvn test
cd ui
npm ci
npm run build
```

没有 Java 时，在仓库根目录使用 Docker：

```powershell
docker run --rm --mount "type=bind,source=$((Get-Location).Path),target=/workspace" -w /workspace/phase1 maven:3.9-eclipse-temurin-17 mvn test
```

开发前端：在 `ui` 下 `npm run dev`，默认 `http://127.0.0.1:5178`，API 代理到本机 `8087`。完整交付以 Dockerfile 构建的前后端同源应用为准。

自动化测试覆盖权限、表单版本冲突、跟进闭环、账号停用、CSV 公式转义、回调验签与企业校验、XML 实体拦截、重复入库、关系删除与重加、失败重试、失败同步不误判删除。外部企微 SDK 在集成测试中使用模拟返回，因此不替代上面的真实接入验收。

本次具体运行与页面检查结果见 [VERIFICATION.md](VERIFICATION.md)。
